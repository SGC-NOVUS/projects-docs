# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду від 2026-09-28.
**Область аудиту:** маршрути фронтенду Vue, композиція сервера Express, збереження даних Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність стандартам чи юридичну сертифікацію.

## Структура виконання

Додаток складається з браузерного клієнта Vue/Vite та Express API, що запускається за допомогою `tsx server/index.ts`.

| Область | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Збереження даних | Prisma 7 з адаптером MariaDB; резервним значенням `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для завантаження та скачування |
| Пошта | Resend та рендеринг за допомогою Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або шаблонний `JWT_SECRET` лише тоді, коли `NODE_ENV=production`, налаштовує CORS із `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшн-середовищі.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване представлення / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, екрани умов та ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочі процеси створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточного користувача, якщо існує токен, і перенаправляє неавтентифіковані захищені переходи на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Двійковий проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за електронною поштою/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/пошти та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес локального завантаження документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Кінцева точка сховища опціонально приймає bearer token; читання є публічними | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Реєстр типів документів для всього середовища / робочого простору |

API не має зафіксованого у репозиторії документа OpenAPI 3.1. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежні шляхи збереження документів:

1. Застарілий шлях `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження зчитує цей шлях у файловій системі; створення архіву виконує стрімінг із цього локального стану.
2. Шлях `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний попередньо підписаний URL (presigned URL) для завантаження та вивантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за штибом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Воно створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Засоби R2 записують запити з шифруванням на стороні сервера `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | рядок; production активує примусове застосування JWT та статичну роздачу | `server/index.ts` | Межа запуску |
| `PORT` | ціле число / рядок; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL MariaDB; вище наведено незахищений локальний резервний варіант | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | секрет; у production має відрізнятися від вартового значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | секрет із 64 шістнадцяткових символів; випадковий резервний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | секрет; випадковий резервний варіант процесу | `server/utils/crypto.ts` | Критично для неперервності пошуку/індексів |
| `CORS_ORIGIN` | рядок джерела; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | кінцева точка / облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовій службі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | локальні для служби зчитування середовища | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Файли `.env.example` або `.env.sample` у репозиторії не знайдено. У README згадано лише частину цього списку, а `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` та налаштування Redis пропущені.

## Режими відмови та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ / секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за blind-index змінюється після перезапуску. Це слід розглядати як збій конфігурації у продакшені, а не як безпечний резервний варіант (fallback). |
| Недійсна довжина ключа шифрування | Операції шифрування/розшифрування викликають помилку, оскільки розібраний шістнадцятковий ключ не має довжини 32 байти. |
| JWT у продакшені не встановлено або використовує sentinel-значення | API реєструє критичну помилку та завершує роботу до початку прослуховування портів. |
| R2 недоступний | Виклики збереження v2/public завершуються помилкою та повертають помилки сервера; тимчасові файли Multer не гарантовано очищаються для кожного шляху виключення. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний потік автентифікації/документів все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) та прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає надану викликом цільову адресу, евристично нормалізує HTTP/HTTPS та здійснює вихідний POST-запит без реалізованого таймауту чи суворого списку дозволених пунктів призначення (allow-list). Перед публічним відкриттям він потребує спеціального огляду безпеки. |

## Необхідні виправлення документації

1. Додайте реальний шаблон середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, виключно з плейсхолдерами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Документуйте локальні `uploads/` у v1 та персистенцію R2 у v2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте резервний варіант випадкових криптографічних ключів як безпечний для продакшну.
