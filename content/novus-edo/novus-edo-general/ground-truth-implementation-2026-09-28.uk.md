# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит checkout станом на 2026-09-28.
**Область:** маршрути фронтенду Vue, композиція сервера Express, збереження даних Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність вимогам чи юридичну сертифікацію.

## Структура виконання

Застосунок є браузерним клієнтом на базі Vue/Vite разом з Express API, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Браузерний UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервним значенням (fallback) для `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK з presigned URL-адресами для завантаження/вивантаження |
| Пошта | Resend плюс рендеринг за допомогою Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Браузерне підписання | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої архітектури клієнта; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/шаблонний `JWT_SECRET` лише у разі `NODE_ENV=production`, налаштовує CORS через `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшені.

## Браузерні маршрути

| Маршрут | Вимога автентифікації | Реалізоване представлення / значення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, створення та робочий процес перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Навігаційний гард отримує дані поточного користувача, якщо токен існує, і перенаправляє неавтентифіковану захищену навігацію на `/login` (`src/router/index.ts`).

## Каталог API Express

Усі наведені нижче шляхи мають префікс `/api`, зазначений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан працездатності процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer-токен | Вхід за email/паролем та KEP/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та керування учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічним | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / робочого простору |

API не містить зафіксованого в репозиторії документа OpenAPI. Роутер і ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву виконується потоком із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний presigned URL для завантаження та вивантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане надсилання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний акаунт для анонімних збережених пакетів. Записи в R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Variable | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове застосування JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний резервний варіант наведено вище | `server/db.ts` | Критично для функціоналу збереження всіх даних |
| `JWT_SECRET` | secret; у production має відрізнятися від контрольного значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | secret із 64 hex-символів; випадкове резервне значення для процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадкове резервне значення для процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | ендпоінт/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише для сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування локальних змінних середовища сервісу | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Зафіксованого в репозиторії `.env.example` або `.env.sample` не знайдено. README згадує лише частину цього списку та пропускає `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими відмов та обмеження реалізації

| Situation | Observed behavior |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за blind-index порушується після перезапуску. Це необхідно розцінювати як збій конфігурації продакшену, а не як безпечний резервний механізм. |
| Некоректна довжина ключа шифрування | Encrypt/decrypt генерує виняток, оскільки розібраний hex-ключ містить не 32 байти. |
| Production JWT не встановлено / значення-заглушка (sentinel) | API логує критичну помилку та завершує роботу до переходу в режим прослуховування. |
| R2 недоступний | Виклики збереження даних v2/public завершуються збоєм і повертають помилки сервера; очищення тимчасових файлів Multer не гарантується на кожному шляху обробки винятків. |
| Електронна пошта недоступна | Поштові функції перехоплюють/логують збої; основний процес автентифікації/роботи з документами все одно може повертати успішну відповідь. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується в блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без використання оболонки та приймає підключення лише на loopback-інтерфейсі. |
| Публічний CMP-проксі | Проксі приймає передану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST-запит без реалізованого таймауту або суворого списку дозволених призначень (allow-list). Він потребує окремого аудиту безпеки перед публічним відкриттям. |

## Необхідні виправлення документації

1. Додати реальний шаблон середовища, що містить усі реалізовані секрети та ключі неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про стабільний публічний API.
3. Задокументувати v1 локальну персистентність `uploads/` та v2 персистентність R2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати резервне використання випадкового криптографічного ключа як безпечне для продакшену.
