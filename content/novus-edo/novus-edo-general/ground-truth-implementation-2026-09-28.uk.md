# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит чекауту від 2026-09-28.
**Область охоплення:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних середовища. Цей документ описує фактично реалізовану поведінку, а не відповідність нормативним вимогам чи юридичну сертифікацію.

## Архітектура виконання

Застосунок являє собою браузерний клієнт на Vue/Vite разом з Express API, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Браузерний UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервним значенням для `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для завантаження/вивантаження |
| Пошта | Resend плюс рендеринг за допомогою Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає процес LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/шаблонний (sentinel) `JWT_SECRET` лише за умови `NODE_ENV=production`, налаштовує CORS з `CORS_ORIGIN` або `*`, підключає маршрути та роздає `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимоги до автентифікації | Реалізоване представлення/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридична інформація та ідентифікація |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та детального перегляду |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Navigation guard отримує дані поточного користувача за наявності токена та перенаправляє неавтентифіковані переходи до захищених маршрутів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі наведені нижче шляхи мають префікс `/api`, зазначений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова перевірка працездатності процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` потрібен Bearer-токен | Вхід за email/паролем та КЕП/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та керування учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опційно приймає bearer token; читання є публічним | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальний реєстр типів документів / реєстр робочого простору |

В API немає зафіксованого документа OpenAPI. Роутер і ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву передається потоком із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний presigned URL для завантаження і передає підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане надсилання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Операції запису в R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Variable | Type/default | Where used | Startup/feature criticality |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує застосування JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний фолбек наведено вище | `server/db.ts` | Критично для функціоналу збереження всіх даних |
| `JWT_SECRET` | secret; у production має відрізнятися від sentinel | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий фолбек процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий фолбек процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; за замовчуванням `APP_URL` дорівнює `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | назва/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише для сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування локального оточення сервісу | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Зафіксованого у репозиторії `.env.example` або `.env.sample` не знайдено. README згадує лише частину цього списку та пропускає `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` та налаштування Redis.

## Failure modes and implementation limits

| Situation | Observed behavior |
| --- | --- |
| Missing/changed `ENCRYPTION_KEY` or `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за blind-index порушується після перезапуску. Це слід розглядати як помилку конфігурації продакшену, а не як безпечний резервний механізм. |
| Invalid encryption key length | Операції шифрування/дешифрування викидають виняток, оскільки розібраний hex-ключ не містить 32 байти. |
| Production JWT unset/sentinel | API записує критичну помилку в лог і завершує роботу до початку прослуховування. |
| R2 unavailable | Виклики збереження для v2/public завершуються збоєм і повертають помилки сервера; очищення тимчасових файлів Multer не гарантується на кожному шляху обробки винятків. |
| Email unavailable | Поштові функції перехоплюють/логують збої; основний потік автентифікації/документів усе одно може повертати успішний результат. |
| Converter missing LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у `finally`. |
| Converter input | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і прослуховує лише loopback. |
| Public CMP proxy | Проксі приймає надану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST без реалізованого таймауту чи суворого дозволеного списку призначень (allow-list). Він потребує окремого аудиту безпеки перед публічним розгортанням. |

## Необхідні виправлення документації

1. Додайте реальний шаблон середовища, який містить усі реалізовані секрети та ключі неперервності стану, лише з плейсхолдерами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про стабільний публічний API.
3. Задокументуйте локальну персистентність v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте резервний перехід на випадковий криптографічний ключ як безпечний для продакшену.
