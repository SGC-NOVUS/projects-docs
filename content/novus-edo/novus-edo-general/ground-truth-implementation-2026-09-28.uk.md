# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит оформлення замовлення станом на 2026-09-28.
**Область застосування:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитані змінні середовища. Цей документ описує реалізовану поведінку, а не відповідність вимогам чи юридичну сертифікацію.

## Виконувана форма

Додаток є браузерним клієнтом Vue/Vite разом із API Express, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Браузерний інтерфейс | Vue 3, Vue Router, Pinia та сервіси підписання на стороні клієнта |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; запасний варіант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Сховище об'єктів | Cloudflare R2 через AWS S3 SDK, з підписаними URL-адресами для завантаження/завантаження |
| Пошта | Resend разом із рендерингом Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |

| Підписування у браузері | Приватні ключі документів залишаються на боці браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або службовий `JWT_SECRET` лише за умов `NODE_ENV=production`, встановлює CORS із `CORS_ORIGIN` або `*`, підключає маршрути та обслуговує `dist/` у продакшн-режимі.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридична інформація та ідентифікація |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, створення та робочий процес перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточні дані користувача за наявності токена та перенаправляє неавтентифіковані запити до захищених розділів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організаціях та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес завантаження документів локально |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічними | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний/робочий реєстр типів документів |

API не має зафіксованого у репозиторії документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежні шляхи персистентності документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження зчитує цей шлях у файловій системі; створення архіву виконує стрімінг з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний попередньо підписаний URL для завантаження та завантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Засоби запису R2 використовують серверне шифрування `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове використання JWT та статику | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; незахищений локальний запасний варіант вказано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від sentinel | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексу |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий secret та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки пошти/посилань |
| `SOFFICE_PATH` | назва/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища локально для сервісу | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Не було знайдено задекларованих `.env.example` або `.env.sample`. У README згадано лише частину цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за допомогою сліпого індексу (blind-index) змінюється після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний запасний варіант (fallback). |
| Недійсна довжина ключа шифрування | Операція шифрування/розшифрування викликає помилку (throws), оскільки розібраний шістнадцятковий ключ не має довжини 32 байти. |
| JWT у production не встановлено або використовує sentinel-значення | API реєструє критичну помилку та завершує роботу перед початком прослуховування портів. |
| R2 недоступний | Виклики збереження v2/public завершуються помилкою та повертають помилки сервера; тимчасові файли Multer не гарантовано очищаються на кожному шляху виключення (exception path). |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють збої; основний потік автентифікації/документів все одно може повернути успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без shell і прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає цільову адресу, надану викликувачем, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST-запит без реалізованого таймауту або суворого списку дозволених пунктів призначення (allow-list). Він потребує спеціального огляду безпеки перед публічним відкриттям. |

## Необхідні виправлення документації

1. Додайте шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з заповнювачами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Задокументуйте локальний `uploads/` для v1 та персистентність R2 для v2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте резервне використання випадкових криптографічних ключів як безпечне для продакшну.
