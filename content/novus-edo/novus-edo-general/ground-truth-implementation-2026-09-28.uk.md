# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду станом на 2026-09-28.
**Область дії:** маршрути фронтенду на Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних середовища. Цей документ описує фактичну поведінку реалізації, а не сертифікацію на відповідність чи юридичний висновок.

## Структура виконання

Застосунок є браузерним клієнтом на Vue/Vite разом із Express API, що запускається за допомогою `tsx server/index.ts`.

| Область | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та сервіси підписання на стороні клієнта |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Persistence | Prisma 7 з адаптером MariaDB; резервним значенням (fallback) для `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Object storage | Cloudflare R2 через AWS S3 SDK, з підписаними URL-адресами (presigned URLs) для завантаження/вивантаження |
| Mail | Resend разом із рендерингом на базі Vue Email |
| Converter | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Browser signing | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої архітектури клієнта; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або sentinel-значення `JWT_SECRET` лише за умови `NODE_ENV=production`, налаштовує CORS із `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у production.

## Браузерні маршрути

| Route | Auth requirement | Implemented view/meaning |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, сторінки правової інформації та ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Navigation guard отримує дані поточного користувача за наявності токена та перенаправляє неавтентифіковані спроби переходу до захищених маршрутів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи, наведені нижче, мають префікс `/api`, зазначений у першому стовпці.

| Prefix | Operations | Authentication | Purpose |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про працездатність процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` потрібен bearer-токен | Вхід за email/паролем та KEP/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес роботи з документами через локальне завантаження |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічним | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр робочого простору типів документів |

В API немає зафіксованого в репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву потоково передається (stream) з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує об'єктні ключі R2. Він генерує п'ятихвилинний попередньо підписаний URL (presigned URL) для завантаження та вивантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане надсилання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 вимагають серверного шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціональності |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує обов'язкову перевірку JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний резервний варіант показано вище | `server/db.ts` | Критично для функціональності всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від sentinel-значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | секрет із 64 hex-символів; випадковий резервний варіант на рівні процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий резервний варіант на рівні процесу | `server/utils/crypto.ts` | Критично для неперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | ендпоінт/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціональності v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | секрет пошти та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціональності доставки листів/посилань |
| `SOFFICE_PATH` | назва/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціональності лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування локальних для сервісу змінних середовища | шляхи коду воркера/черги | Критично для функціональності лише там, де запущено воркер черги |

Файлів `.env.example` або `.env.sample` у репозиторії не знайдено. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Сценарії збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за blind-index порушується після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний резервний сценарій (fallback). |
| Некоректна довжина ключа шифрування | Операції encrypt/decrypt генерують виняток, оскільки розібраний hex-ключ не містить 32 байти. |
| JWT для production не задано/значення sentinel | API логує критичну помилку та завершує роботу до початку прослуховування. |
| R2 недоступний | Виклики збереження даних (persistence) для v2/public завершуються помилкою та повертають серверні помилки; очищення тимчасових файлів Multer не гарантується для всіх шляхів винятків. |
| Email недоступний | Функції пошти перехоплюють/логують збої; основний потік автентифікації/роботи з документами все ще може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і слухає лише loopback. |
| Публічний CMP-проксі | Проксі приймає передану стороною виклику цільову адресу, евристично нормалізує HTTP/HTTPS і виконує вихідний POST-запит без реалізованого таймауту чи суворого білого списку призначень (allow-list). Він потребує окремого аудиту безпеки перед публічним відкриттям доступу. |

## Необхідні виправлення документації

1. Додайте реальний шаблон середовища, який містить усі реалізовані секрети та ключі безперервності стану, лише з плейсхолдерами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про стабільний публічний API.
3. Задокументуйте локальне збереження v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте фолбек на випадкові криптографічні ключі як безпечний для продакшену.
