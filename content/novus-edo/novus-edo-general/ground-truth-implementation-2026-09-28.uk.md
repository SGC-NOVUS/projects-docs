# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит чекауту станом на 2026-09-28.
**Обсяг:** маршрути Vue frontend, композиція Express сервера, персистентність Prisma/R2, криптографія, конвертер та зчитування середовища. Цей документ описує реалізовану поведінку, а не комплаєнс чи юридичну сертифікацію.

## Виконувана форма

Додаток являє собою браузерний клієнт Vue/Vite плюс Express API, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Браузерний UI | Vue 3, Vue Router, Pinia та сервіси підписання на стороні клієнта |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервний варіант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Сховище об'єктів | Cloudflare R2 через AWS S3 SDK з препідписаними URL-адресами завантаження/завантаження |
| Пошта | Resend плюс рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Браузерне підписання | Приватні ключі документа залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підписів та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/контрольний `JWT_SECRET` лише коли `NODE_ENV=production`, встановлює CORS з `CORS_ORIGIN` або `*`, монтує маршрути та обслуговує `dist/` у продакшн-режимі.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридична інформація та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочі процеси створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточні дані користувача за наявності токена та перенаправляє неавтентифіковані захищені переходи на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Двійковий проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організаціях та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес локального завантаження документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічними | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр робочого простору типів документів |

API не має зафіксованого у сховищі документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежних шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження зчитує цей шлях файлової системи; створення архіву виконує стрімінг із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він видає п'ятихвилинний попередньо підписаний URL для завантаження та вивантажує підписи / файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Запити на запис до R2 використовують шифрування на стороні сервера `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | рядок; production активує примусове застосування JWT та сталу роздачу | `server/index.ts` | Межа запуску |
| `PORT` | ціле число/рядок; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL MariaDB; небезпечний локальний запасний варіант вказано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | секрет; у production має відрізнятися від sentinel | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | секрет із 64 шістнадцяткових символів; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | секрет; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для неперервності пошуку/індексів |
| `CORS_ORIGIN` | рядок походження; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | ендпоінт/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет і URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовому сервісі NOVUS Flow.EDO | `server/emailService.ts` | Критично для функціоналу доставки пошти/посилань |
| `SOFFICE_PATH` | ім'я/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише для сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища локально для сервісу | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Не було знайдено задекларованих `.env.example` або `.env.sample`. У README згадується лише частина цього списку та опускаються `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими відмов та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ / секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за сліпим індексом (blind-index) змінюється після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний запасний варіант. |
| Недійсна довжина ключа шифрування | Операції шифрування/розшифрування викликають помилку, оскільки розібраний шістнадцятковий ключ (hex key) не має довжини 32 байти. |
| JWT у production не встановлено або використовує сигнальне значення | API реєструє критичну помилку та завершує роботу перед початком прослуховування портів. |
| R2 недоступний | Виклики збереження v2/public зазнають невдачі та повертають помилки сервера; тимчасові файли Multer не гарантовано очищуються на кожному шляху виключення. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний потік автентифікації/документів все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без shell та прослуховує запити лише через loopback-інтерфейс. |
| Публічний CMP проксі | Проксі приймає надану викликом цільову адресу, евристично нормалізує HTTP/HTTPS і виконує вихідний POST-запит без реалізованого таймауту чи суворого списку дозволених пунктів призначення (allow-list). Він потребує спеціального перевіряння безпеки перед публічним доступом. |

## Необхідні виправлення документації

1. Додайте реальний шаблон середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з заповнювачами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Задокументуйте локальний `uploads/` для v1 та персистентність R2 для v2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте випадковий резервний криптоключ як безпечний для production.
