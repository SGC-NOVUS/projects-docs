# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду станом на 2026-09-28.
**Обсяг:** маршрути Vue-фронтенду, композиція Express-сервера, збереження даних Prisma/R2, криптографія, конвертер та зчитування змінних середовища. Цей документ описує реалізовану поведінку, а не юридичну відповідність чи комплаєнс-сертифікацію.

## Склад виконуваної системи

Застосунок складається з браузерного клієнта Vue/Vite та Express API, що запускається за допомогою `tsx server/index.ts`.

| Компонент | Фактична реалізація |
| --- | --- |
| Браузерний інтерфейс | Vue 3, Vue Router, Pinia та клієнтські сервіси підпису |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Збереження даних | Prisma 7 з адаптером MariaDB; резервним значенням `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK з попередньо підписаними URL для завантаження/вивантаження |
| Електронна пошта | Resend плюс рендеринг через Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підпис у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/шаблонний (sentinel) `JWT_SECRET` лише тоді, коли `NODE_ENV=production`, налаштовує CORS із `CORS_ORIGIN` або `*`, підключає маршрути та роздає `dist/` у production.

## Маршрути браузера

| Route | Auth requirement | Implemented view/meaning |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та детального перегляду |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Navigation guard отримує поточного користувача за наявності токена та перенаправляє неавтентифіковані спроби переходу до захищених маршрутів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи, наведені нижче, мають префікс `/api`, зазначений у першому стовпці.

| Prefix | Operations | Authentication | Purpose |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` потрібен bearer-токен | Вхід за email/паролем та KEP/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес локального завантаження документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опційно приймає bearer-токен; читання є публічним | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / реєстр робочого простору |

В API немає зафіксованого в репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву передається потоком із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує ключі об'єктів R2. Він видає попередньо підписаний URL для завантаження з терміном дії п'ять хвилин і завантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане надсилання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для збережених анонімних пакетів. Операції запису в R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | рядок; production активує застосування JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | ціле число/рядок; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечне локальне резервне значення наведено вище | `server/db.ts` | Критично для функціоналу збереження всіх даних |
| `JWT_SECRET` | секрет; у production має відрізнятися від контрольного значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-символьний шістнадцятковий секрет; випадковий резервний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | секрет; випадковий резервний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | кінцева точка/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; за замовчуванням `APP_URL` має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки електронних листів/посилань |
| `SOFFICE_PATH` | назва/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише для сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування змінних середовища, локальних для сервісу | шляхи виконання коду worker/черги | Критично для функціоналу лише там, де запущено обробник черги |

Зафіксованих у репозиторії файлів `.env.example` або `.env.sample` не знайдено. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за сліпим індексом (blind-index) порушується після перезапуску. Це слід розглядати як збій конфігурації продакшену, а не як безпечний резервний механізм (fallback). |
| Неприпустима довжина ключа шифрування | Операції шифрування/розшифрування генерують виняток (throws), оскільки розібраний hex-ключ не дорівнює 32 байтам. |
| Продакшен-JWT не встановлено/використано sentinel | API логує критичну помилку та завершує роботу перед початком прослуховування. |
| R2 недоступний | Виклики збереження v2/public зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується на кожному шляху обробки винятків. |
| Електронна пошта недоступна | Поштові функції перехоплюють/логують збої; основний потік автентифікації/роботи з документами все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і слухає лише loopback. |
| Публічний проксі CMP | Проксі приймає передану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS і виконує вихідний POST-запит без реалізованого таймауту або суворого списку дозволених адрес призначення (allow-list). Він потребує окремого аудиту безпеки перед публічним відкриттям. |

## Необхідні виправлення документації

1. Додайте шаблон реального середовища, який містить усі реалізовані секрети та ключі безперервності стану, лише із заповнювачами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про наявність стабільного публічного API.
3. Задокументуйте локальне збереження v1 `uploads/` та збереження v2 в R2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте використання резервного випадкового криптографічного ключа як безпечне для продакшну.
