# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит чекауту станом на 2026-09-28.
**Обсяг:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не комплаєнс чи юридичну сертифікацію.

## Структура середовища виконання

Застосунок являє собою браузерний клієнт Vue/Vite та Express API, що запускається за допомогою `tsx server/index.ts`.

| Компонент | Фактична реалізація |
| --- | --- |
| Браузерний UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на порту `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервним значенням для `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, із попередньо підписаними URL-адресами для завантаження/скачування |
| Пошта | Resend та рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/шаблонний `JWT_SECRET` лише за умови `NODE_ENV=production`, налаштовує CORS за допомогою `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшені.

## Браузерні маршрути

| Маршрут | Вимога автентифікації | Реалізоване подання/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Навігаційний guard отримує поточного користувача за наявності токена та перенаправляє неавтентифіковану спробу переходу до захищених маршрутів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі наведені нижче шляхи мають префікс `/api`, зазначений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь щодо працездатності процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` потрібен bearer-токен | Вхід, реєстрація та верифікація за email/паролем та KEP/TIN |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; операції читання є публічними | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / реєстр робочого простору |

API не має зафіксованого в репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву здійснює потокове передавання з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує об'єктні ключі R2. Він видає 5-хвилинний попередньо підписаний URL для завантаження та завантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане надсилання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове застосування JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний фолбек наведено вище | `server/db.ts` | Критично для функціоналу персистентності всіх даних |
| `JWT_SECRET` | secret; у production має відрізнятися від сентинельного значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-символьний секрет; випадковий фолбек на рівні процесу | `server/utils/crypto.ts` | Критично для безпеки та зчитування даних |
| `BLIND_INDEX_SECRET` | secret; випадковий фолбек на рівні процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | ендпоінт/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | секрет пошти та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | назва/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | локальні для сервісу зчитування змінних оточення | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Не знайдено зафіксованих у репозиторії файлів `.env.example` або `.env.sample`. У README згадується лише частина цього списку й опущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` та налаштування Redis.

## Режими відмов та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за blind-index порушується після перезапуску. Це слід розглядати як збій конфігурації у продакшені, а не як безпечний резервний механізм (fallback). |
| Недійсна довжина ключа шифрування | Операції шифрування/дешифрування викликають виняток (throws), оскільки розібраний hex-ключ містить не 32 байти. |
| Production JWT не задано/має значення-sentinel | API записує в лог критичну помилку та завершує роботу до початку прослуховування з'єднань. |
| R2 недоступний | Виклики збереження стану v2/public зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується для кожного шляху обробки винятків. |
| Електронна пошта недоступна | Поштові функції перехоплюють/логують помилки; основний потік автентифікації/документів все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується в блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 MiB, запускає LibreOffice без виклику командної оболонки (shell) і слухає лише loopback-інтерфейс. |
| Публічний CMP proxy | Проксі приймає передану клієнтом цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST-запит без реалізованого таймауту або суворого списку дозволених адрес призначення (allow-list). Потрібен окремий аудит безпеки перед відкриттям у публічний доступ. |

## Необхідні виправлення документації

1. Додати реальний шаблон середовища, що містить усі реалізовані секрети та ключі неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про стабільний публічний API.
3. Задокументувати локальне збереження v1 `uploads/` та персистентність v2 в R2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати фолбек на випадковий криптографічний ключ як безпечний для продакшену.
