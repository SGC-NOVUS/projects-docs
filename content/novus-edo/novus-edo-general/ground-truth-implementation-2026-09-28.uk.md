# Ground truth: реалізація Novus Flow.EDO

**Status:** internal static audit of the checkout on 2026-09-28.
**Scope:** Vue frontend routes, Express server composition, Prisma/R2 persistence, crypto, converter and environment reads. This document describes implemented behavior, not a compliance or legal certification.

## Executable shape

The application is a Vue/Vite browser client plus an Express API started through `tsx server/index.ts`.

| Surface | Actual implementation |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські послуги підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Persistence | Prisma 7 з адаптером MariaDB; резервний варіант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Object storage | Cloudflare R2 через AWS S3 SDK, з підписаними URL-адресами завантаження/завантаження |
| Mail | Resend плюс рендеринг Vue Email |
| Converter | Незалежна HTTP-служба на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |

| Підписування у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої архітектури клієнта; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або сигнальний `JWT_SECRET` лише коли `NODE_ENV=production`, встановлює CORS з `CORS_ORIGIN` або `*`, монтує маршрути та обслуговує `dist/` у продакшн-середовищі.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, екрани умов та ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та детального перегляду |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточний профіль користувача за наявності токена та перенаправляє неавтентифіковані запити до захищених розділів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче містять префікс `/api`, зазначений у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Двійковий проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організаціях та керування учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес завантаження документів локально |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Кінцева точка збереження опціонально приймає bearer-токен; читання є публічним | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр робочого простору типів документів |

API не має зафіксованого у репозиторії документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежних шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження зчитує цей шлях файлової системи; створення архіву виконує стрімінг із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він видає попередньо підписану URL-адресу для завантаження на п'ять хвилин і завантажує підписи / файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 виконують шифрування на стороні сервера за допомогою `AES256`.

## Реєстр середовища

| Змінна | Тип / за замовчуванням | Де використовується | Критичність для запуску / функцій |
| --- | --- | --- | --- |
| `NODE_ENV` | рядок; production активує примусове застосування JWT та сталу роздачу контенту | `server/index.ts` | Межа запуску |
| `PORT` | ціле число / рядок; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL MariaDB; вище вказано незахищений локальний запасний варіант | `server/db.ts` | Критично для функцій для всього збереження даних |
| `JWT_SECRET` | секрет; у production має відрізнятися від вартового значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | секрет з 64 шістнадцяткових символів; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | секрет; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку / індексів |
| `CORS_ORIGIN` | рядок походження; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | кінцева точка / облікові дані R2; час дії `900` секунд | `server/storageService.ts` | Критично для функцій v2 / публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет і URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовій службі NOVUS Flow.EDO | `server/emailService.ts` | Критично для функцій доставки пошти / посилань |
| `SOFFICE_PATH` | ім'я / шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функцій лише для служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища локально для служби | шляхи коду воркера / черги | Критично для функцій лише там, де запускається воркер черги |

Не знайдено жодного зафіксованого `.env.example` або `.env.sample`. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за blind-index змінюється після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний запасний варіант. |
| Недійсна довжина ключа шифрування | Шифрування/розшифрування викликає виняток, оскільки розіменований шістнадцятковий ключ не має довжини 32 байти. |
| JWT у production не встановлено/використовується sentinel | API реєструє критичну помилку та завершує роботу перед початком прослуховування. |
| R2 недоступний | Виклики персистентності v2/public завершуються помилкою та повертають помилки сервера; тимчасові файли Multer не гарантовано очищаються на кожному шляху виникнення винятку. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний потік автентифікації/документів все одно може повертати успіх. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає надану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS та здійснює вихідний запит POST без реалізованого таймауту чи суворого списку дозволених пунктів призначення. Це потребує спеціального огляду безпеки перед публічним відкриттям. |

## Потрібні виправлення до документації

1. Додати шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з підказками-заповнювачами (placeholders).
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням публічного API стабільним.
3. Описати локальний `uploads/` для v1 та персистентність R2 для v2 як окремі робочі процеси, що наразі існують паралельно.
4. Не описувати резервний механізм випадкових криптографічних ключів як безпечний для продуктивного середовища (production-safe).
