# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу репозиторію від 2026-09-28.
**Обсяг:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує фактично реалізовану поведінку, а не сертифікацію на відповідність чи юридичну сертифікацію.

## Структура виконання

Застосунок складається з клієнтської браузерної частини на Vue/Vite та Express API, що запускається за допомогою `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Браузерний UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервним значенням для `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для завантаження/вивантаження |
| Пошта | Resend плюс рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що породжує процес LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/шаблонний `JWT_SECRET` лише тоді, коли `NODE_ENV=production`, налаштовує CORS з `CORS_ORIGIN` або `*`, підключає маршрути та роздає `dist/` у продакшені.

## Браузерні маршрути

| Маршрут | Вимога автентифікації | Реалізоване подання/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, процес створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Navigation guard отримує поточного користувача за наявності токена та перенаправляє неавтентифіковану захищену навігацію на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, наведений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан працездатності процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` потрібен bearer-токен | Вхід за email/паролем та KEP/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічними | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний/робочого простору реєстр типів документів |

API не має зафіксованого в репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Завантаження оригіналу читає цей шлях із файлової системи; створення архіву виконує стримінг із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує об'єктні ключі R2. Він видає попередньо підписаний URL для завантаження із терміном дії п'ять хвилин і завантажує підписи/PAdES-файли до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | рядок; значення production активує обов'язковість JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | ціле число/рядок; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL-адреса MariaDB; небезпечний локальний резервний варіант показано вище | `server/db.ts` | Критично для функціоналу збереження даних |
| `JWT_SECRET` | секрет; у production має відрізнятися від контрольного значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-символьний шістнадцятковий секрет; резервний варіант — випадкова генерація процесом | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | секрет; резервний варіант — випадкова генерація процесом | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок джерела (origin); `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 ендпоінт/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовій службі EDO | `server/emailService.ts` | Критично для функціоналу доставки пошти/посилань |
| `SOFFICE_PATH` | ім'я/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | локальні для сервісу зчитування оточення | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Не було знайдено зафіксованих у репозиторії файлів `.env.example` або `.env.sample`. У `README` згадується лише частина цього списку і пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` та налаштування Redis.

## Failure modes and implementation limits

| Situation | Observed behavior |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за сліпим індексом (blind-index) порушується після перезапуску. Це має розглядатися як збій конфігурації продуктивного середовища, а не як безпечний резервний варіант. |
| Недійсна довжина ключа шифрування | Операції шифрування/дешифрування викликають помилку, оскільки розпарсений hex-ключ не має довжини 32 байти. |
| Не встановлено JWT для продуктивного середовища / встановлено шаблонне значення (sentinel) | API логує критичну помилку та завершує роботу перед початком прослуховування. |
| R2 недоступний | Виклики збереження `v2/public` зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується для кожного шляху обробки винятків. |
| Електронна пошта недоступна | Функції надсилання пошти перехоплюють/логують помилки; основний процес автентифікації/документообігу все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 MiB, запускає LibreOffice без оболонки (shell) і слухає лише на loopback. |
| Публічний CMP-проксі | Проксі приймає надану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS і виконує вихідний POST-запит без реалізованого таймауту або суворого білого списку (allow-list) призначень. Він потребує окремого аудиту безпеки перед публічним відкриттям. |

## Необхідні виправлення документації

1. Додайте реальний шаблон середовища, який містить усі впроваджені секрети та ключі безперервності стану, лише з плейсхолдерами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про стабільний публічний API.
3. Задокументуйте локальне збереження v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте резервний механізм із випадковим криптографічним ключем як безпечний для продуктивного середовища.
