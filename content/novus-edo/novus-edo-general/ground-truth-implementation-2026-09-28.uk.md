# Ground truth: Novus Flow.EDO implementation

**Status:** внутрішній статичний аудит процесу оформлення замовлення станом на 2026-09-28.
**Scope:** Маршрути Vue frontend, композиція Express server, персистентність Prisma/R2, криптографія, конвертер та зчитування середовища. Цей документ описує реалізовану поведінку, а не відповідність вимогам чи юридичну сертифікацію.

## Executable shape

Додаток є браузерним клієнтом Vue/Vite разом із Express API, що запускається через `tsx server/index.ts`.

| Surface | Actual implementation |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські служби підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Persistence | Prisma 7 з адаптером MariaDB; резервний варіант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Object storage | Cloudflare R2 через AWS S3 SDK, з підписаними URL-адресами для завантаження/скачування |
| Mail | Resend плюс рендеринг Vue Email |
| Converter | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |

| Підписування у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або сигнальний `JWT_SECRET` лише коли `NODE_ENV=production`, встановлює CORS з `CORS_ORIGIN` або `*`, підключає маршрути та обслуговує `dist/` у продакшн-режимі.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридична інформація та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Робочий процес списку, створення та детального перегляду документів |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточні дані користувача за наявності токена та перенаправляє неавтентифіковані захищені переходи на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче містять префікс `/api`, показаний у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає Bearer-токен | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організаціях та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес локального завантаження документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт зберігання опціонально приймає bearer-токен; читання є публічними | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / реєстр типів документів робочого простору |

API не має зафіксованого у репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежних шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження зчитує цей шлях у файловій системі; створення архіву виконує стрімінг із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний попередньо підписаний URL для завантаження та завантажує підписи / файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 виконують серверне шифрування запитів `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове використання JWT та статичну роздачу | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; незахищений локальний запасний варіант показано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від сторожового значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | секрет з 64 шістнадцяткових символів; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексів |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовій службі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища на рівні локального сервісу | шлях коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Жодного зафіксованого `.env.example` або `.env.sample` не знайдено. У README згадано лише частину цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за сліпим індексом змінюється після перезапуску. Це слід розглядати як збій конфігурації у продакшн, а не як безпечний запасний варіант. |
| Недійсна довжина ключа шифрування | Операції шифрування/розшифрування викликають виняток, оскільки розібраний шістнадцятковий ключ не має довжини 32 байти. |
| JWT у продакшн не встановлено / вказано значення-маркер | API реєструє критичну помилку та завершує роботу перед початком прослуховування портів. |
| R2 недоступний | Виклики збереження v2/public завершуються помилкою та повертають помилки сервера; немає гарантій очищення тимчасових файлів Multer для кожного шляху винятку. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний процес автентифікації/роботи з документами все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 MiB, запускає LibreOffice без оболонки (shell) і прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає надану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний запит POST без реалізованого таймауту чи суворого списку дозволених пунктів призначення. Перед публічним розгортанням він потребує окремого перевірення безпеки. |

## Потрібні виправлення документації

1. Додати шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням публічного API стабільним.
3. Задокументувати локальне сховище v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати резервний механізм випадкових криптографічних ключів як безпечний для продакшну.
