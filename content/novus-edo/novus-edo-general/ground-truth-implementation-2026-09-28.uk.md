# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду станом на 2026-09-28.
**Сфера охоплення:** маршрути Vue-фронтенду, композиція Express-сервера, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність стандартам чи юридичну сертифікацію.

## Архітектура виконання

Застосунок складається з браузерного клієнта Vue/Vite та Express API, який запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські служби підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервне значення `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Сховище об'єктів | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для завантаження/скачування |
| Пошта | Resend та рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Браузерне підписання | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або зразковий `JWT_SECRET` лише при `NODE_ENV=production`, налаштовує CORS з `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшні.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, процес створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Навігаційний захисник отримує поточного користувача, якщо токен існує, і перенаправляє неавтентифіковану захищену навігацію на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, показаний у першому стовпчику.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` потрібен Bearer-токен | Вхід за допомогою email/пароля та КЕП/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий процес роботи з документами локального завантаження |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічним | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / реєстр робочого простору |

API не має збереженого у репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існують два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву виконує потокове зчитування з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він видає п'ятихвилинний попередньо підписаний URL для завантаження та завантажує підписи/PAdES-файли до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для збережених анонімних пакетів. Записи в R2 вимагають шифрування на стороні сервера `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує дотримання JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; ненадійне локальне резервне значення (fallback) показано вище | `server/db.ts` | Критично для функціоналу персистентності |
| `JWT_SECRET` | secret; значення для production має відрізнятися від sentinel | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадкове резервне значення (fallback) для процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадкове резервне значення (fallback) для процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки пошти/посилань |
| `SOFFICE_PATH` | назва/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише для сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування змінних середовища, локальних для сервісу | шляхи коду worker/queue | Критично для функціоналу лише там, де запущено воркер черги |

Перевірених файлів `.env.example` або `.env.sample` не знайдено. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` та налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній або змінений `ENCRYPTION_KEY` чи `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за blind-index змінюється після перезапуску. Це слід розглядати як збій конфігурації для продакшену, а не як безпечний резервний варіант. |
| Недійсна довжина ключа шифрування | Операції encrypt/decrypt викликають помилку, оскільки розібраний hex-ключ не дорівнює 32 байтам. |
| JWT для продакшену не задано / має значення-маркер (sentinel) | API записує критичну помилку в журнал і завершує роботу до початку прослуховування запитів. |
| R2 недоступний | Виклики збереження даних `v2/public` зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується для кожного шляху виняткових ситуацій. |
| Електронна пошта недоступна | Поштові функції перехоплюють/записують збої у журнал; основний процес автентифікації/документообігу все ще може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає вказану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний запит POST без реалізованого таймауту чи суворого дозволеного списку (allow-list) призначень. Вона потребує окремого аудиту безпеки перед публічним відкриттям. |

## Необхідні виправлення в документації

1. Додайте реальний шаблон середовища, який включає всі реалізовані секрети та ключі безперервності стану, лише з заповнювачами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж стверджувати про наявність стабільного публічного API.
3. Задокументуйте локальне збереження v1 `uploads/` та збереження v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте використання резервного випадкового криптоключа як безпечне для продакшену.
