# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит оформлення замовлення станом на 2026-09-28.
**Область застосування:** маршрути фронтенду Vue, композиція сервера Express, збереження Prisma/R2, шифрування, конвертер та зчитування середовища. Цей документ описує реалізовану поведінку, а не сертифікацію відповідності чи юридичну сертифікацію.

## Виконувана форма

Додаток складається з браузерного клієнта Vue/Vite та API Express, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Браузерний інтерфейс | Vue 3, Vue Router, Pinia та клієнтські служби підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервний варіант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з підписаними URL-адресами завантаження/завантаження (upload/download) |
| Пошта | Resend плюс рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |

| Підписування у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або службовий `JWT_SECRET` лише за умов `NODE_ENV=production`, встановлює CORS за допомогою `CORS_ORIGIN` або `*`, підключає маршрути та роздає `dist/` у продакшн-режимі.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридичні документи та ідентифікація |
| `/dashboard` | Так | Наразі використовує повторно `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Робочий процес списку, створення та деталей документів |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточного користувача, якщо існує токен, і перенаправляє неавтентифіковані захищені переходи на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Двійковий проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організаціях та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес завантаження документів локально |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічними | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр робочого простору типів документів |

API не має зафіксованого в системі документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежні шляхи персистентності документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження читає цей шлях файлової системи; створення архіву виконує стрімінг з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний попередньо підписаний URL для завантаження та вивантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. За записи в R2 відповідає серверне шифрування запитів `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове застосування JWT та сталу роздачу | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; незахищений локальний запасний варіант показано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від сертинела | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для неперервності пошуку/індексу |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий secret та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовій службі NOVUS Flow.EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | назва/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища локально для служби | шлях коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Жодних задепозитованих `.env.example` чи `.env.sample` не знайдено. У README згадано лише частину цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими відмови та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за сліпим індексом (blind-index) змінюється після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний резервний варіант (fallback). |
| Недійсна довжина ключа шифрування | Операція шифрування/розшифрування викликає виняток (throws), оскільки розібраний шістнадцятковий ключ не має довжини 32 бати. |
| Production JWT не встановлено / вказано значення-індикатор (sentinel) | API реєструє критичну помилку та завершує роботу перед початком прослуховування порту. |
| R2 недоступний | Виклики збереження v2/public зазнають невдачі та повертають помилки сервера; немає гарантії, що тимчасові файли Multer очищаються на кожному шляху виникнення винятку. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють збої; первинний потік аутентифікації/документів усе ще може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 MiB, запускає LibreOffice без оболонки (shell) та прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає надану викликом цільову адресу, евристично нормалізує HTTP/HTTPS та здійснює вихідний POST-запит без реалізованого таймауту чи суворого списку дозволених пунктів призначення (allow-list). Він потребує спеціального огляду безпеки перед публічним доступом. |

## Потрібні виправлення документації

1. Додати шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням публічного API стабільним.
3. Задокументувати локальне сховище v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати резервний механізм випадкових криптографічних ключів як безпечний для продакшну.
