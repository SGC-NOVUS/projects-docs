# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду станом на 2026-09-28.
**Область охоплення:** маршрути Vue-фронтенду, композиція Express-сервера, збереження даних у Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність нормам чи юридичну сертифікацію.

## Структура виконання

Застосунок складається з браузерного клієнта на Vue/Vite та Express API, який запускається через `tsx server/index.ts`.

| Компонент | Фактична реалізація |
| --- | --- |
| UI у браузері | Vue 3, Vue Router, Pinia та сервіси підписання на стороні клієнта |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Збереження даних | Prisma 7 з адаптером MariaDB; резервним значенням `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, із попередньо підписаними URL-адресами для завантаження/скачування |
| Пошта | Resend та рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, який запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/шаблонний `JWT_SECRET` лише при `NODE_ENV=production`, налаштовує CORS з `CORS_ORIGIN` або `*`, підключає маршрути та роздає `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване представлення/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Навігаційний захисник (navigation guard) отримує поточного користувача за наявності токена та перенаправляє неавтентифіковану навігацію захищеними маршрутами до `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, вказаний у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан процесу |
| `/proxy` | `POST` | Ні | Бінарне проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає Bearer-токен | Вхід за допомогою email/пароля та КЕП/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Кінцева точка збереження опціонально приймає bearer-токен; операції читання є публічними | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / реєстр робочого простору |

API не має зафіксованого OpenAPI-документа. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву транслюється потоком із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma і використовує ключі об'єктів R2. Він видає 5-хвилинний попередньо підписаний URL для завантаження та завантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифікована відправка використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 запитують серверне шифрування `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове застосування JWT та статичну роздачу | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL MariaDB; небезепечний локальний запасний варіант вказано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від варти | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексів |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; час дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий secret та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовій службі NOVUS Flow.EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища локально для служби | шляхи коду воркера/черги | Критично для функціоналу лише там, де запускається воркер черги |

Не було знайдено задепозитованих у репозиторій файлів `.env.example` або `.env.sample`. README згадує лише частину цього списку та пропускає `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими відмови та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за blind-index змінюється після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний запасний варіант. |
| Недійсна довжина ключа шифрування | Операція шифрування/розшифрування викликає виняток, оскільки розібраний hex-ключ не має довжини 32 байти. |
| JWT у production не встановлено або використовує сигнальне значення | API записує критичну помилку в лог і завершує роботу перед початком прослуховування порту. |
| R2 недоступний | Виклики збереження v2/public завершуються помилкою та повертають помилки сервера; немає гарантії, що тимчасові файли Multer очищаються на кожному шляху виникнення винятків. |
| Електронна пошта недоступна | Поштові функції перехоплюють/логують помилки; основний процес автентифікації/роботи з документами все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) та прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає надану викликаючою стороною цільову адресу, евристично нормалізує HTTP/HTTPS і виконує вихідний запит POST без реалізованого таймауту чи суворого списку дозволених пунктів призначення. Він потребує спеціального огляду безпеки перед публічним відкриттям. |

## Необхідні виправлення документації

1. Додайте реальний шаблон середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з підстановками.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Задокументуйте локальний `uploads/` для v1 та персистентність R2 для v2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте резервне використання випадкових криптографічних ключів як безпечне для продакшну.
