# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду від 2026-09-28.
**Обсяг:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних середовища. Цей документ описує реалізовану поведінку, а не відповідність вимогам чи юридичну сертифікацію.

## Структура середовища виконання

Застосунок є клієнтом для браузера на базі Vue/Vite та Express API, що запускається через `tsx server/index.ts`.

| Область | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Збереження даних | Prisma 7 з адаптером MariaDB; резервним значенням `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для завантаження/вивантаження |
| Пошта | Resend плюс рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/шаблонний `JWT_SECRET` лише тоді, коли `NODE_ENV=production`, налаштовує CORS із `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшені.

## Браузерні маршрути

| Маршрут | Вимога автентифікації | Реалізоване представлення/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Navigation guard отримує поточного користувача за наявності токена та перенаправляє неавтентифіковану захищену навігацію на `/login` (`src/router/index.ts`).

## Каталог API Express

Усі шляхи, наведені нижче, мають префікс `/api`, зазначений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан працездатності процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає токен Bearer | Вхід, реєстрація та верифікація за email/паролем та KEP/TIN |
| `/users` | `PUT /me`, `PUT /me/password` | Токен Bearer | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Токен Bearer | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Токен Bearer | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Токен Bearer | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічним | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / реєстр робочого простору |

В API немає збереженого в репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу читає цей шлях у файловій системі; створення архіву здійснює потокове передавання з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує об'єктні ключі R2. Він генерує п'ятихвилинний presigned upload URL і завантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане надсилання використовує `individuals/<user ID>/documents/<verification ID>/...`. Сервіс створює або повторно використовує фіксований системний акаунт для анонімних збережених пакетів. Записи в R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове застосування JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний fallback наведено вище | `server/db.ts` | Критично для функціоналу персистентності всіх даних |
| `JWT_SECRET` | secret; у production має відрізнятися від контрольного значення (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | секрет із 64 hex-символів; випадковий fallback процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий fallback процесу | `server/utils/crypto.ts` | Критично для неперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | ендпоінт/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет і URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування локальних для сервісу змінних середовища | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Не знайдено зафіксованого в репозиторії `.env.example` або `.env.sample`. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Сценарії відмов та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за сліпим індексом (blind-index) змінюється після перезапуску. Це слід розглядати як помилку конфігурації продакшен-середовища, а не як безпечний резервний механізм (fallback). |
| Неприпустима довжина ключа шифрування | Операції encrypt/decrypt викликають виняток, оскільки розпарсений hex-ключ не дорівнює 32 байтам. |
| Продакшен-значення JWT не встановлено / значення-маркер (sentinel) | API логує критичну помилку та завершує роботу перед початком прослуховування. |
| R2 недоступний | Виклики збереження даних v2/public зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується для кожної гілки винятків. |
| Email недоступний | Поштові функції перехоплюють/логують збої; основний потік автентифікації/роботи з документами все ще може повертати успішний статус. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується в блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і слухає виключно loopback. |
| Публічний CMP-проксі | Проксі приймає передану клієнтом цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST без реалізованого таймауту або суворого білого списку призначень (allow-list). Він потребує окремого аудиту безпеки перед публічним відкриттям. |

## Необхідні виправлення документації

1. Додати реальний шаблон середовища, що містить усі реалізовані секрети та ключі неперервності стану, виключно з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про стабільний публічний API.
3. Задокументувати локальне збереження v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати фолбек на випадковий криптографічний ключ як безпечний для продакшену.
