# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит оформлення замовлення станом на 2026-09-28.
**Область застосування:** маршрути фронтенду на Vue, композиція сервера Express, персистентність через Prisma/R2, криптографія, конвертер та читання середовища. Цей документ описує реалізовану поведінку, а не сертифікацію на відповідність вимогам чи юридичну сертифікацію.

## Виконувана структура

Додатком є браузерний клієнт на Vue/Vite плюс API на Express, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Браузерний інтерфейс | Vue 3, Vue Router, Pinia та сервіси підписання на боці клієнта |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервний варіант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Сховище об'єктів | Cloudflare R2 через AWS S3 SDK із попередньо підписаними URL-адресами завантаження/завантаження |
| Пошта | Resend плюс рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що породжує LibreOffice (`SOFFICE_PATH` або `soffice`) |

| Підписування у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/контрольний `JWT_SECRET` лише коли `NODE_ENV=production`, встановлює CORS з `CORS_ORIGIN` або `*`, підключає маршрути та обслуговує `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, екрани умов та ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочі процеси створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточний стан користувача за наявності токена та перенаправляє неавтентифіковані запити на захищені маршрути до `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Участь в організаціях та керування учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт зберігання опціонально приймає bearer-токен; читання є публічними | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів / реєстр типів документів робочого простору |

API не має зафіксованого у репозиторії документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежних шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження читає цей шлях файлової системи; створення архіву виконує стрімінг із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакету в Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний попередньо підписаний URL для завантаження та завантажує файли підписів/PAdES в R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. За записи в R2 відповідає шифрування на стороні сервера за алгоритмом `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове використання JWT та статичну роздачу | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL MariaDB; небезепечний локальний запасний варіант показано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від sentinel | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для неперервності пошуку/індексів |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий secret та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовому сервісі NOVUS Flow.EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища локально для сервісу | кодові шляхи воркера/черги | Критично для функціоналу лише там, де запускається воркер черги |

Не було знайдено задекларованих `.env.example` або `.env.sample`. У файлі README згадано лише частину цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за сліпим індексом (blind-index) змінюється після перезапуску. Це слід розглядати як збій конфігурації у продакшені, а не як безпечний запасний варіант (fallback). |
| Недійсна довжина ключа шифрування | Операція шифрування/розшифрування викликає виняток, оскільки розібраний шістнадцятковий ключ не має довжини 32 бати. |
| Продакшен JWT не встановлено / встановлено sentinel-значення | API реєструє критичну помилку та завершує роботу перед початком прослуховування порту. |
| R2 недоступний | Виклики персистентності v2/public зазнають невдачі та повертають помилки сервера; тимчасові файли Multer не гарантовано очищаються для кожного шляху винятку. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний потік автентифікації/документів все одно може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 MiB, запускає LibreOffice без оболонки (shell) та слухає лише на loopback-інтерфейсі. |
| Публічний проксі CMP | Проксі приймає вказану викликувачем цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST-запит без реалізованого таймауту чи суворого списку дозволених пунктів призначення (allow-list). Він потребує спеціального огляду безпеки перед публічним вивченням. |

## Потрібні виправлення документації

1. Додайте шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з плейсхолдерами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Задокументуйте локальний `uploads/` для v1 та персистентність R2 для v2 як окремі робочі процеси, що наразі співіснують.
4. Не описуйте резервний варіант із випадковими криптографічними ключами як безпечний для продакшну.
