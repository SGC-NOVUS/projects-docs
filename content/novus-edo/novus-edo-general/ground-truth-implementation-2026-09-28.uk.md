# Ground truth: реалізація Novus Flow.EDO

**Status:** internal static audit of the checkout on 2026-09-28.
**Scope:** Vue frontend routes, Express server composition, Prisma/R2 persistence, crypto, converter and environment reads. Цей документ описує реалізовану поведінку, а не відповідність вимогам чи юридичну сертифікацію.

## Виконувана форма

Додаток є браузерним клієнтом на Vue/Vite плюс Express API, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські служби підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Persistence | Prisma 7 з адаптером MariaDB; запасним варіантом для `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Object storage | Cloudflare R2 через AWS S3 SDK, з підписаними URL-адресами для завантаження/скачування |
| Mail | Resend плюс рендеринг Vue Email |
| Converter | Незалежна HTTP-служба на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |

| Підписування у браузері | Приватні ключі документів залишаються на боці браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або службовий `JWT_SECRET` лише за умов `NODE_ENV=production`, встановлює CORS з `CORS_ORIGIN` або `*`, підключає маршрути та обслуговує `dist/` у продакшн-режимі.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридичні документи та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, створення та робочий процес перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточні дані користувача за наявності токена та перенаправляє неавтентифіковані захищені переходи на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першому стовпці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за email/паролем та КЕП/ІПН, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організації та керування учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес локального завантаження документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Точка доступу магазину опціонально приймає bearer-токен; читання є публічним | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр типів документів робочого простору |

API не має зафіксованого в репозиторії документа OpenAPI. Роутер і ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження зчитує цей шлях у файловій системі; створення архіву виконує стрімінг із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує ключі об'єктів R2. Він видає попередньо підписану URL-адресу для завантаження на п'ять хвилин і завантажує підписи / файли PAdES в R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Засоби запису R2 використовують шифрування на стороні сервера `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функції |
| --- | --- | --- | --- |
| `NODE_ENV` | рядок; production активує примусове застосування JWT та статичну роздачу | `server/index.ts` | Межа запуску |
| `PORT` | ціле число / рядок; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL MariaDB; незахищений локальний запасний варіант вказано вище | `server/db.ts` | Критично для функціонування всієї персистентності |
| `JWT_SECRET` | секрет; у середовищі production має відрізнятися від контрольного значення | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | секрет із 64 шістнадцяткових символів; випадковий резервний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | секрет; випадковий резервний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексів |
| `CORS_ORIGIN` | рядок походження; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | кінцева точка/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функцій v2 / публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет і URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для доставки електронної пошти / посилань |
| `SOFFICE_PATH` | ім'я/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично лише для служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища локально для сервісу | шляхи до коду воркера/черги | Критично лише там, де запущено воркер черги |

Жодного зафіксованого у репозиторії файла `.env.example` чи `.env.sample` не знайдено. README згадує лише частину цього списку та пропускає `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за сліпим індексом (blind-index) змінюється після перезапуску. Це слід розглядати як збій конфігурації у продакшені, а не як безпечний запасний варіант (fallback). |
| Недійсна довжина ключа шифрування | Операція шифрування/розшифрування викликає помилку (throws), оскільки розібраний шістнадцятковий ключ має довжину не 32 байти. |
| JWT у продакшені не встановлено / вказано значення-індикатор (sentinel) | API реєструє критичну помилку та завершує роботу до початку прослуховування портів. |
| R2 недоступний | Виклики збереження v2/public зазнають невдачі та повертають помилки сервера; тимчасові файли Multer не гарантовано очищуються на кожному шляху винятку. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний потік автентифікації/документів все одно може повернути успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) та прослуховує лише петльовий інтерфейс (loopback). |
| Публічний проксі CMP | Проксі приймає надану викликом цільову адресу, евристично нормалізує HTTP/HTTPS та здійснює вихідний запит POST без реалізованого таймауту чи суворого списку дозволених пунктів призначення (allow-list). Він потребує спеціального огляду безпеки перед публічним відкриттям. |

## Потрібні виправлення документації

1. Додати шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Окументирувати локальні `uploads/` для v1 та персистентність R2 для v2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати резервний механізм випадкових криптографічних ключів як безпечний для продуктивного середовища.
