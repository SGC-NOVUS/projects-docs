# Ground truth: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду від 2026-09-28.
**Область:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних середовища. Цей документ описує фактично реалізовану поведінку, а не відповідність стандартам чи юридичну сертифікацію.

## Виконувана структура

Додаток є клієнтом браузера Vue/Vite та Express API, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та сервіси підписання на стороні клієнта |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Persistence | Prisma 7 з адаптером MariaDB; резервним значенням `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Сховище об'єктів | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL для завантаження/вивантаження |
| Пошта | Resend плюс рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, який запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній/маркерний `JWT_SECRET` лише коли `NODE_ENV=production`, налаштовує CORS з `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізований вигляд/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, створення та робочий процес перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Навігаційний guard отримує поточного користувача за наявності токена та перенаправляє неавтентифіковані захищені переходи на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, вказаний у першому стовпчику.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Успадкований (legacy) робочий процес завантаження локальних документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічним | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний/робочого простору реєстр типів документів |

API не має збереженого у репозиторії OpenAPI-документа. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях із файлової системи; створення архіву транслюється з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує ключі об'єктів R2. Він видає п'ятихвилинний попередньо підписаний URL для завантаження та завантажує підписи/PAdES-файли до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифікована відправка використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Операції запису в R2 вимагають серверного шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове використання JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; незахищений локальний резервний варіант показано вище | `server/db.ts` | Критично для функціоналу збереження даних |
| `JWT_SECRET` | secret; у production має відрізнятися від значення sentinel | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; резервний варіант з випадковою генерацією в процесі | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; резервний варіант з випадковою генерацією в процесі | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | endpoint/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки пошти/посилань |
| `SOFFICE_PATH` | назва/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування локальних змінних середовища сервісу | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Не знайдено доданих до репозиторію файлів `.env.example` або `.env.sample`. У README згадано лише частину цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` та налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за blind-index змінюється після перезапуску. Це слід розглядати як помилку конфігурації у продакшені, а не як безпечний резервний варіант. |
| Недійсна довжина ключа шифрування | Операції Encrypt/decrypt викликають виключення, оскільки розібраний hex-ключ має довжину не 32 байти. |
| Production JWT не задано/значення-вартовий (sentinel) | API записує критичну помилку в лог і завершує роботу до початку прослуховування. |
| R2 недоступний | Виклики збереження v2/public зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується для кожного шляху виключення. |
| Електронна пошта недоступна | Поштові функції перехоплюють/записують збої в лог; основний потік автентифікації/документообігу все ще може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується у `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без shell і слухає лише на loopback. |
| Публічний CMP-проксі | Проксі приймає надану викликачем цільову адресу, евристично нормалізує HTTP/HTTPS і робить вихідний POST без реалізованого таймауту чи суворого списку дозволених призначень (allow-list). Він потребує окремого аудиту безпеки перед публічним відкриттям. |

## Необхідні виправлення в документації

1. Додати шаблон реального середовища, який містить усі реалізовані секрети та ключі безперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед тим, як заявляти про наявність стабільного публічного API.
3. Задокументувати локальне збереження v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, які наразі співіснують.
4. Не описувати фолбек на випадковий криптографічний ключ як безпечний для продакшену.
