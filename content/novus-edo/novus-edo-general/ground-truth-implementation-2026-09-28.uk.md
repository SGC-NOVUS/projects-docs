# Фактичний стан: реалізація NOVUS Flow.EDO

**Статус:** внутрішній статичний аудит checkout від 28.09.2026.
**Область аудиту:** маршрути фронтенду Vue, композиція сервера Express, збереження даних Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність стандартам чи юридичну сертифікацію.

## Структура виконання

Додаток складається з браузерного клієнта Vue/Vite та Express API, що запускається за допомогою `tsx server/index.ts`.

| Область | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Збереження даних | Prisma 7 з адаптером MariaDB; резервний `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для вивантаження та завантаження |
| Пошта | Resend та рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або шаблонний `JWT_SECRET` лише тоді, коли `NODE_ENV=production`, налаштовує CORS із `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване представлення / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридична інформація та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Робочий процес списку, створення та перегляду деталей документів |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації отримує поточного користувача за наявності токена та перенаправляє неавтентифіковану захищену навігацію на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першому стовпчику.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід за електронною поштою/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/електронної пошти та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організаціях та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт зберігання опціонально приймає bearer-токен; читання є публічним | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр робочого простору типів документів |

API не має зафіксованого в системі документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежних шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження читає цей шлях файлової системи; створення архіву виконує стрімінг з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він генерує препідписаний URL для завантаження терміном на п'ять хвилин та завантажує підписи / файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шлюзом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Воно створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. За записи в R2 відповідає серверне шифрування `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску / функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує перевірку JWT та статичну роздачу | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний запасний варіант вказано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від мітки-контролера | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку / індексів |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; час дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2 / публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий secret та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів / посилань |
| `SOFFICE_PATH` | executable name/path; `soffice` | `server/converter.mjs` | Критично для функціоналу лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища на рівні локального сервісу | шляхи коду воркера / черги | Критично для функціоналу лише там, де запущено воркер черги |

Жодного зафіксованого `.env.example` або `.env.sample` не знайдено. У README згадано лише частину цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за blind-index змінюється після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний запасний варіант. |
| Недійсна довжина ключа шифрування | Операції шифрування/розшифрування викликають виняток, оскільки розібраний шістнадцятковий ключ не має довжини 32 байти. |
| Production JWT не встановлено / встановлено у вигляді sentinel-значення | API реєструє критичну помилку та завершує роботу перед початком прослуховування портів. |
| R2 недоступний | Виклики збереження v2/public завершуються помилкою та повертають помилки сервера; тимчасові файли Multer не гарантовано очищуються на кожному шляху виникнення винятку. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний потік автентифікації/документів усе ще може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без shell і прослуховує лише loopback. |
| Публічний проксі CMP | Проксі приймає надану викликом цільову адресу, евристично нормалізує HTTP/HTTPS та виконує вихідний POST без реалізованого таймауту чи суворого списку дозволених пунктів призначення. Він потребує спеціального огляду безпеки перед публічним вивченням. |

## Необхідні виправлення документації

1. Додати шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Задокументувати локальне збереження `uploads/` для v1 та персистентність R2 для v2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати випадковий резервний криптоключ (crypto-key fallback) як безпечний для виробничого середовища (production-safe).
