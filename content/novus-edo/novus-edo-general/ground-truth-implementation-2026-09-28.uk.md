# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду станом на 2026-09-28.
**Область охоплення:** маршрути Vue-фронтенду, композиція сервера Express, збереження даних у Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність стандартам чи юридичну сертифікацію.

## Структура виконання

Застосунок складається з браузерного клієнта Vue/Vite та Express API, який запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| UI браузера | Vue 3, Vue Router, Pinia та сервіси підписання на стороні клієнта |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервне значення `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об’єктне сховище | Cloudflare R2 через AWS S3 SDK з попередньо підписаними URL-адресами для завантаження/скачування |
| Пошта | Resend плюс рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої архітектури клієнта; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або значення-заглушку для `JWT_SECRET` лише якщо `NODE_ENV=production`, налаштовує CORS із `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридичні сторінки та ідентифікація |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, створення та детальний робочий процес |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточний профіль користувача за наявності токена та перенаправляє неавтентифіковані запити до захищених розділів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче містять префікс `/api`, зазначений у першому стовпчику.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає bearer token | Вхід через email/пароль та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організаціях та керування учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Застарілий робочий процес локального завантаження документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт зберігання опціонально приймає bearer-токен; читання є публічними | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр типів документів робочого простору |

API не має зафіксованого у сховищі документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та сховища об'єктів

Існує два незалежних шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` та зберігає локальні шляхи в базі даних. Оригінальне завантаження читає цей шлях файлової системи; створення архіву виконує стрімінг із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він генерує п'ятихвилинний підписаний URL для завантаження та завантажує підписи / файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Це створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. За записи в R2 відповідає серверне шифрування запитів `AES256`.

## Реєстр середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове застосування JWT та сталу роздачу | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; незахищений локальний запасний варіант вказано вище | `server/db.ts` | Критично для функціоналу всієї персистентності |
| `JWT_SECRET` | secret; у production має відрізнятися від початкового | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий запасний варіант процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексів |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; час дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий secret та URL; `APP_URL` за замовчуванням `http://localhost:5173` у поштовій службі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування середовища на рівні локального сервісу | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Не знайдено жодного доданого до репозиторію `.env.example` або `.env.sample`. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутність/зміна `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за сліпим індексом (blind-index) змінюється після перезапуску. Це слід розглядати як збій конфігурації у production, а не як безпечний запасний варіант (fallback). |
| Недійсна довжина ключа шифрування | Операції шифрування/розшифрування викликають помилку (throw), оскільки розібраний hex-ключ має довжину не 32 байти. |
| JWT у production не встановлено або використовує sentinel-значення | API реєструє критичну помилку та завершує роботу перед початком прослуховування портів. |
| R2 недоступний | Виклики персистентності v2/public завершуються з помилкою та повертають помилки сервера; тимчасові файли Multer не гарантовано очищуються на кожному шляху виключення (exception path). |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють збої; основний потік автентифікації/документів все одно може повернути успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 MiB, запускає LibreOffice без shell і прослуховує лише loopback-інтерфейс. |
| Публічний CMP проксі | Проксі приймає надану викликом цільову адресу, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST-запит без реалізованого таймауту або суворого списку дозволених пунктів призначення (allow-list). Він потребує ретельного перевірення безпеки перед публічним доступом. |

## Потрібні виправлення документації

1. Додати шаблон реального середовища, який включає всі імплементовані секрети та ключі збереження стану, лише з полями-заповнювачами (placeholders).
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням публічного API стабільним.
3. Документувати локальний v1 `uploads/` та персистентність v2 R2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати резервний механізм випадкових криптографічних ключів як безпечний для production.
