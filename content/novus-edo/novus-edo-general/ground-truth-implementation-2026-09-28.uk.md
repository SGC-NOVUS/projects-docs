# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду станом на 2026-09-28.
**Область аудиту:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність стандартам чи юридичну сертифікацію.

## Структура виконання

Застосунок складається з браузерного клієнта Vue/Vite та Express API, який запускається через `tsx server/index.ts`.

| Компонент | Фактична реалізація |
| --- | --- |
| Браузерний UI | Vue 3, Vue Router, Pinia та клієнтські служби підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервний `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для завантаження/скачування |
| Пошта | Resend та рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, який запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання в браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої архітектури клієнта; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або маркерний `JWT_SECRET` лише коли `NODE_ENV=production`, налаштовує CORS з `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у production.

## Маршрути браузера

| Маршрут | Вимога до автентифікації | Реалізований вигляд/призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, створення та робочий процес перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Навігаційний захисник отримує поточного користувача за наявності токена та перенаправляє неавтентифіковану захищену навігацію на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, показаний у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає токен Bearer | Вхід за email/паролем та КЕП/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Токен Bearer | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Токен Bearer | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Токен Bearer | Застарілий робочий процес завантаження локальних документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Токен Bearer | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; операції читання є публічними | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний/робочого простору реєстр типів документів |

API не має збереженого в репозиторії документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу зчитує цей шлях у файловій системі; створення архіву виконує потокове зчитування з цього локального стану.
2. `/api/v2/documents` зберігає метадані пакета в Prisma та використовує ключі об'єктів R2. Він видає п'ятихвилинний попередньо підписаний URL для завантаження та завантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифікована відправка використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 запитують шифрування на стороні сервера `AES256`.

## Реєстр змінних оточення

| Змінна | Тип/за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | рядок; production активує примусове використання JWT та роздачу статичного контенту | `server/index.ts` | Межа запуску |
| `PORT` | ціле число/рядок; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | URL MariaDB; небезпечний локальний резервний варіант показано вище | `server/db.ts` | Критично для функціоналу збереження даних |
| `JWT_SECRET` | секретний ключ; у production повинен відрізнятися від значення-сторожа (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-значний hex-секрет; випадкове значення процесу як резервний варіант | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | секретний ключ; випадкове значення процесу як резервний варіант | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок походження (origin); `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | еліпсоїд/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет і URL; `APP_URL` за замовчуванням дорівнює `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки листів/посилань |
| `SOFFICE_PATH` | ім'я/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу тільки для сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування локальних змінних оточення сервісу | шляхи коду воркера/черги | Критично для функціоналу тільки там, де запущено воркер черги |

Не знайдено зафіксованих у репозиторії файлів `.env.example` або `.env.sample`. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` та налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за сліпим індексом (blind-index) змінюється після перезапуску. Це слід розглядати як помилку конфігурації у продакшені, а не як безпечний варіант за замовчуванням. |
| Недійсна довжина ключа шифрування | Операції шифрування/розшифрування викликають помилку, оскільки розібраний hex-ключ не дорівнює 32 байтам. |
| JWT для продакшену не задано/значення sentinel | API записує критичну помилку в журнал і завершує роботу до початку прослуховування. |
| R2 недоступний | Виклики збереження даних v2/public зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується для кожного шляху виключення. |
| Електронна пошта недоступна | Поштові функції перехоплюють/записують у журнал помилки; основний потік автентифікації/документообігу все ще може повертати успішний результат. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується в блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і прослуховує лише loopback. |
| Публічний CMP-проксі | Проксі приймає цільову адресу, надану клієнтом, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST-запит без реалізованого таймауту або суворого білого списку призначень (allow-list). Він потребує окремого аудиту безпеки перед публічним відкриттям. |

## Необхідні виправлення в документації

1. Додайте реальний шаблон середовища, який містить усі реалізовані секрети та ключі безперервності стану, лише із заповнювачами.
2. Опублікуйте згенерований контракт OpenAPI з файлів маршрутів Express, перш ніж заявляти про стабільний публічний API.
3. Задокументуйте локальне збереження v1 в `uploads/` та збереження v2 в R2 як окремі робочі процеси, які наразі співіснують.
4. Не описуйте фолбек із випадковим криптографічним ключем як безпечний для продакшену.
