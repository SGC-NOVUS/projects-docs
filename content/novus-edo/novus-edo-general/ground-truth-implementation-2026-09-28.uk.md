# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит чекауту від 2026-09-28.
**Обсяг:** маршрути фронтенду Vue, композиція сервера Express, персистентність Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність нормативним вимогам чи юридичну сертифікацію.

## Структура виконання

Застосунок складається з клієнта для браузера на базі Vue/Vite та Express API, що запускається за допомогою `tsx server/index.ts`.

| Область | Фактична реалізація |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські сервіси підпису |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Персистентність | Prisma 7 з адаптером MariaDB; резервним значенням для `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з presigned URL-адресами для завантаження/вивантаження |
| Пошта | Resend та рендеринг через Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підпис у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або сигнальний (sentinel) `JWT_SECRET` лише за умови `NODE_ENV=production`, налаштовує CORS за допомогою `CORS_ORIGIN` або `*`, монтує маршрути та роздає `dist/` у режимі production.

## Маршрути браузера

| Route | Auth requirement | Implemented view/meaning |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, робочий процес створення та перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Navigation guard отримує дані поточного користувача, якщо токен існує, і перенаправляє неавтентифіковані спроби переходу до захищених розділів на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, наведений у першому стовпці.

| Prefix | Operations | Authentication | Purpose |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь щодо працездатності процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` потрібен bearer-токен | Вхід за email/паролем та KEP/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організації та керування учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічним | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр / реєстр робочого простору типів документів |

В API немає зафіксованого в репозиторії документа OpenAPI. Роутер і ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу читає цей шлях у файловій системі; створення архіву передається потоком із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує об'єктні ключі R2. Він видає п'ятихвилинний попередньо підписаний URL для завантаження та вивантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане надсилання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи до R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціональності |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує обов'язкове застосування JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний резервний варіант наведено вище | `server/db.ts` | Критично для функціональності збереження всіх даних |
| `JWT_SECRET` | secret; у production має відрізнятися від sentinel | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-символьний hex-секрет; резервне випадкове значення для процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; резервне випадкове значення для процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | рядок origin; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | ендпоінт/облікові дані R2; термін дії `900` секунд | `server/storageService.ts` | Критично для функціональності об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | поштовий секрет та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціональності доставки пошти/посилань |
| `SOFFICE_PATH` | назва/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціональності лише для сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування локального середовища сервісу | шляхи виконання коду воркера/черги | Критично для функціональності лише там, де запущено воркер черги |

Не знайдено зафіксованого у репозиторії `.env.example` або `.env.sample`. У README згадується лише частина цього списку та пропущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля стає неможливо розшифрувати, а безперервність пошуку за сліпим індексом порушується після перезапуску. Це слід розцінювати як збій конфігурації продакшену, а не як безпечний резервний механізм. |
| Недійсна довжина ключа шифрування | Операції encrypt/decrypt генерують виняток, оскільки розібраний hex-ключ не дорівнює 32 байтам. |
| JWT для продакшену не встановлено або задано як sentinel | API логує критичну помилку та завершує роботу до початку прослуховування портів. |
| R2 недоступний | Виклики збереження даних v2/public зазнають збою та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується на кожній гілці обробки винятків. |
| Електронна пошта недоступна | Поштові функції перехоплюють/логують збої; основний потік автентифікації/роботи з документами все одно може повернути успішний статус. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується в блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і слухає лише loopback-інтерфейс. |
| Публічний проксі CMP | Проксі приймає цільову адресу, передану ініціатором виклику, евристично нормалізує HTTP/HTTPS і виконує вихідний запит POST без реалізованого таймауту або суворого списку дозволених адрес призначення (allow-list). Потрібен окремий аудит безпеки перед відкриттям публічного доступу. |

## Необхідні виправлення документації

1. Додайте шаблон реального середовища, який містить усі реалізовані секрети та ключі безперервності стану, лише з плейсхолдерами.
2. Опублікуйте згенерований контракт OpenAPI із файлів маршрутів Express, перш ніж заявляти про наявність стабільного публічного API.
3. Задокументуйте локальне збереження v1 в uploads/ та збереження v2 в R2 як окремі робочі процеси, які наразі співіснують.
4. Не описуйте використання випадкового криптографічного ключа як резервного варіанта (fallback) як безпечне для продакшену.
