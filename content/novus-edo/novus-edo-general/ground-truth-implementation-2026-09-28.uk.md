# Ground truth: реалізація Novus Flow.EDO

**Status:** internal static audit of the checkout on 2026-09-28.
**Scope:** Vue frontend routes, Express server composition, Prisma/R2 persistence, crypto, converter and environment reads. Цей документ описує реалізовану поведінку, а не сертифікацію відповідності чи юридичну сертифікацію.

## Executable shape

Додаток складається з браузерного клієнта Vue/Vite та API Express, що запускається за допомогою `tsx server/index.ts`.

| Surface | Actual implementation |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia та клієнтські послуги підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Persistence | Prisma 7 з адаптером MariaDB; резервний варіант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Object storage | Cloudflare R2 через AWS S3 SDK з попередньо підписаними URL-адресами завантаження/завантаження |
| Mail | Resend плюс рендеринг Vue Email |
| Converter | Незалежна служба HTTP на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |

| Підписування у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підписів і метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або службовий `JWT_SECRET` лише за умови `NODE_ENV=production`, встановлює CORS з `CORS_ORIGIN` або `*`, підключає маршрути та обслуговує `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване представлення / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні екрани, юридична інформація та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Робочий процес списку, створення та перегляду деталей документів |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Захисник навігації (navigation guard) отримує поточного користувача за наявності токена та перенаправляє неавтентифіковані захищені переходи на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, зазначений у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан здоров'я процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає Bearer-токен | Вхід за email/паролем та КЕП/РНОКПП, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в організаціях та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Застарілий робочий процес документів із локальним завантаженням |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; читання є публічним | Публічна верифікація підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний реєстр типів документів робочого простору |

API не має збереженого в репозиторії документа OpenAPI. Роутер та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежних шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Оригінальне завантаження зчитує цей шлях у файловій системі; створення архіву передається потоком із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він видає п'ятихвилинний попередньо підписаний URL для завантаження та завантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна верифікація зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане відправлення використовує `individuals/<user ID>/documents/<verification ID>/...`. Воно створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 запитують серверне шифрування `AES256`.

## Реєстр змінних середовища

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує обов'язкову перевірку JWT та роздачу статичного контенту | `server/index.ts` | Критично для запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Критично для запуску |
| `DATABASE_URL` | MariaDB URL; небезпечний локальний резервний варіант показано вище | `server/db.ts` | Критично для роботи всіх механізмів збереження даних |
| `JWT_SECRET` | secret; у production має відрізнятися від значення-заглушки (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; резервний варіант із випадковою генерацією в процесі | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; резервний варіант із випадковою генерацією в процесі | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для роботи об'єктів v2/публічних об'єктів |
| `RESEND_API_KEY`, `APP_URL` | секретний ключ пошти та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовій службі EDO | `server/emailService.ts` | Критично для доставки електронної пошти/посилань |
| `SOFFICE_PATH` | ім'я/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для роботи тільки служби конвертації |
| `REDIS_HOST`, `REDIS_PORT` | локальні для сервісу зчитування середовища | шляхи коду worker/queue | Критично для роботи тільки там, де запущено воркер черги |

Не було знайдено зафіксованих у репозиторії `.env.example` або `.env.sample`. У файлі README згадується лише частина цього списку та пропускаються `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими відмов та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля не можуть бути розшифровані, а безперервність пошуку за blind-index змінюється після перезапуску. Це слід розглядати як конфігураційну помилку в продакшені, а не як безпечний запасний варіант. |
| Недійсна довжина ключа шифрування | Операція шифрування/розшифрування викликає виняток, оскільки розібраний hex-ключ не має довжини 32 байти. |
| JWT у продакшені не задано / встановлено значення за замовчуванням (sentinel) | API реєструє критичну помилку та завершує роботу перед початком прослуховування портів. |
| R2 недоступний | Виклики збереження v2/public завершуються помилкою та повертають помилки сервера; тимчасові файли Multer не гарантовано очищуються на кожному шляху виникнення винятків. |
| Електронна пошта недоступна | Поштові функції перехоплюють/реєструють помилки; основний процес автентифікації/роботи з документами все одно може повертати успішний результат. |
| Конвертер не має LibreOffice | `/api/convert` повертає `422`; очищення тимчасової директорії виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і прослуховує запити лише на loopback-інтерфейсі. |
| Публічний CMP-проксі | Проксі приймає надану викликом цільову адресу, евристично нормалізує HTTP/HTTPS і виконує вихідний POST-запит без реалізованого таймауту чи суворого списку дозволених адрес призначення (allow-list). Він потребує спеціального огляду безпеки перед публічним випуском. |

## Потрібні виправлення документації

1. Додати шаблон реального середовища, який містить усі реалізовані секрети та ключі забезпечення неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням стабільного публічного API.
3. Задокументувати локальне персистентне сховище `uploads/` для v1 та персистентне сховище R2 для v2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати резервний механізм випадкових криптографічних ключів як безпечний для production.
