# Фактичний стан: реалізація Novus Flow.EDO

**Статус:** внутрішній статичний аудит зрізу коду станом на 2026-09-28.
**Область аудиту:** маршрути Vue-фронтенду, композиція Express-сервера, збереження даних Prisma/R2, криптографія, конвертер та зчитування змінних оточення. Цей документ описує реалізовану поведінку, а не відповідність нормам чи юридичну сертифікацію.

## Структура виконання

Додаток складається з браузерного клієнта Vue/Vite та Express API, що запускається через `tsx server/index.ts`.

| Поверхня | Фактична реалізація |
| --- | --- |
| UI браузера | Vue 3, Vue Router, Pinia та клієнтські сервіси підписання |
| API | Express 5 на `PORT`, за замовчуванням `3001` |
| Збереження даних | Prisma 7 з адаптером MariaDB; резервним значенням `DATABASE_URL` є `mysql://novus:novus123@localhost:3306/novus_edo` |
| Об'єктне сховище | Cloudflare R2 через AWS S3 SDK, з попередньо підписаними URL-адресами для вивантаження/завантаження |
| Пошта | Resend та рендеринг Vue Email |
| Конвертер | Незалежний HTTP-сервіс на `127.0.0.1:4174`, що запускає LibreOffice (`SOFFICE_PATH` або `soffice`) |
| Підписання у браузері | Приватні ключі документів залишаються на стороні браузера відповідно до реалізованої клієнтської архітектури; сервер зберігає артефакти підпису та метадані |

`server/index.ts` завантажує dotenv, відхиляє відсутній або фіктивний `JWT_SECRET` лише коли `NODE_ENV=production`, налаштовує CORS із `CORS_ORIGIN` або `*`, монтує маршрути та надає доступ до `dist/` у продакшені.

## Маршрути браузера

| Маршрут | Вимога автентифікації | Реалізоване подання / призначення |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Ні | Публічні, юридичні екрани та екрани ідентифікації |
| `/dashboard` | Так | Наразі повторно використовує `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Так | Список документів, створення та робочий процес перегляду деталей |
| `/contacts`, `/archive`, `/settings` | Так | Адресна книга, архів та налаштування |
| `/features`, `/pricing` | Ні | Перенаправлення на `/` |

Навігаційний захисник (navigation guard) отримує поточного користувача за наявності токена та перенаправляє неавтентифіковані запити до захищених сторінок на `/login` (`src/router/index.ts`).

## Каталог Express API

Усі шляхи нижче мають префікс `/api`, вказаний у першій колонці.

| Префікс | Операції | Автентифікація | Призначення |
| --- | --- | --- | --- |
| `/health` | `GET` | Ні | Базова відповідь про стан (health) процесу |
| `/proxy` | `POST` | Ні | Бінарний проксі для трафіку EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` вимагає Bearer token | Вхід за допомогою email/пароля та КЕП/TIN, реєстрація та верифікація |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Оновлення профілю/email та встановлення/зміна пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в організації та управління учасниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Успадкований (legacy) робочий процес локального завантаження документів |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Робочий процес DocumentPackage зі сховищем R2 та маршрутизацією учасників |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Ендпоінт збереження опціонально приймає bearer-токен; операції читання є публічними | Публічна перевірка підпису та завантаження протоколу |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальний/робочого простору реєстр типів документів |

API не має закоміченого документа OpenAPI. Маршрутизатор та ці вихідні файли є поточним HTTP-контрактом.

## Поведінка даних та об'єктного сховища

Існує два незалежні шляхи збереження документів:

1. Застарілий `/api/documents` використовує Multer `uploads/` і зберігає локальні шляхи в базі даних. Завантаження оригіналу читає цей шлях у файловій системі; створення архіву передається потоком із цього локального стану.
2. `/api/v2/documents` зберігає метадані пакетів у Prisma та використовує ключі об'єктів R2. Він видає п'ятихвилинний попередньо підписаний URL для завантаження та вивантажує підписи/файли PAdES до R2 після того, як Multer отримує їх локально.

Публічна перевірка зберігає анонімні об'єкти за шляхом `unclaimed/<RNOKPP>/<document UUID>/...`; автентифіковане подання використовує `individuals/<user ID>/documents/<verification ID>/...`. Вона створює або повторно використовує фіксований системний обліковий запис для анонімних збережених пакетів. Записи в R2 запитують шифрування на стороні сервера `AES256`.

## Реєстр змінних оточення

| Змінна | Тип/значення за замовчуванням | Де використовується | Критичність для запуску/функціоналу |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активує примусове застосування JWT та роздачу статики | `server/index.ts` | Межа запуску |
| `PORT` | integer/string; `3001` | `server/index.ts` | Межа запуску |
| `DATABASE_URL` | MariaDB URL; незахищене локальне резервне значення показано вище | `server/db.ts` | Критично для функціоналу збереження даних |
| `JWT_SECRET` | secret; у production має відрізнятися від сентинела | `server/index.ts`, `server/middleware/auth.ts` | Критично для безпеки |
| `ENCRYPTION_KEY` | 64-hex-char secret; випадковий резервний варіант на рівні процесу | `server/utils/crypto.ts` | Критично для безпеки та читання даних |
| `BLIND_INDEX_SECRET` | secret; випадковий резервний варіант на рівні процесу | `server/utils/crypto.ts` | Критично для безперервності пошуку/індексації |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Межа безпеки |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 endpoint/облікові дані; термін дії `900` секунд | `server/storageService.ts` | Критично для функціоналу об'єктів v2/public |
| `RESEND_API_KEY`, `APP_URL` | секрет пошти та URL; `APP_URL` за замовчуванням має значення `http://localhost:5173` у поштовому сервісі EDO | `server/emailService.ts` | Критично для функціоналу доставки пошти/посилань |
| `SOFFICE_PATH` | назва/шлях до виконуваного файлу; `soffice` | `server/converter.mjs` | Критично для функціоналу лише сервісу конвертації |
| `REDIS_HOST`, `REDIS_PORT` | зчитування змінних оточення локально для сервісу | шляхи коду воркера/черги | Критично для функціоналу лише там, де запущено воркер черги |

Зафіксованих у репозиторії файлів `.env.example` або `.env.sample` не знайдено. У README згадується лише частина цього списку та випущено `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` і налаштування Redis.

## Режими збоїв та обмеження реалізації

| Ситуація | Спостережувана поведінка |
| --- | --- |
| Відсутній/змінений `ENCRYPTION_KEY` або `BLIND_INDEX_SECRET` | Процес генерує новий випадковий ключ/секрет. Раніше зашифровані поля неможливо розшифрувати, а безперервність пошуку за сліпим індексом змінюється після перезапуску. Це слід розглядати як збій конфігурації продакшену, а не як безпечний аварійний режим (fallback). |
| Некоректна довжина ключа шифрування | Операції шифрування/розшифрування завершуються помилкою (throws), оскільки розібраний hex-ключ не дорівнює 32 байтам. |
| Продакшен JWT не встановлено/встановлено у значення-маркер (sentinel) | API записує критичну помилку в журнал і завершує роботу до початку прослуховування. |
| R2 недоступний | Виклики збереження даних v2/public зазнають невдачі та повертають помилки сервера; очищення тимчасових файлів Multer не гарантується при кожному шляху обробки винятків (exception path). |
| Email недоступний | Функції пошти перехоплюють/записують збої в журнал; основний потік автентифікації/документообігу все ще може повертати успішну відповідь. |
| У конвертері відсутній LibreOffice | `/api/convert` повертає `422`; очищення тимчасового каталогу виконується у блоці `finally`. |
| Вхідні дані конвертера | Конвертер приймає один підтримуваний офісний файл розміром до 25 МіБ, запускає LibreOffice без оболонки (shell) і прослуховує тільки loopback. |
| Публічний CMP-проксі | Проксі приймає цільову адресу, надану викликачем, евристично нормалізує HTTP/HTTPS і здійснює вихідний POST-запит без реалізованого таймауту або суворого списку дозволених призначень (allow-list). Він потребує окремого аналізу безпеки перед публічним відкриттям. |

## Поточні виправлення документації

1. Додати шаблон реального середовища, який містить усі імплементовані секрети та ключі забезпечення неперервності стану, лише з плейсхолдерами.
2. Опублікувати згенерований контракт OpenAPI з файлів маршрутів Express перед оголошенням публічного API стабільним.
3. Задокументувати локальний `uploads/` у v1 та персистентність R2 у v2 як окремі робочі процеси, що наразі співіснують.
4. Не описувати резервне використання випадкових криптоключів як безпечне для продакшну.
