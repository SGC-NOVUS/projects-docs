# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит чек-аута по состоянию на 2026-09-28.
**Область:** маршруты Vue frontend, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и службы клиентской подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL-адресами загрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимая HTTP-служба на `127.0.0.1:4174`, порождающая процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерная подпись | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или заменяющий его `JWT_SECRET` только когда `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны аутентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Рабочий процесс списка, создания и просмотра деталей документов |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на страницу `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/изменение пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение публично | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочей области |

У API нет зафиксированного документа OpenAPI. Роутер и эти исходные файлы служат текущим HTTP-контрактом.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала читает этот путь в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует объектные ключи R2. Он выдает предварительно подписанный URL для загрузки со сроком действия пять минут и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Процесс создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип / значение по умолчанию | Где используется | Критичность для запуска / функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительное использование JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для функционала персистентного хранения |
| `JWT_SECRET` | secret; в production должен отличаться от эталонного значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 hex-символов; случайный резервный вариант на уровне процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайный резервный вариант на уровне процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для функционала доставки почты/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функционала только для службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локальных для сервиса переменных окружения | пути в коде воркера/очереди | Критично для функционала только там, где запущен воркер очереди |

В репозитории не найдено закоммиченных файлов `.env.example` или `.env.sample`. Файл README содержит только часть этого списка и опускает `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоя и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствующий или измененный `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу (blind-index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в продакшене, а не как безопасный аварийный режим. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифровки вызывают исключение, так как разобранный hex-ключ не равен 32 байтам. |
| Production JWT не задан или содержит значение-заглушку (sentinel) | API логирует критическую ошибку и завершает работу до начала прослушивания порта. |
| Недоступность R2 | Вызовы сохранения v2/public завершаются с ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется при каждом пути выполнения исключения. |
| Недоступность электронной почты | Почтовые функции перехватывают/логируют ошибки; основной поток аутентификации/документооборота все еще может возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | Эндпоинт `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и прослушивает только loopback-интерфейс. |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка разрешенных назначений. Требуется отдельный аудит безопасности перед публичным использованием. |

## Требуемые исправления документации

1. Добавьте шаблон реального окружения, включающий все реализованные секреты и ключи непрерывности состояния, содержащий только плейсхолдеры.
2. Опубликуйте сгенерированный контракт OpenAPI на основе файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументируйте локальное хранение v1 в `uploads/` и персистентное хранение v2 в R2 как отдельные, в настоящее время сосуществующие процессы.
4. Не описывайте фолбэк со случайным криптоключом как безопасный для production.
