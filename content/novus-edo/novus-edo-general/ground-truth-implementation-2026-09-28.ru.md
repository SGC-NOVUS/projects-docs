# Источник истины: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления заказа по состоянию на 2026-09-28.
**Область:** маршруты frontend на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL-адресами для загрузки и скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерное подписание | Заключенные в документах приватные ключи остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Общедоступные юридические экраны и экраны управления учетными записями |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Рабочий процесс списка, создания и просмотра деталей документов |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) получает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная конечная точка сохранения опционально принимает bearer-токен; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр типов документов / реестр типов документов воркспейса |

Для API отсутствует зафиксированный в репозитории документ OpenAPI. Текущим HTTP-контрактом являются маршрутизатор и эти исходные файлы.

## Поведение данных и объектного хранилища

Существуют два независимых пути персистентности документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Первоначальное скачивание считывает этот путь файловой системы; создание архива выполняется путем стриминга из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он генерирует преподписанный URL для загрузки со сроком действия пять минут и загружает подписи/файлы PAdES в R2 после их получения Multer локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. При записи в R2 запрашивается серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функций |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительную проверку JWT и статические раздачи | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный запасной вариант указан выше | `server/db.ts` | Критично для функций для всех персистентных данных |
| `JWT_SECRET` | секрет; в production должен отличаться от контрольного значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 шестнадцатеричных символов; запасной вариант — случайный процесс | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; запасной вариант — случайный процесс | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функций для объектов v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | почтовый секрет и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для функций доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функций только для службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения локально для службы | кодовые пути воркера/очереди | Критично для функций только там, где запускается воркер очереди |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается лишь часть этого списка, а `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis опущены.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` либо `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепым индексам (blind-index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный запасной вариант. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифрования вызывают исключение, так как разобранный hex-ключ не равен 32 байтам. |
| JWT для production не задан или используется sentinel-значение | API записывает в лог критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется для каждого пути исключений. |
| Электронная почта недоступна | Почтовые функции перехватывают и логируют сбои; основной поток аутентификации или работы с документами все равно может вернуть успех. |
| Конвертер не нашел LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и принимает соединения только на loopback-интерфейсе. |
| Публичный прокси CMP | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий запрос POST без реализации таймаута или строгого списков разрешенных адресов назначения (allow-list). Перед публичным доступом требуется специализированный анализ безопасности. |

## Требуемые исправления документации

1. Добавить реальный шаблон окружения, содержащий все реализованные секреты и ключи обеспечения непрерывности состояния, исключительно с плейсхолдерами.
2. Опубликовать сгенерированный OpenAPI контракт из файлов маршрутов Express до заявления о стабильном публичном API.
3. Задокументировать локальный `uploads/` в v1 и персистентность R2 в v2 как раздельные, сосуществующие в настоящее время рабочие процессы.
4. Не описывать запасной вариант с генерацией случайных криптоключей как безопасный для production.
