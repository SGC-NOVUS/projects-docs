# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 28.09.2026.
**Область применения:** маршруты Vue frontend, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент Vue/Vite плюс API Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL-адресами выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерное подписание | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

Файл `server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Общедоступные юридические экраны и экраны идентификации |
| `/dashboard` | Да | В настоящее время использует повторно `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, рабочий процесс создания и просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) получает текущего пользователя при наличии токена и перенаправляет неавторизованные защищенные переходы на страницу `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer-токен | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/изменение пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная конечная точка сохранения опционально принимает bearer-токен; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр типов документов рабочей области / пространства |

Для данного API отсутствует зафиксированный в системе документ OpenAPI. Роутер и эти исходные файлы представляют собой текущий контракт HTTP.

## Поведение данных и объектного хранилища (object-storage)

Существует два независимых пути персистентности документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Первоначальное скачивание читает этот путь файловой системы; создание архива происходит потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает предварительно подписанный (presigned) URL для загрузки сроком на пять минут и загружает подписи / файлы PAdES в R2 после их получения локально через Multer.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запросы на запись в R2 используют серверное шифрование `AES256`.

## Реестр переменных окружения

| Variable | Type/default | Where used | Startup/feature criticality |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует обязательную проверку JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный fallback приведен выше | `server/db.ts` | Критично для персистентности всех данных |
| `JWT_SECRET` | secret; в production должен отличаться от контрольного значения (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 hex-символов; случайный fallback на уровне процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайный fallback на уровне процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функциональности объектов v2/public |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь к исполняемому файлу; `soffice` | `server/converter.mjs` | Критично только для сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локального окружения сервиса | кодовые пути worker/queue | Критично только там, где запущен queue worker |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В файле README упоминается лишь часть этого списка и пропущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Failure modes and implementation limits

| Situation | Observed behavior |
| --- | --- |
| Missing/changed `ENCRYPTION_KEY` or `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по blind index нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации продакшена, а не как безопасный фолбэк. |
| Invalid encryption key length | Операции шифрования/расшифрования генерируют исключение, поскольку распарсенный hex-ключ не равен 32 байтам. |
| Production JWT unset/sentinel | API регистрирует критическую ошибку в логах и завершает работу до начала прослушивания порта. |
| R2 unavailable | Вызовы сохранения v2/public завершаются сбоем и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется на всех путях обработки исключений. |
| Email unavailable | Почтовые функции перехватывают/логируют ошибки; основной поток аутентификации/документооборота может продолжать возвращать успешный статус. |
| Converter missing LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Converter input | Конвертер принимает один поддерживаемый офисный файл размером до 25 MiB, запускает LibreOffice без оболочки (shell) и слушает только интерфейс loopback. |
| Public CMP proxy | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий запрос POST без реализованного таймаута или строгого белого списка разрешенных адресов назначения. Требуется проведение отдельного аудита безопасности перед открытием публичного доступа. |

## Требуемые исправления документации

1. Добавить реальный шаблон переменных окружения, включающий все реализованные секреты и ключи непрерывности состояния, содержащий только плейсхолдеры.
2. Опубликовать сгенерированный контракт OpenAPI на основе файлов маршрутов Express, прежде чем заявлять о стабильном публичном API.
3. Задокументировать локальное хранение данных v1 `uploads/` и персистентность v2 в R2 как отдельные, сосуществующие в настоящее время рабочие процессы.
4. Не описывать fallback на случайный криптографический ключ как безопасный для production.
