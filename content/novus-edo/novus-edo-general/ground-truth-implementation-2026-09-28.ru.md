# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 28.09.2026.
**Область применения:** маршруты Vue frontend, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В данном документе описывается реализованное поведение, а не соответствие стандартам или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL для выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерная подпись | Приватные ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

Файл `server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и раздает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, экраны с правовой информацией и аутентификацией |
| `/dashboard` | Да | В настоящий момент повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Рабочий процесс списка, создания и детального просмотра документов |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Store endpoint optionally accepts bearer token; reads are public | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр типов документов / реестр типов документов рабочей области |

У API нет зафиксированного документа OpenAPI. Маршрутизатор и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути персистентности документов:

1. Устаревший путь `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Первоначальное скачивание читает этот путь файловой системы; создание архива выполняет стриминг из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает предварительно подписанный (presigned) URL для загрузки со сроком действия пять минут и загружает подписи/файлы PAdES в R2 после их получения Multer локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. При записи в R2 запрашивается серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функций |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительную проверку JWT и статические раздачи | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный запасной вариант указан выше | `server/db.ts` | Критично для функций постоянного хранения |
| `JWT_SECRET` | secret; в production должно отличаться от контрольного значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-hex-char secret; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 эндпоинт/учетные данные; срок действия `900` секунд | `server/storageService.ts` | Критично для функций v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | почтовый секрет и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | локальные для службы чтения из окружения | кодовые пути воркера/очереди | Критично только при запуске воркера очереди |

Не найдено зафиксированных в репозитории файлов `.env.example` или `.env.sample`. В файле README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу изменяется после перезапуска. Это должно рассматриваться как ошибка конфигурации промышленной среды, а не как безопасный резервный механизм. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифровки вызывают исключение, так как разобранный hex-ключ содержит не 32 байта. |
| JWT для промышленной среды не задан или содержит значение-заглушку | API логирует критическую ошибку и завершает работу до начала приема подключений. |
| Недоступность R2 | Вызовы сохранения данных v2/public завершаются с ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется при каждом сценарии исключения. |
| Недоступность электронной почты | Почтовые функции перехватывают и логируют сбои; основной поток аутентификации/документооборота всё ещё может возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | Эндпоинт `/api/convert` возвращает `422`; очистка временного каталога выполняется в `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 MiB, запускает LibreOffice без командной оболочки и принимает подключения только на loopback-интерфейсе. |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и делает исходящий POST-запрос без реализованного таймаута или строгого списка разрешенных назначений. Требуется отдельный аудит безопасности перед открытием публичного доступа. |

## Требуемые исправления документации

1. Добавить шаблон реальной среды, включающий все реализованные секреты и ключи обеспечения непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express перед объявлением публичного API стабильным.
3. Задокументировать локальный `uploads/` v1 и персистентность R2 v2 как отдельные, сосуществующие в данный момент рабочие процессы.
4. Не описывать резервный вариант с генерацией случайных криптоключей как безопасный для production.
