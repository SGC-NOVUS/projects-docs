# Источник истины: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления заказа по состоянию на 2026-09-28.
**Область:** маршруты frontend на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие требованиям или юридическую сертификацию.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL-адресами выгрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимая служба HTTP на `127.0.0.1:4174`, порождающая процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подписание в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной архитектурой клиента; сервер сохраняет артефакты подписи и метаданные |

Файл `server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в продакшене.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Общедоступные юридические экраны и экраны идентификации |
| `/dashboard` | Да | В настоящее время использует `Inbox.vue` повторно |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и детальный рабочий процесс |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации (navigation guard) получает текущего пользователя при наличии токена и перенаправляет неавторизованные защищенные переходы на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/изменение пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная точка входа опционально принимает bearer token; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр / реестр типов документов рабочего пространства |

API не имеет зафиксированного документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий контракт HTTP.

## Поведение данных и объектного хранилища

Существует два независимых пути персистентности документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает путь из этой файловой системы; создание архива выполняется потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает подписанный URL для загрузки со сроком действия пять минут и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запросы на запись в R2 используют шифрование на стороне сервера `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует проверку JWT и статик-сервинг | `server/index.ts` | Граница запуска |
| `PORT` | целое число/строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный фоллбэк указан выше | `server/db.ts` | Критично для всего персистентного хранения |
| `JWT_SECRET` | секрет; в production должен отличаться от эталонного | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 hex-символов; случайный фоллбэк процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный фоллбэк процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 эндпоинт/учетные данные; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для доставки почты / ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения на уровне сервиса | пути кода воркеров/очередей | Критично только при запуске воркера очередей |

Не найдено закоммиченных файлов `.env.example` или `.env.sample`. В README упоминается лишь часть этого списка, а `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis опущены.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие/изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ / секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу (blind-index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации production, а не как безопасный fallback. |
| Неверная длина ключа шифрования | Операции шифрования/расшифрования вызывают исключение, так как разобранный hex-ключ не равен 32 байтам. |
| JWT для production не задан или используется sentinel-значение | API логирует критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется для каждого пути исключения. |
| Электронная почта недоступна | Почтовые функции перехватывают/логируют сбои; основной поток аутентификации/документов все равно может вернуть успех. |
| Конвертер без LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и слушает только на loopback. |
| Публичный прокси CMP | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализации таймаута или строгого белого списка назначений (allow-list). Перед публичным доступом необходим специализированный анализ безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реальной среды, включающий все реализованные секреты и ключи обеспечения непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный OpenAPI контракт из файлов маршрутов Express перед объявлением публичного API стабильным.
3. Задокументировать локальный `uploads/` v1 и постоянное хранение R2 v2 как отдельные, сосуществующие в настоящее время рабочие процессы.
4. Не описывать резервный вариант со случайными криптоключами как безопасный для production.
