# Опорные данные: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит репозитория по состоянию на 2026-09-28.
**Область:** маршруты фронтенда на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается фактически реализованное поведение, а не соответствие стандартам или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервное значение `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL-адресами выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подпись в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

Файл `server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production-режиме.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны аутентификации |
| `/dashboard` | Да | В настоящее время использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и рабочий процесс просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации (navigation guard) получает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Точка входа сохранения опционально принимает bearer-токен; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Реестр типов документов для глобального пространства / workspace |

В репозитории отсутствует закоммиченный документ OpenAPI. Роутер и эти исходные файлы представляют собой актуальный HTTP-контракт.

## Поведение данных и объектного хранилища (object-storage)

Существуют два независимых пути персистентности документов:

1. Устаревший эндпоинт `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала читает этот путь в файловой системе; создание архива выполняется потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает пятиминутный presigned URL для загрузки и выгружает подписи / файлы PAdES в R2 после того, как Multer получает их локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запросы на запись в R2 используют серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует проверку JWT и статический вывод | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный запасной вариант указан выше | `server/db.ts` | Критично для функционала всей персистентности |
| `JWT_SECRET` | секрет; в production должен отличаться от маркера | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 шестнадцатеричных символов; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для функционала доставки почты/ссылок |
| `SOFFICE_PATH` | имя/путь к исполняемому файлу; `soffice` | `server/converter.mjs` | Критично для функционала только службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения локально для сервиса | кодовые пути воркера/очереди | Критично для функционала только там, где запущен воркер очереди |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается лишь часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный запасной вариант. |
| Неверная длина ключа шифрования | Операции шифрования/расшифрования вызывают исключение, так как разобранный hex-ключ имеет длину не 32 байта. |
| Производственный JWT не задан или используется значение-маркер (sentinel) | API записывает критическую ошибку в лог и завершает работу перед началом прослушивания портов. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; для временных файлов Multer не гарантируется очистка на каждом пути возникновения исключений. |
| Электронная почта недоступна | Почтовые функции перехватывают/логируют ошибки; основной процесс аутентификации/документооборота все еще может возвращать успех. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и прослушивает запросы только на loopback. |
| Публичный прокси CMP | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализации таймаута или строгого списков разрешенных адресов назначения (allow-list). Перед публичным доступом необходим специализированный аудит безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реальной среды, включающий все реализованные секреты и ключи обеспечения непрерывности состояния, содержащий только плейсхолдеры.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express перед объявлением публичного API стабильным.
3. Задокументировать локальный `uploads/` в v1 и персистентность в R2 в v2 как раздельные, сосуществующие в данный момент рабочие процессы.
4. Не описывать резервный вариант с генерацией случайных криптографических ключей как безопасный для продакшена.
