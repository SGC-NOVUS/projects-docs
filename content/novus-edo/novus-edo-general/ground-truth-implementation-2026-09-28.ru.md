# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит чекаута от 2026-09-28.
**Область охвата:** маршруты фронтенда на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие стандартам или юридическую сертификацию.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite и API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Браузерный UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервное значение для `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL для загрузки и скачивания |
| Почта | Resend плюс рендеринг через Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подписание в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий/sentinel `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и рабочий процесс просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Navigation guard получает данные текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода к защищенным маршрутам на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer token | Вход по email/паролю и KEP/TIN, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email, установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организации и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший (legacy) рабочий процесс с локальной загрузкой документов |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; операции чтения публичны | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочего пространства |

У API нет зафиксированного в репозитории документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает этот путь в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он генерирует пятиминутный presigned URL для загрузки и отправляет файлы подписей/PAdES в R2 после того, как Multer принимает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Для анонимных сохраняемых пакетов создается или повторно используется фиксированная системная учетная запись. Запросы на запись в R2 требуют серверного шифрования `AES256`.

## Реестр переменных окружения

| Переменная | Тип / значение по умолчанию | Где используется | Критичность для запуска / функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительное использование JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный резервный вариант приведен выше | `server/db.ts` | Критично для функционала всех механизмов персистентности |
| `JWT_SECRET` | secret; в production должно отличаться от значения по умолчанию (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 hex-символов; случайное значение процесса в качестве резервного варианта | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайное значение процесса в качестве резервного варианта | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала объектов v2/public |
| `RESEND_API_KEY`, `APP_URL` | секрет и URL почтового сервиса; по умолчанию `APP_URL` равен `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для функционала доставки почты и ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функционала только сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локального окружения сервиса | пути в коде воркеров/очередей | Критично для функционала только там, где запущен воркер очереди |

Зафиксированные в репозитории файлы `.env.example` или `.env.sample` не найдены. В файле README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоя и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствующий или измененный `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации продуктивной среды, а не как безопасный резервный сценарий. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифровки вызывают исключение, так как обработанный hex-ключ содержит не 32 байта. |
| JWT для продуктивной среды не задан или содержит значение-заглушку (sentinel) | API логирует критическую ошибку и завершает работу до начала прослушивания соединений. |
| R2 недоступен | Вызовы сохранения v2/public завершаются с ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется при каждом сценарии возникновения исключения. |
| Служба электронной почты недоступна | Почтовые функции перехватывают и логируют сбои; основной поток аутентификации/документооборота все еще может возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | Эндпоинт `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без командной оболочки и прослушивает только локальный интерфейс (loopback). |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка назначений. Требуется отдельный аудит безопасности перед открытием публичного доступа. |

## Требуемые исправления документации

1. Добавить реальный шаблон окружения, содержащий все реализованные секреты и ключи обеспечения непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express перед объявлением публичного API стабильным.
3. Задокументировать локальный `uploads/` в v1 и персистентность в R2 в v2 как отдельные, сосуществующие в данный момент рабочие процессы.
4. Не описывать использование резервного случайного криптоключа как безопасное для production.
