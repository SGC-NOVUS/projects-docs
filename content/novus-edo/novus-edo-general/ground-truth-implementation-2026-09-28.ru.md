# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит checkout по состоянию на 2026-09-28.
**Область:** маршруты frontend на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение окружения. Этот документ описывает реализованное поведение, а не соответствие стандартам или юридическую сертификацию.

## Исполняемая структура

Приложение представляет собой клиент браузера на Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Интерфейс браузера | Vue 3, Vue Router, Pinia и службы клиентской подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL загрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подпись в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время использует повторно `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и рабочий процесс просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) получает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на страницу `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer token; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр типов документов / реестр типов документов рабочего пространства |

Для API отсутствует закоммиченный документ OpenAPI 3.1. Текущим HTTP-контрактом являются роутер и эти исходные файлы.

## Поведение данных и объектного хранилища (object-storage)

Существуют два независимых пути персистентности документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает этот путь файловой системы; создание архива выполняется потоково из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает пятиминутный presigned URL для загрузки и выгружает файлы подписей / PAdES в R2 после того, как Multer принимает их локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запросы на запись в R2 используют серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип / по умолчанию | Где используется | Критичность при запуске / для функций |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует проверку JWT и статический вывод | `server/index.ts` | Граница запуска |
| `PORT` | целое число / строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный запасной вариант указан выше | `server/db.ts` | Критично для функций постоянного хранения |
| `JWT_SECRET` | секрет; в production должен отличаться от эталонного | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 шестнадцатеричных символов; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | строка источника; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функций v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для функций доставки почты / ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функций только службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения на уровне локальной службы | кодовые пути воркера/очереди | Критично для функций только там, где запускается воркер очереди |

Не найдено закоммиченных файлов `.env.example` или `.env.sample`. В README упоминается лишь часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствует/изменен `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по blind-index нарушается после перезапуска. Это должно рассматриваться как критический сбой конфигурации production, а не как безопасный резервный вариант (fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/дешифрования вызывают исключение (throws), так как распарсенный hex-ключ не равен 32 байтам. |
| JWT для production не задан или имеет значение-заглушку (sentinel) | API логирует критическую ошибку и завершает работу до начала прослушивания портов. |
| Недоступность R2 | Вызовы сохранения v2/public завершаются ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется при каждом сценарии возникновения исключений. |
| Недоступность Email | Почтовые функции перехватывают/логируют ошибки; основной процесс аутентификации/документооборота все еще может возвращать успешный статус. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 MiB, запускает LibreOffice без использования оболочки (shell) и принимает соединения только на loopback-интерфейсе. |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка (allow-list) назначений. Требуется проведение отдельного аудита безопасности перед открытием публичного доступа. |

## Требуемые исправления документации

1. Добавить реальный шаблон переменных окружения, включающий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный контракт OpenAPI на основе файлов маршрутов Express, прежде чем заявлять о стабильном публичном API.
3. Задокументировать локальное хранилище v1 `uploads/` и персистентность v2 R2 как отдельные, сосуществующие в настоящее время рабочие процессы.
4. Не описывать резервный механизм со случайными криптографическими ключами (fallback) как безопасный для production.
