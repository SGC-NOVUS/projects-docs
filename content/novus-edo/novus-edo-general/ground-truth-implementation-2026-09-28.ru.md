# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 2026-09-28.
**Область:** маршруты frontend на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite плюс API на Express, запущенный через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и службы клиентской подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL для выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерная подпись | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны аутентификации |
| `/dashboard` | Да | В настоящее время использует `Inbox.vue` повторно |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и рабочий процесс работы с детальной информацией |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на страницу `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/изменение пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Точка входа сохранения опционально принимает bearer-токен; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр / реестр типов документов рабочего пространства |

API не имеет зафиксированного в репозитории документа OpenAPI. Роутер и эти исходные файлы представляют собой актуальный HTTP-контракт.

## Поведение данных и объектного хранилища (Data and object-storage behavior)

Существует два независимых пути персистентности документов:

1. Устаревший путь `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала читает этот путь в файловой системе; создание архива выполняется потоком из этого локального состояния.
2. Путь `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает пятиминутный presigned URL для загрузки и выгружает подписи / файлы PAdES в R2 после того, как Multer получает их локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запись в R2 запрашивает серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность при запуске / для функций |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует проверку JWT и статический вывод | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный резервный вариант указан выше | `server/db.ts` | Критично для функций постоянного хранения |
| `JWT_SECRET` | secret; в production должно отличаться от контрольного значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-hex-char secret; случайный резервный вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайный резервный вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 эндпоинт/учетные данные; срок действия `900` секунд | `server/storageService.ts` | Критично для функций v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для доставки почты / ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функций только службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локального окружения службы | пути кода воркера/очереди | Критично для функций только там, где запускается воркер очереди |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается лишь часть этого списка, а переменные `ENCRYPTION_Key`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis опущены.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ / секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный резервный вариант. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифрования вызывают ошибку, так как разобранный шестнадцатеричный ключ не равен 32 байтам. |
| Производственный JWT не задан или используется значение по умолчанию | API записывает в лог критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется по каждому пути возникновения исключения. |
| Сервис электронной почты недоступен | Почтовые функции перехватывают и логируют ошибки; основной сценарий аутентификации или работы с документами все равно может вернуть успешный результат. |
| У конвертера отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки и принимает соединения только на loopback-интерфейсе. |
| Публичный CMP прокси | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализации тайм-аута или строгого белого списка адресов назначения. Перед публичным размещением требуется проведение специализированной проверки безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реального окружения, включающий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный OpenAPI contract из файлов маршрутов Express перед объявлением публичного API стабильным.
3. Задокументировать локальный v1 `uploads/` и персистентность v2 R2 как раздельные, существующие одновременно рабочие процессы.
4. Не описывать фоллбэк на случайные crypto-key как безопасный для production.
