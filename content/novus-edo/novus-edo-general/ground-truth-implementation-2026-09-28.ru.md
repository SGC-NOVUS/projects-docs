# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 2026-09-28.
**Область:** маршруты Vue frontend, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Браузерный UI | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL (presigned URLs) для загрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерное подписание | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписей и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или зарезервированный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны учетных записей |
| `/dashboard` | Да | В настоящее время использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Рабочий процесс списка, создания и просмотра деталей документов |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на страницу `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная конечная точка сохранения опционально принимает bearer token; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр / реестр типов документов рабочего пространства |

API не содержит закоммиченного документа OpenAPI. Текущим HTTP-контрактом являются роутер и эти исходные файлы.

## Поведение данных и объектного хранилища

Существуют два независимых пути персистентности документов:

1. Устаревший `/api/documents` использует Multer (`uploads/`) и сохраняет локальные пути в базе данных. Скачивание оригинала считывает путь из этой файловой системы; создание архива выполняется потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает предварительно подписанный URL для загрузки (presigned upload URL) сроком на пять минут и загружает файлы подписей / PAdES в R2 после их получения Multer локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запись в R2 выполняет серверное шифрование `AES256` запроса.

## Реестр переменных окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функциональности |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительное применение JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный fallback показан выше | `server/db.ts` | Критично для функциональности всей персистентности |
| `JWT_SECRET` | secret; в production должен отличаться от sentinel-значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 hex-символов; fallback на случайное значение процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; fallback на случайное значение процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функциональности v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функциональности только сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локальных для сервиса переменных окружения | пути кода воркеров/очередей | Критично для функциональности только там, где запущен воркер очередей |

Зафиксированные в репозитории файлы `.env.example` или `.env.sample` не найдены. В README упомянута лишь часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Сценарии сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствует/изменен `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля невозможно расшифровать, а непрерывность поиска по blind index нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации продакшена, а не как безопасный fallback. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифрования вызывают исключение, так как распарсенный hex-ключ не равен 32 байтам. |
| Продакшен-JWT не задан или содержит sentinel-значение | API логирует критическую ошибку и завершает процесс до начала прослушивания соединений. |
| R2 недоступен | Вызовы сохранения v2/public завершаются со сбоем и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется на всех путях обработки исключений. |
| Почтовый сервис недоступен | Функции отправки почты перехватывают/логируют сбои; основной поток аутентификации/документооборота может по-прежнему возвращать успешный ответ. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и слушает только loopback-интерфейс. |
| Публичный прокси CMP | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого allow-list адресов назначения. Требуется отдельный аудит безопасности перед открытием публичного доступа. |

## Требуемые исправления документации

1. Добавьте шаблон реального окружения, включающий все реализованные секреты и ключи непрерывности состояния, содержащий только заполнители.
2. Опубликуйте сгенерированный контракт OpenAPI из файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументируйте локальное хранение v1 в `uploads/` и персистентность v2 в R2 как отдельные, в настоящее время сосуществующие процессы.
4. Не описывайте резервное использование случайного криптографического ключа как безопасное для промышленной эксплуатации.
