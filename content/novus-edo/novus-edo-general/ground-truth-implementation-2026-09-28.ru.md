# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 2026-09-28.
**Область:** маршруты Vue frontend, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая форма

Приложение представляет собой браузерный клиент Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL-адресами выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерная подпись | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или зарезервированный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Рабочий процесс списка, создания и просмотра деталей документов |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неавторизованные защищенные переходы на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии здоровья процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная конечная точка сохранения опционально принимает bearer token; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр / реестр типов документов рабочего пространства |

API не имеет зафиксированного документа OpenAPI. Маршрутизатор и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существует два независимых пути персистентности документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Первоначальное скачивание читает этот путь в файловой системе; создание архива выполняет стриминг из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает пятиминутный presigned URL для загрузки и загружает подписи / файлы PAdES в R2 после того, как Multer получает их локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запись в R2 выполняет серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность при запуске / для функций |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительную проверку JWT и стат. раздачу | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный фоллбек указан выше | `server/db.ts` | Критично для функций любого сохранения |
| `JWT_SECRET` | secret; в production должен отличаться от заглушки | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-hex-char secret; фоллбек на случайный процесс | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; фоллбек на случайный процесс | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 эндпоинт / учетные данные; срок действия `900` секунд | `server/storageService.ts` | Критично для функций v2 / публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | почтовый секрет и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функций отправки писем / ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функций только службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения локально для сервиса | кодовые пути воркеров/очередей | Критично для функций только там, где запускается воркер очереди |

Файлы `.env.example` или `.env.sample` в системе контроля версий не найдены. В README упоминается лишь часть этого списка, при этом опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` либо `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепым индексам (blind-index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный резервный вариант (fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифрования вызывают ошибку, так как разобранный hex-ключ имеет длину менее 32 байт. |
| Production JWT не задан или используется sentinel-значение | API записывает в лог критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется для каждого пути исключений. |
| Сервис электронной почты недоступен | Функции отправки почты перехватывают/логируют ошибки; основной сценарий аутентификации или работы с документами всё равно может возвращать успешный результат. |
| Конвертер не обнаружил LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и принимает соединения только на loopback-интерфейсе. |
| Публичный CMP прокси | Прокси принимает целевой адрес, переданный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализации тайм-аута или строгого белого списка (allow-list) получателей. Перед публичным размещением требуется проведение специализированной проверки безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реальной среды, включающий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express перед объявлением стабильного публичного API.
3. Задокументировать локальную v1 `uploads/` и персистентность v2 R2 как отдельные, сосуществующие в данный момент рабочие процессы.
4. Не описывать резервный вариант со случайными криптографическими ключами как безопасный для production.
