# Фактическое состояние: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит среза кода от 2026-09-28.
**Область аудита:** маршруты Vue-фронтенда, структура Express-сервера, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В данном документе описано фактическое поведение системы, а не юридический сертификат или сертификат соответствия.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite и Express API, запускаемый через `tsx server/index.ts`.

| Компонент | Фактическая реализация |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервное значение `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL для загрузки и скачивания |
| Почта | Resend плюс рендеринг через Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подпись в браузере | Закрытые ключи документов остаются на стороне браузера согласно реализованной архитектуре клиента; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или совпадающий с заглушкой `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в продакшене.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление/значение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные, юридические экраны и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, процесс создания и детализации |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) получает данные текущего пользователя при наличии токена и перенаправляет неаутентифицированные переходы по защищенным маршрутам на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по Email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организации и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс загрузки и обработки локальных документов |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение является публичным | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Реестр типов документов глобального уровня / рабочей области |

У API нет закоммиченного документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существует два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает этот путь из файловой системы; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует объектные ключи R2. Он выдает предварительно подписанный URL для загрузки со сроком действия пять минут и загружает файлы подписей/PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; отправка с аутентификацией использует `individuals/<user ID>/documents/<verification ID>/...`. Она создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип/по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует обязательную проверку JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | целое число/строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для работы всех механизмов персистентности |
| `JWT_SECRET` | секрет; в production должен отличаться от маркерного значения (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-символьный hex-секрет; случайное значение процесса в качестве резервного | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайное значение процесса в качестве резервного | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для работы с публичными объектами и объектами v2 |
| `RESEND_API_KEY`, `APP_URL` | секрет почтового сервиса и URL; по умолчанию `APP_URL` равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для доставки писем и ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение переменных окружения внутри сервиса | пути в коде воркеров/очередей | Критично только там, где запускается воркер очереди |

Закоммиченные файлы `.env.example` или `.env.sample` не найдены. В README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоя и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствует или изменен `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу (blind-index) нарушается после перезапуска. Это необходимо рассматривать как сбой конфигурации в продакшене, а не как безопасный резервный механизм (safe fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифровки (encrypt/decrypt) вызывают исключение, поскольку распознанный hex-ключ не равен 32 байтам. |
| JWT для продакшена не задан или имеет значение-заглушку (sentinel) | API записывает критическую ошибку в лог и завершает работу до начала прослушивания. |
| R2 недоступен | Вызовы сохранения в `v2/public` завершаются с ошибкой и возвращают серверные ошибки; очистка временных файлов Multer гарантируется не для всех путей обработки исключений. |
| Почтовый сервис недоступен | Функции отправки почты перехватывают/логируют сбои; основной поток аутентификации/документооборота может по-прежнему возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без использования оболочки (shell) и прослушивает только loopback-интерфейс. |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий запрос POST без реализованного таймаута или строгого списка разрешенных назначений (allow-list). Перед публичным открытием требуется отдельный аудит безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реального окружения, включающий все реализованные секреты и ключи непрерывности состояния, содержащий только плейсхолдеры.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументировать локальное хранение v1 `uploads/` и персистентность v2 R2 как отдельные, в настоящее время сосуществующие процессы.
4. Не описывать фоллбэк на случайный криптоключ как безопасный для production.
