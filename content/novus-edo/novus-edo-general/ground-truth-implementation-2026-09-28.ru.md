# Фактическое состояние: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит среза кода от 2026-09-28.
**Область охвата:** маршруты Vue-фронтенда, композиция Express-сервера, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие требованиям или юридическую сертификацию.

## Структура исполняемого приложения

Приложение представляет собой браузерный клиент на Vue/Vite и Express API, запускаемый через `tsx server/index.ts`.

| Компонент | Фактическая реализация |
| --- | --- |
| Браузерный UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Хранение данных | Prisma 7 с адаптером MariaDB; значение по умолчанию для `DATABASE_URL`: `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL для загрузки и скачивания |
| Почта | Resend плюс рендеринг через Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подпись в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или тестовый `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в продакшене.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные страницы, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, процесс создания и детального просмотра |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации получает текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода на защищенные маршруты на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по Email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс документооборота с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение является публичным | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочего пространства |

У API нет сохраненного документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существует два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает этот путь в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует объектные ключи R2. Он выдает пятиминутный предподписанный URL для загрузки и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Она создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функций |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует проверку JWT и статик-сервер | `server/index.ts` | Граница запуска |
| `PORT` | целое число/строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный запасной вариант указан выше | `server/db.ts` | Критично для функций персистентности |
| `JWT_SECRET` | секрет; в production должен отличаться от сторожевого значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 шестнадцатеричных символов; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | endpoint/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функций v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | почтовый секрет и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | локальные для службы чтения из окружения | пути кода воркеров/очередей | Критично только там, где запускается воркер очереди |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается лишь часть этого списка, а `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis опущены.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` либо `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепым индексам (blind-index) нарушается после перезапуска. Это должно рассматриваться как ошибка конфигурации в production, а не как безопасный резервный вариант (fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифрования вызывают исключение, так как разобранный hex-ключ имеет длину не 32 байта. |
| Production JWT не задан или используется sentinel-значение | API логирует критическую ошибку и завершает работу до начала прослушивания порта. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется для каждого пути обработки исключений. |
| Электронная почта недоступна | Почтовые функции перехватывают и логируют ошибки; основной сценарий авторизации или работы с документами все равно может вернуть успех. |
| Конвертер не нашел LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и слушает только на loopback-интерфейсе. |
| Публичный прокси CMP | Прокси принимает целевой адрес, переданный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализации тайм-аута или строгого белого списка (allow-list) назначений. Перед публичным размещением требуется проведение специализированного аудит безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реальной среды, включающий все реализованные секреты и ключи обеспечения непрерывности состояния, содержащий только заполнители.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express до заявления о стабильном публичном API.
3. Задокументировать локальные `uploads/` v1 и персистентность R2 v2 как отдельные, сосуществующие в данный момент рабочие процессы.
4. Не описывать резервный вариант со случайными криптографическими ключами как безопасный для промышленной эксплуатации.
