# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит репозитория от 2026-09-28.
**Область охвата:** маршруты клиентской части Vue, структура сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие требованиям или юридическую сертификацию.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite и API на Express, запускаемый через `tsx server/index.ts`.

| Компонент | Фактическая реализация |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia и сервисы подписи на стороне клиента |
| API | Express 5 на порту `PORT`, по умолчанию `3001` |
| Хранение данных | Prisma 7 с адаптером MariaDB; запасной вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL для загрузки и скачивания |
| Почта | Resend плюс рендеринг через Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подпись в браузере | Закрытые ключи документов остаются на стороне браузера согласно реализованной архитектуре клиента; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или совпадающий с шаблоном `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с использованием `CORS_ORIGIN` или `*`, подключает маршруты и раздает `dist/` в продакшене.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, процесс создания и просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Navigation guard получает текущего пользователя при наличии токена и перенаправляет неаутентифицированные переходы по защищенным маршрутам на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс работы с локальной загрузкой документов |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; операции чтения публичны | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочего пространства |

У API нет зафиксированного в репозитории документа OpenAPI. Текущим HTTP-контрактом являются роутер и эти исходные файлы.

## Поведение данных и объектного хранилища

Существуют два независимых пути персистентного хранения документов:

1. Устаревший путь `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала читает этот путь в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует объектные ключи R2. Он выдает предварительно подписанный URL для загрузки с пятиминутным сроком действия и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Она создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип / значение по умолчанию | Где используется | Критичность при запуске / для функциональности |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительное применение JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный fallback показан выше | `server/db.ts` | Критично для функциональности персистентности всех данных |
| `JWT_SECRET` | secret; в production должен отличаться от значения-сентинела | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-символьный hex-секрет; случайный fallback для процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайный fallback для процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функциональности v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секретный ключ почты и URL; `APP_URL` по умолчанию равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функциональности доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь к исполняемому файлу; `soffice` | `server/converter.mjs` | Критично для функциональности только сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение переменных окружения на уровне сервиса | пути кода worker/queue | Критично для функциональности только там, где запущен воркер очередей |

Не найдено закоммиченных файлов `.env.example` или `.env.sample`. В README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH`, а также настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствует или изменён `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу (blind-index) нарушается после перезапуска. Это следует рассматривать как сбой конфигурации в продакшене, а не как безопасный аварийный режим (fallback). |
| Некорректная длина ключа шифрования | Операции шифрования/расшифровки вызывают ошибку (throw), так как распарсенный hex-ключ не равен 32 байтам. |
| Не задан или имеет значение-заглушку (sentinel) JWT для продакшена | API логирует критическую ошибку и завершает работу до начала прослушивания порта. |
| Недоступность R2 | Вызовы сохранения v2/public завершаются ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется при каждом ветвлении исключений. |
| Недоступность Email | Почтовые функции перехватывают/логируют ошибки; основной поток аутентификации/документооборота всё ещё может возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | Эндпоинт `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без командной оболочки (shell) и прослушивает только loopback. |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого разрешительного списка (allow-list) назначения. Перед публичным открытием требуется отдельный аудит безопасности. |

## Требуемые исправления в документации

1. Добавьте реальный шаблон окружения, содержащий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликуйте сгенерированный контракт OpenAPI из файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументируйте локальное хранение v1 `uploads/` и персистентность v2 R2 как отдельные, в настоящее время сосуществующие процессы.
4. Не описывайте фолбэк на случайный криптоключ как безопасный для production.
