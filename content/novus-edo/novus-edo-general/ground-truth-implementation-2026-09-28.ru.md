# Ground truth: реализация NOVUS Flow.EDO

**Статус:** внутренний статический аудит чекаута на 2026-09-28.
**Область охвата:** маршруты фронтенда на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Данный документ описывает реализованное поведение, а не сертификацию на соответствие стандартам или правовым нормам.

## Структура исполняемой системы

Приложение представляет собой браузерный клиент на базе Vue/Vite и API на Express, запускаемый с помощью `tsx server/index.ts`.

| Компонент | Фактическая реализация |
| --- | --- |
| Браузерный UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; fallback-значением для `DATABASE_URL` является `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с presigned-URL для загрузки и скачивания |
| Почта | Resend плюс рендеринг через Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подписание в браузере | Закрытые ключи документов остаются на стороне браузера согласно реализованной клиентской архитектуре; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или шаблонный (sentinel) `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и процесс детального просмотра |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Navigation guard запрашивает данные текущего пользователя при наличии токена и перенаправляет неаутентифицированные переходы по защищенным маршрутам на `/login` (`src/router/index.ts`).

## Каталог API Express

Все приведенные ниже пути имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по email/паролю и KEP/TIN, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организации и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший workflow документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Workflow DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; операции чтения публичны | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочего пространства |

У API нет зафиксированного в репозитории документа OpenAPI. Роутер и данные исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает этот путь в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он генерирует пятиминутный presigned URL для загрузки и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Для анонимных сохраняемых пакетов создается или повторно используется фиксированная системная учетная запись. Операции записи в R2 запрашивают серверное шифрование `AES256`.

## Реестр переменных окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует принудительное применение JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | целое число/строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для функционала всех механизмов персистентности |
| `JWT_SECRET` | секрет; в production должен отличаться от сторожевого значения (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-значный шестнадцатеричный секрет; случайный резервный вариант на уровне процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный резервный вариант на уровне процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | конечная точка/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | почтовый секрет и URL; по умолчанию `APP_URL` равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функционала доставки почты/ссылок |
| `SOFFICE_PATH` | имя/путь к исполняемому файлу; `soffice` | `server/converter.mjs` | Критично только для функционала сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локального окружения сервиса | пути кода воркера/очереди | Критично только для функционала там, где запущен воркер очереди |

В репозитории не найдено закоммиченных файлов `.env.example` или `.env.sample`. В файле README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Failure modes and implementation limits

| Situation | Observed behavior |
| --- | --- |
| Missing/changed `ENCRYPTION_KEY` or `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не удастся расшифровать, а непрерывность поиска по слепому индексу изменится после перезапуска. Это следует рассматривать как сбой конфигурации рабочей среды (production), а не как безопасный резервный механизм (fallback). |
| Invalid encryption key length | Операции шифрования/расшифровки генерируют исключение, так как разобранный hex-ключ имеет длину не 32 байта. |
| Production JWT unset/sentinel | API логирует критическую ошибку и завершает работу до начала прослушивания соединений. |
| R2 unavailable | Вызовы сохранения v2/public завершаются со сбоем и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется при каждом сценарии возникновения исключения. |
| Email unavailable | Почтовые функции перехватывают/логируют ошибки; основной сценарий аутентификации/документооборота всё ещё может завершаться успешно. |
| Converter missing LibreOffice | Эндпоинт `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Converter input | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и прослушивает только loopback-интерфейс. |
| Public CMP proxy | Прокси принимает целевой адрес, переданный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка назначений (allow-list). Перед публичным открытием требуется отдельный аудит безопасности. |

## Необходимые исправления документации

1. Добавьте шаблон реального окружения, содержащий все реализованные секреты и ключи непрерывности состояния, исключительно с плейсхолдерами.
2. Опубликуйте сгенерированный контракт OpenAPI из файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументируйте локальное хранение v1 в `uploads/` и персистентность v2 в R2 как отдельные, в настоящее время сосуществующие рабочие процессы.
4. Не описывайте резервное использование случайного криптоключа как безопасное для production.
