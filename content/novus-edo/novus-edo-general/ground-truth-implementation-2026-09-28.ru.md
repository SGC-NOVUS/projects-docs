# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 28.09.2026.
**Область:** маршруты Vue frontend, композиция Express сервера, персистентность Prisma/R2, криптография, конвертер и чтение окружения. Этот документ описывает реализованное поведение, а не соответствие требованиям или юридическую сертификацию.

## Исполняемая структура

Приложение представляет собой браузерный клиент Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL-адресами загрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимая HTTP-служба на `127.0.0.1:4174`, порождающая процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерное подписание | Заключенные в документе приватные ключи остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или заменяющий его `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и раздает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, экраны с правовой информацией и аутентификацией |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Рабочий процесс списка, создания и детального просмотра документов |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует Bearer-токен | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/изменение пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная точка входа опционально принимает bearer token; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Реестр типов документов (глобальный/для воркспейса) |

В репозитории отсутствует зафиксированный документ OpenAPI. Текущим HTTP-контрактом являются маршрутизатор и следующие исходные файлы.

## Поведение данных и объектного хранилища

Существует два независимых пути персистентности документов:

1. Устаревший `/api/documents` использует Multer (`uploads/`) и сохраняет локальные пути в базе данных. Первоначальное скачивание читает этот путь из файловой системы; создание архива происходит путем стриминга из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он генерирует пятиминутный presigned URL для загрузки и выгружает подписи / файлы PAdES в R2 после их локального получения через Multer.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. При записи в R2 запрашивается серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функций |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует принудительную проверку JWT и статические раздачи | `server/index.ts` | Граница запуска |
| `PORT` | целое число/строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный запасной вариант указан выше | `server/db.ts` | Критично для функций постоянного хранения |
| `JWT_SECRET` | секрет; в production должен отличаться от сторожевого значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 шестнадцатеричных символов; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка источника; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функций v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для доставки почты/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функций только службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения на уровне локальной службы | пути кода воркеров/очередей | Критично для функций только там, где запускается воркер очереди |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается лишь часть этого списка, а `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis опущены.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие/изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ / секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепым индексам (blind-index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный фоллбэк. |
| Неверная длина ключа шифрования | Операции шифрования/расшифрования вызывают ошибку, так как разобранный hex-ключ имеет длину менее 32 байт. |
| Production JWT не задан или используется sentinel-значение | API записывает в лог критическую ошибку и завершает работу до начала прослушивания порта. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; для временных файлов Multer не гарантируется очистка при любом пути исключения. |
| Электронная почта недоступна | Почтовые функции перехватывают и логируют ошибки; основной процесс аутентификации/документооборота все еще может завершиться успешно. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и принимает запросы только на loopback-интерфейсе. |
| Публичный CMP proxy | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализации таймаута или строгого белого списка назначений. Требуется отдельный аудит безопасности перед публичным доступом. |

## Требуемые исправления в документации

1. Добавьте реальный шаблон окружения, включающий все реализованные секреты и ключи непрерывности состояния, содержащий только плейсхолдеры.
2. Опубликуйте сгенерированный контракт OpenAPI из файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументируйте локальное хранение v1 в `uploads/` и персистентность v2 в R2 как отдельные, в настоящее время сосуществующие рабочие процессы.
4. Не описывайте фоллбэк на случайные криптоключи как безопасный для промышленной эксплуатации.
