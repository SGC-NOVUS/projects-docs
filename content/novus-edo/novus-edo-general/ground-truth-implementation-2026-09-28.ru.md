# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 28.09.2026.
**Область применения:** маршруты frontend на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение окружения. Этот документ описывает реализованное поведение, а не соответствие требованиям или юридическую сертификацию.

## Исполняемая форма

Приложение представляет собой браузерный клиент Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; запасной вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL-адресами выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерное подписание | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписей и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Браузерные маршруты

| Маршрут | Требование к аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные страницы, юридическая информация и экраны авторизации/идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, процесс создания и просмотр деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Navigation guard запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода на защищенные маршруты на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по Email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/Email, установка и смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс работы с документами с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение является публичным | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный/рабочий реестр типов документов |

У API нет закоммиченного документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает этот путь из файловой системы; создание архива выполняется потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует объектные ключи R2. Он выдаёт пятиминутный presigned URL для загрузки и отправляет подписи/файлы PAdES в R2 после того, как Multer принимает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Она создаёт или повторно использует фиксированную системную учётную запись для анонимных сохранённых пакетов. Операции записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип / значение по умолчанию | Где используется | Критичность для запуска / функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительную проверку JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для всего функционала сохранения данных |
| `JWT_SECRET` | secret; в production должен отличаться от сигнального значения (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-hex-char secret; резервный вариант — случайная генерация в процессе | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; резервный вариант — случайная генерация в процессе | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секретный ключ почты и URL; по умолчанию `APP_URL` равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функционала доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для функционала сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локального окружения сервиса | пути кода воркеров/очередей | Критично для функционала только там, где запущен воркер очередей |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается только часть этого списка и отсутствуют `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствующий или измененный `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу меняется после перезапуска. Это должно рассматриваться как сбой конфигурации production, а не как безопасный резервный механизм (fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифрования выбрасывают исключение, поскольку обработанный hex-ключ не равен 32 байтам. |
| Не задан или содержит значение-заглушку (sentinel) JWT для production | API логирует критическую ошибку и завершает работу до начала прослушивания порта. |
| Недоступность R2 | Вызовы сохранения v2/public завершаются с ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется при каждом сценарии исключения. |
| Недоступность Email | Почтовые функции перехватывают/логируют сбои; основной поток аутентификации/документооборота всё ещё может возвращать успешный результат. |
| Отсутствие LibreOffice у конвертера | `/api/convert` возвращает `422`; очистка временного каталога выполняется в `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и прослушивает только loopback. |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий запрос POST без реализованного таймаута или строгого списка разрешенных назначений (allow-list). Перед публичным доступом ему требуется отдельный аудит безопасности. |

## Требуемые исправления документации

1. Добавьте реальный шаблон окружения, включающий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликуйте сгенерированный контракт OpenAPI из файлов маршрутов Express перед тем, как заявлять о наличии стабильного публичного API.
3. Задокументируйте локальное хранение v1 в `uploads/` и персистентность v2 в R2 как отдельные, в настоящее время сосуществующие рабочие процессы.
4. Не описывайте фоллбэк на случайные криптоключи как безопасное решение для production.
