# Ground truth: реализация NOVUS Flow.EDO

**Статус:** внутренний статический аудит среза кода от 28.09.2026.
**Область аудита:** маршруты Vue-фронтенда, композиция Express-сервера, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие стандартам или юридическую сертификацию.

## Исполняемая архитектура

Приложение представляет собой браузерный клиент на Vue/Vite и Express API, запускаемый через `tsx server/index.ts`.

| Компонент | Фактическая реализация |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервное значение `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL для загрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подписание в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной архитектурой клиента; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или стандартный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в продакшене.

## Маршруты браузера

| Маршрут | Требование к аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные, юридические экраны и экраны аутентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и процесс работы с деталями |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный гард запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода на защищенные маршруты на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс работы с локально загружаемыми документами |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс DocumentPackage с использованием хранилища R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение является публичным | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр типов документов / реестр рабочей области |

У API нет зафиксированного в репозитории документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший эндпоинт `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает файл по этому пути в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает предварительно подписанный URL для загрузки (presigned upload URL) со сроком действия пять минут и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Она создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип/по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует принудительное использование JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для функционала всех операций сохранения данных |
| `JWT_SECRET` | secret; в production должен отличаться от контрольного значения (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-символьный hex-секрет; резервный случайный вариант на уровне процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; резервный случайный вариант на уровне процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала объектов v2/public |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию равен `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для функционала доставки почты/ссылок |
| `SOFFICE_PATH` | имя/путь к исполняемому файлу; `soffice` | `server/converter.mjs` | Критично для функционала только службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локального окружения сервиса | пути кода worker/queue | Критично для функционала только там, где запущен воркер очереди |

Файлы `.env.example` или `.env.sample` не найдены в репозитории. В README упоминается лишь часть этого списка, при этом пропущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоя и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепым индексам (blind-index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный запасной вариант (fallback). |
| Неверная длина ключа шифрования | Операции шифрования/расшифрования вызывают ошибку, так как разобранный hex-ключ имеет длину менее 32 байт. |
| Production JWT не задан или используется sentinel-значение | API записывает в лог критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; для временных файлов Multer не гарантируется очистка при любом пути возникновения исключения. |
| Электронная почта недоступна | Почтовые функции перехватывают/логируют ошибки; основной сценарий аутентификации/документооборота все еще может возвращать успех. |
| Конвертер без LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и прослушивает только loopback. |
| Публичный прокси CMP | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий запрос POST без реализации таймаута или строгого белого списка (allow-list) получателей. Перед публичным размещением требуется проведение специализированной проверки безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реальной среды, включающий все реализованные секреты и ключи обеспечения непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express перед объявлением публичного API стабильным.
3. Задокументировать локальный `uploads/` в v1 и персистентность в R2 в v2 как раздельные, сосуществующие в данный момент рабочие процессы.
4. Не описывать использование случайного резервного криптоключа как безопасное для production.
