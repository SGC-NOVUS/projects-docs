# Источник истины: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления заказа от 28.09.2026.
**Область:** маршруты frontend на Vue, композиция сервера Express, персистентность Prisma/R2, шифрование, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой клиент браузера на Vue/Vite и API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL-адресами выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимая служба HTTP на `127.0.0.1:4174`, порождающая процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подписание в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

Файл `server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, устанавливает CORS с `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает `dist/` в production.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные страницы, юридические документы и экраны идентификации |
| `/dashboard` | Да | В настоящий момент использует повторно `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Рабочий процесс списка, создания и просмотра деталей документов |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неавторизованные защищенные переходы на страницу `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная конечная точка сохранения опционально принимает bearer token; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer token | Глобальный реестр / реестр типов документов рабочего пространства |

API не содержит закоммиченного документа OpenAPI. Текущим HTTP-контрактом являются маршрутизатор и эти исходные файлы.

## Поведение данных и объектного хранилища

Существуют два независимых пути персистентности документов:

1. Устаревший путь `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала читает путь из этой файловой системы; создание архива выполняется потоково из этого локального состояния.
2. Путь `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает предварительно подписанный (presigned) URL для загрузки сроком на пять минут и загружает подписи/файлы PAdES в R2 после их получения локально через Multer.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запись в R2 выполняет серверное шифрование запросов `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность при запускe / для функций |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует проверку JWT и статик-сервинг | `server/index.ts` | Граница запуска |
| `PORT` | целое число / строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный фоллбек указан выше | `server/db.ts` | Критично для функций персистентности |
| `JWT_SECRET` | секрет; в production должен отличаться от заглушки | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 hex-символов; случайный фоллбек процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный фоллбек процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 эндпоинт/учетные данные; срок действия `900` секунд | `server/storageService.ts` | Критично для функций v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | почтовый секрет и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для доставки почты / ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения на уровне локального сервиса | пути кода воркеров/очередей | Критично только там, где запускается воркер очереди |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается лишь часть этого списка, а `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis опущены.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` либо `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепым индексам нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный запасной вариант. |
| Неверная длина ключа шифрования | Операции шифрования/расшифрования вызывают исключение, так как разобранный шестнадцатеричный ключ имеет длину менее 32 байт. |
| Production JWT не задан или используется значение-заглушка | API логирует критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы сохранения v2/public завершаются ошибкой и возвращают ошибки сервера; нет гарантии очистки временных файлов Multer по каждому пути исключений. |
| Электронная почта недоступна | Почтовые функции перехватывают и логируют ошибки; основной процесс аутентификации/документооборота все еще может возвращать успех. |
| У конвертера отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без оболочки (shell) и прослушивает запросы только на loopback-интерфейсе. |
| Публичный CMP proxy | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного тайм-аута или строгого белого списка адресов назначения. Перед публичным размещением требуется проведение специализированного аудита безопасности. |

## Требуемые исправления документации

1. Добавить реальный шаблон окружения, включающий все реализованные секреты и ключи обеспечения непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express перед объявлением публичного API стабильным.
3. Задокументировать локальный `uploads/` в v1 и персистентность R2 в v2 как раздельные, сосуществующие в данный момент рабочие процессы.
4. Не описывать fallback на случайные криптографические ключи как безопасный для production.
