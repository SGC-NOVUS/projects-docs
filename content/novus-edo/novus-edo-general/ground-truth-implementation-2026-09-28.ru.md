# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит checkout от 2026-09-28.
**Область охвата:** маршруты фронтенда на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие стандартам или юридическую сертификацию.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite и Express API, запускаемый через `tsx server/index.ts`.

| Область | Фактическая реализация |
| --- | --- |
| Браузерный UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервное значение `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными (presigned) URL для загрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подписание в браузере | Закрытые ключи документов остаются на стороне браузера согласно реализованной клиентской архитектуре; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или шаблонный (sentinel) `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в production.

## Браузерные маршруты

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, рабочий процесс создания и детального просмотра |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный guard получает данные текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода на защищенные маршруты на `/login` (`src/router/index.ts`).

## Каталог Express API

Все указанные ниже пути имеют префикс `/api`, приведенный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по email/паролю и KEP/TIN, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/изменение пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организации и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; операции чтения публичны | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр / реестр рабочей области для типов документов |

У API нет зафиксированного в репозитории документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший эндпоинт `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает данные по этому пути в файловой системе; создание архива выполняется потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакетов в Prisma и использует ключи объектов R2. Он выдает пятиминутный presigned URL для загрузки и отправляет подписи/PAdES-файлы в R2 после того, как Multer принимает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Для сохраняемых анонимных пакетов создается или повторно используется фиксированная системная учетная запись. Операции записи в R2 запрашивают серверное шифрование `AES256`.

## Реестр переменных окружения

| Variable | Type/default | Where used | Startup/feature criticality |
| --- | --- | --- | --- |
| `NODE_ENV` | string; в production активирует обязательную проверку JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный fallback показан выше | `server/db.ts` | Критично для функционала: вся персистентность данных |
| `JWT_SECRET` | секрет; в production должен отличаться от sentinel-значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-значный hex-секрет; случайный fallback на уровне процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный fallback на уровне процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | почтовый секрет и URL; по умолчанию `APP_URL` равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функционала доставки писем/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для функционала сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение переменных окружения, локальных для сервиса | пути кода воркера/очереди | Критично для функционала только там, где запущен воркер очереди |

Закоммиченные файлы `.env.example` или `.env.sample` не найдены. В README упомянута лишь часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Сценарии отказов и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля невозможно расшифровать, а непрерывность поиска по слепому индексу (blind index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации окружения production, а не как безопасный резервный механизм (fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/дешифрования выбрасывают исключение, поскольку распарсенный hex-ключ имеет длину, отличную от 32 байт. |
| JWT для production не задан или содержит плейсхолдер (sentinel) | API логирует критическую ошибку и завершает процесс до начала прослушивания порта. |
| Недоступность R2 | Вызовы сохранения v2/public завершаются сбоем и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется для всех путей обработки исключений. |
| Недоступность email | Функции отправки почты перехватывают/логируют сбои; основной поток аутентификации/документооборота может по-прежнему возвращать успешный статус. |
| Отсутствие LibreOffice у конвертера | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без командной оболочки (shell) и слушает только интерфейс loopback. |
| Публичный CMP-прокси | Прокси принимает переданный клиентом целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий запрос POST без реализованного таймаута или строгого белого списка адресатов (allow-list). Требуется проведение отдельного аудита безопасности перед публикацией во внешнюю сеть. |

## Требуемые исправления документации

1. Добавить реальный шаблон окружения, включающий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликовать сгенерированный контракт OpenAPI на основе файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументировать локальное хранилище v1 `uploads/` и персистентность v2 R2 как отдельные, сосуществующие в настоящее время рабочие процессы.
4. Не описывать фолбэк на случайные криптографические ключи как безопасный для промышленной эксплуатации.
