# Фактическое состояние: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит состояния кода на 2026-09-28.
**Область анализа:** маршруты Vue-фронтенда, композиция Express-сервера, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает фактически реализованное поведение, а не соответствие стандартам или юридическую сертификацию.

## Структура исполняемых компонентов

Приложение представляет собой браузерный клиент Vue/Vite и Express API, запускаемый с помощью `tsx server/index.ts`.

| Область | Фактическая реализация |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на порту `PORT`, по умолчанию `3001` |
| Persistence | Prisma 7 с адаптером MariaDB; резервное значение `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Object storage | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL-адресами для загрузки и скачивания |
| Mail | Resend и рендеринг с помощью Vue Email |
| Converter | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Browser signing | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или дефолтный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с использованием `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в продакшене.

## Маршруты браузера

| Маршрут | Требование к авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные, юридические страницы и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, создание и рабочий процесс детализации |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный guard получает данные текущего пользователя при наличии токена и перенаправляет неавторизованные защищенные переходы на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует Bearer token | Вход по email/паролю и KEP/TIN, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организации и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс загрузки локальных документов |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; операции чтения публичны | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочей области |

У API нет сохраненного в репозитории документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существует два независимых пути сохранения документов:

1. Устаревший путь `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. При скачивании оригинала считывается этот путь в файловой системе; создание архива осуществляет потоковую передачу из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает пятиминутный предварительно подписанный URL-адрес для загрузки и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Для анонимных сохраненных пакетов создается или повторно используется фиксированная системная учетная запись. Операции записи в R2 запрашивают серверное шифрование `AES256`.

## Реестр переменных окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; значение `production` активирует обязательную проверку JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для работы всех механизмов персистентности |
| `JWT_SECRET` | secret; в `production` должен отличаться от значения по умолчанию | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-символьный hex-секрет; резервный вариант с генерацией случайного значения в процессе | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; резервный вариант с генерацией случайного значения в процессе | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для работы с объектами v2/публичными объектами |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; по умолчанию `APP_URL` равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для доставки писем и работы ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично только для работы сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | локальные для сервиса чтения окружения | пути кода воркера/очереди | Критично только в местах запуска воркера очереди |

Не найдено закоммиченных файлов `.env.example` или `.env.sample`. В README упоминается лишь часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствует/изменен `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по blind-index нарушается после перезапуска. Это должно рассматриваться как критический сбой конфигурации production, а не как безопасный резервный вариант (fallback). |
| Неверная длина ключа шифрования | Операции шифрования/расшифрования вызывают исключение, так как распарсенный hex-ключ не равен 32 байтам. |
| Не задан или имеет дефолтное значение (sentinel) JWT для production | API логирует критическую ошибку и завершает работу до начала прослушивания порта. |
| R2 недоступен | Вызовы сохранения v2/public завершаются ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется для всех путей обработки исключений. |
| Email недоступен | Функции отправки почты перехватывают/логируют ошибки; основной процесс аутентификации/документооборота все еще может возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МиБ, запускает LibreOffice без использования shell и слушает только loopback-интерфейс. |
| Публичный прокси CMP | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка (allow-list) назначений. Требуется проведение отдельного аудита безопасности перед открытием публичного доступа. |

## Требуемые исправления в документации

1. Добавьте реальный шаблон окружения, содержащий все реализованные секреты и ключи непрерывности состояния, используя только плейсхолдеры.
2. Опубликуйте сгенерированный контракт OpenAPI на основе файлов маршрутов Express, прежде чем заявлять о стабильном публичном API.
3. Задокументируйте локальное хранение v1 в `uploads/` и персистентность v2 R2 как отдельные, сосуществующие в настоящее время рабочие процессы.
4. Не описывайте резервный переход на случайный криптографический ключ как безопасный для использования в production.
