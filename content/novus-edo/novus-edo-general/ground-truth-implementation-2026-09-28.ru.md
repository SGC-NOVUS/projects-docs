# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит среза от 2026-09-28.
**Область охвата:** маршруты Vue-фронтенда, структура сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Данный документ описывает фактически реализованное поведение, а не соответствие требованиям или юридическую сертификацию.

## Исполняемая архитектура

Приложение представляет собой браузерный клиент на Vue/Vite и API на Express, запускаемый через `tsx server/index.ts`.

| Слой | Фактическая реализация |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Хранение данных | Prisma 7 с адаптером MariaDB; резервное значение `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL для загрузки и скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерная подпись | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или значение-заглушку `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в продакшене.

## Браузерные маршруты

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные, юридические экраны и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, процесс создания и детального просмотра |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный guard запрашивает данные текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода на защищенные маршруты на `/login` (`src/router/index.ts`).

## Каталог Express API

Все пути ниже имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по email/паролю и KEP/TIN, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email, установка и смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс работы с документами при локальной загрузке |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение публично | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / рабочей области |

У API нет зафиксированного в репозитории документа OpenAPI. Маршрутизатор и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает этот путь из файловой системы; создание архива передаётся потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует объектные ключи R2. Он выдаёт пятиминутный предварительно подписанный URL для загрузки (presigned upload URL) и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; отправка с аутентификацией использует `individuals/<user ID>/documents/<verification ID>/...`. Она создаёт или повторно использует фиксированную системную учётную запись для анонимных сохранённых пакетов. Записи в R2 запрашивают серверное шифрование `AES256`.

## Реестр переменных окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; `production` активирует обязательную проверку JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | целое число/строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для функционала (все хранение данных) |
| `JWT_SECRET` | секрет; в `production` должен отличаться от sentinel-значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-значный hex-секрет; резервное случайное значение для процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; резервное случайное значение для процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | конечная точка/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала (публичные объекты и объекты v2) |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; по умолчанию `APP_URL` равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функционала (доставка писем/ссылки) |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функционала (только для сервиса конвертации) |
| `REDIS_HOST`, `REDIS_PORT` | чтение из локального окружения сервиса | пути кода воркеров/очереди | Критично для функционала (только там, где запущен воркер очереди) |

В репозитории не найдено закоммиченных файлов `.env.example` или `.env.sample`. В README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоя и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствующий или изменённый `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу (blind-index) меняется после перезапуска. Это должно рассматриваться как сбой конфигурации в продакшене, а не как безопасный резервный механизм (fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифровки выбрасывают исключение, так как обработанный hex-ключ не равен 32 байтам. |
| Продакшен-JWT не задан или имеет значение-заглушку (sentinel) | API логирует критическую ошибку и завершает работу до начала прослушивания порта. |
| Недоступность R2 | Вызовы сохранения v2/public завершаются с ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется для каждого пути выполнения с исключением. |
| Недоступность Email | Почтовые функции перехватывают/логируют ошибки; основной поток аутентификации/документов может по-прежнему возвращать успешный результат. |
| Отсутствие LibreOffice у конвертера | Эндпоинт `/api/convert` возвращает `422`; очистка временной директории выполняется в `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 MiB, запускает LibreOffice без оболочки (shell) и прослушивает только loopback-интерфейс. |
| Публичный CMP-прокси | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка (allow-list) назначения. Требуется отдельный аудит безопасности перед предоставлением публичного доступа. |

## Необходимые исправления документации

1. Добавьте шаблон реального окружения, включающий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликуйте сгенерированный контракт OpenAPI из файлов маршрутов Express, прежде чем заявлять о наличии стабильного публичного API.
3. Задокументируйте локальное хранение в `uploads/` для v1 и персистентность R2 для v2 как отдельные, в настоящее время сосуществующие процессы.
4. Не описывайте фолбэк на случайные криптографические ключи как безопасный для production.
