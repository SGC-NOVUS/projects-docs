# Эталонные данные: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 2026-09-28.
**Область:** маршруты фронтенда на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. В этом документе описывается реализованное поведение, а не соответствие требованиям или юридическая сертификация.

## Исполняемая структура

Приложение представляет собой браузерный клиент Vue/Vite плюс API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL для выгрузки/скачивания |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процесс LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерная подпись | Приватные ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или стандартный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, подключает маршруты и раздает `dist/` в production.

## Браузерные маршруты

| Маршрут | Требование аутентификации | Реализованное представление/назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, процесс создания и просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник получает данные текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода на защищенные маршруты на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс работы с документами через локальную загрузку |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение является публичным | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочей области |

У API нет зафиксированного в репозитории документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существует два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала читает этот путь в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает предварительно подписанный URL для загрузки со сроком действия пять минут и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Она создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип / по умолчанию | Где используется | Критичность для запуска / функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | строка; production активирует принудительную проверку JWT и раздачу статики | `server/index.ts` | Граница запуска |
| `PORT` | целое число/строка; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный резервный вариант показан выше | `server/db.ts` | Критично для функционала персистентного хранения |
| `JWT_SECRET` | секрет; в production должен отличаться от значения по умолчанию (sentinel) | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-символьный hex-секрет; генерация случайного значения для процесса при отсутствии | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; генерация случайного значения для процесса при отсутствии | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала публичных объектов и объектов v2 |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; по умолчанию `APP_URL` принимает значение `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функционала доставки почты/ссылок |
| `SOFFICE_PATH` | имя/путь к исполняемому файлу; `soffice` | `server/converter.mjs` | Критично для функционала только сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | локальное чтение окружения сервиса | пути в коде воркеров/очередей | Критично для функционала только там, где запущен воркер очередей |

В репозитории не найдено закоммиченных файлов `.env.example` или `.env.sample`. В README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствует или изменён `ENCRYPTION_KEY` либо `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по blind-index нарушается после перезапуска. Это необходимо рассматривать как сбой конфигурации в продакшене, а не как безопасный фолбэк. |
| Недействительная длина ключа шифрования | Операции encrypt/decrypt выбрасывают исключение, так как обработанный hex-ключ не равен 32 байтам. |
| JWT в продакшене не задан или имеет значение-заглушку (sentinel) | API логирует критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы сохранения v2/public завершаются с ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется при каждом сценарии возникновения исключений. |
| Email недоступен | Почтовые функции перехватывают/логируют ошибки; основной процесс аутентификации/работы с документами всё ещё может возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временной директории выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый файл office размером до 25 МиБ, запускает LibreOffice без использования оболочки (shell) и прослушивает только loopback-интерфейс. |
| Публичный прокси CMP | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка назначения (allow-list). Перед публичным открытием требуется отдельный аудит безопасности. |

## Требуемые исправления документации

1. Добавить реальный шаблон окружения, включающий все реализованные секреты и ключи непрерывности состояния, содержащий только заполнители.
2. Опубликовать сгенерированный контракт OpenAPI из файлов маршрутов Express перед тем, как заявлять о наличии стабильного публичного API.
3. Задокументировать локальное хранение v1 `uploads/` и персистентность v2 R2 как отдельные, в настоящее время сосуществующие процессы.
4. Не описывать фоллбэк со случайным криптоключом как безопасный для продакшена.
