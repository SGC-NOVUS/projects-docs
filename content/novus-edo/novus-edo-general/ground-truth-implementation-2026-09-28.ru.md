# Фактическая реализация: Novus Flow.EDO

**Статус:** внутренний статический аудит ревизии от 28.09.2026.
**Область аудита:** маршруты Vue-фронтенда, композиция Express-сервера, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие требованиям или юридическую сертификацию.

## Структура исполняемой системы

Приложение представляет собой клиентский браузерный интерфейс на Vue/Vite и API на Express, запускаемый с помощью `tsx server/index.ts`.

| Компонент | Фактическая реализация |
| --- | --- |
| Пользовательский интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Хранение данных | Prisma 7 с адаптером MariaDB; резервный `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK, с предварительно подписанными URL для загрузки/скачивания |
| Почта | Resend и рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерная подпись | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с помощью `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в продакшене.

## Маршруты браузера

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные, юридические экраны и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, процесс создания и детального просмотра |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Guard навигации запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные попытки перехода на защищенные маршруты на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по Email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организации и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший процесс работы с документами через локальную загрузку |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Процесс работы с DocumentPackage с использованием хранилища R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает Bearer-токен; операции чтения публичны | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочей области |

У API нет зафиксированного в репозитории документа OpenAPI. Роутер и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существуют два независимых пути сохранения документов:

1. Устаревший путь `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает данный путь в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает пятиминутный предварительно подписанный URL для загрузки и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Она создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип / по умолчанию | Где используется | Критичность для запуска / функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; в режиме production активируется соблюдение JWT и раздача статических файлов | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | URL MariaDB; небезопасный локальный резервный вариант приведен выше | `server/db.ts` | Критично для функционала (все хранилища данных) |
| `JWT_SECRET` | secret; в production должен отличаться от эталонного значения | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | 64-символьный hex-secret; случайный резервный вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайный резервный вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала (публичные объекты / объекты v2) |
| `RESEND_API_KEY`, `APP_URL` | секретный ключ почты и URL; `APP_URL` по умолчанию равен `http://localhost:5173` в почтовом сервисе EDO | `server/emailService.ts` | Критично для функционала (доставка писем/ссылки) |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функционала (только для сервиса конвертации) |
| `REDIS_HOST`, `REDIS_PORT` | чтение локального окружения сервиса | пути кода воркера/очереди | Критично для функционала (только там, где запущен воркер очереди) |

Не найдено закоммиченных файлов `.env.example` или `.env.sample`. В README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствует или изменен `ENCRYPTION_KEY` либо `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Зашифрованные ранее поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу (blind-index) нарушается после перезапуска. Это должно рассматриваться как ошибка конфигурации в production, а не как безопасный резервный механизм (fallback). |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифровки вызывают исключение (throws), так как разобранный hex-ключ содержит не 32 байта. |
| В production не задан JWT или использовано значение-заглушка (sentinel) | API логирует критическую ошибку и завершает работу до начала прослушивания порта. |
| Недоступен R2 | Вызовы сохранения v2/public завершаются с ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется при каждом сценарии возникновения исключений. |
| Недоступна электронная почта | Почтовые функции перехватывают/логируют сбои; основной поток аутентификации/документооборота может по-прежнему возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый файл офисного формата размером до 25 МиБ, запускает LibreOffice без командной оболочки (shell) и прослушивает только loopback-интерфейс. |
| Публичный CMP-прокси | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий запрос POST без реализованного таймаута или строгого белого списка назначения (allow-list). Перед публичным открытием требуется отдельный аудит безопасности. |

## Требуемые исправления документации

1. Добавьте реальный шаблон окружения, включающий все реализованные секреты и ключи непрерывности состояния, содержащий только плейсхолдеры.
2. Опубликуйте сгенерированный контракт OpenAPI на основе файлов маршрутов Express, прежде чем заявлять о стабильном публичном API.
3. Задокументируйте локальное хранение v1 uploads/ и персистентное хранение v2 R2 как отдельные, в настоящее время сосуществующие рабочие процессы.
4. Не описывайте фолбэк на случайные криптоключи как безопасный для production.
