# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит процесса оформления (checkout) по состоянию на 28.09.2026.
**Область:** маршруты фронтенда на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие стандартам или юридическую сертификацию.

## Исполняемая форма

Приложение представляет собой браузерный клиент на Vue/Vite и API на Express, запускаемый через `tsx server/index.ts`.

| Поверхность | Фактическая реализация |
| --- | --- |
| Интерфейс браузера | Vue 3, Vue Router, Pinia и клиентские службы подписания |
| API | Express 5 на `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; резервный вариант `DATABASE_URL`: `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL-адресами выгрузки/загрузки |
| Почта | Resend плюс рендеринг Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, порождающий процессы LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Браузерное подписание | Заключенные в браузере приватные ключи документов остаются на стороне клиента в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

Файл `server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с использованием `CORS_ORIGIN` или `*`, подключает маршруты и обслуживает директорию `dist/` в production-режиме.

## Маршруты браузера

| Маршрут | Требование авторизации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные экраны, юридическая информация и экраны аутентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, рабочий процесс создания и просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Защитник навигации (navigation guard) запрашивает текущего пользователя при наличии токена и перенаправляет неаутентифицированные защищенные переходы на страницу `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первом столбце.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о работоспособности процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | `/me` требует Bearer token | Вход по email/паролю и КЭП/ИНН, регистрация и верификация |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer token | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer token | Членство в организациях и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer token | Устаревший рабочий процесс документов с локальной загрузкой |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer token | Рабочий процесс DocumentPackage с хранилищем R2 и участниками маршрутизации |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Публичная эндпоинт-точка хранилища опционально принимает bearer-токен; чтение является публичным | Публичная верификация подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр типов документов рабочего пространства |

У API нет зафиксированного в репозитории документа OpenAPI. Текущим HTTP-контрактом являются роутер и эти исходные файлы.

## Поведение данных и объектного хранилища (object-storage)

Существует два независимых пути персистентности документов:

1. Устаревший путь `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Оригинальное скачивание читает этот путь файловой системы; создание архива выполняется потоком из этого локального состояния.
2. Путь `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает пятиминутный presigned URL для загрузки и загружает подписи/файлы PAdES в R2 после того, как Multer получает их локально.

Публичная верификация сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Создается или переиспользуется фиксированная системная учетная запись для анонимных сохраненных пакетов. Запросы на запись в R2 используют серверное шифрование `AES256`.

## Реестр окружения

| Переменная | Тип/значение по умолчанию | Где используется | Критичность для запуска/функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует проверку JWT и статический вывод | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный запасной вариант указан выше | `server/db.ts` | Критично для функционала всей персистентности |
| `JWT_SECRET` | секрет; в production должен отличаться от заглушки | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 шестнадцатеричных символов; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | секрет; случайный запасной вариант процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексов |
| `CORS_ORIGIN` | строка origin; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | R2 эндпоинт/учетные данные; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию `http://localhost:5173` в почтовой службе EDO | `server/emailService.ts` | Критично для функционала доставки почты/ссылок |
| `SOFFICE_PATH` | имя/путь исполняемого файла; `soffice` | `server/converter.mjs` | Критично для функционала только службы конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение окружения на уровне локального сервиса | пути кода воркеров/очередей | Критично для функционала только там, где запускается воркер очереди |

Файлы `.env.example` или `.env.sample` в репозитории не найдены. В README упоминается лишь часть этого списка, а `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis опущены.

## Режимы сбоев и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` либо `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ / секрет. Ранее зашифрованные поля невозможно расшифровать, а целостность поиска по слепым индексам (blind-index) нарушается после перезапуска. Это должно рассматриваться как сбой конфигурации в production, а не как безопасный фоллбэк. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифрования вызывают ошибку, так как разобранный hex-ключ не равен 32 байтам. |
| JWT для production не задан или используется sentinel-значение | API записывает в лог критическую ошибку и завершает работу до начала прослушивания портов. |
| R2 недоступен | Вызовы персистентности v2/public завершаются ошибкой и возвращают ошибки сервера; очистка временных файлов Multer не гарантируется для каждого пути обработки исключений. |
| Электронная почта недоступна | Почтовые функции перехватывают и логируют ошибки; основной сценарий аутентификации/документооборота при этом может вернуть успех. |
| У конвертера отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в блоке `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 МБ, запускает LibreOffice без оболочки (shell) и принимает соединения только на loopback-интерфейсе. |
| Публичный CMP-прокси | Прокси принимает переданный вызывающей стороной целевой адрес, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого белого списка назначений. Перед публичным размещением требуется отдельный аудит безопасности. |

## Требуемые исправления документации

1. Добавить шаблон реально используемого окружения, содержащий все реализованные секреты и ключи обеспечения непрерывности состояния, исключительно с плейсхолдерами.
2. Опубликовать сгенерированный OpenAPI контракт из файлов маршрутов Express до того, как заявлять о стабильности публичного API.
3. Задокументировать локальные `uploads/` в v1 и персистентность в R2 в v2 как раздельные рабочие процессы, сосуществующие в настоящее время.
4. Не описывать fallback на случайные криптографические ключи как безопасный для production.
