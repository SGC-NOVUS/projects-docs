# Ground truth: реализация Novus Flow.EDO

**Статус:** внутренний статический аудит среза от 2026-09-28.
**Область охвата:** маршруты frontend на Vue, композиция сервера Express, персистентность Prisma/R2, криптография, конвертер и чтение переменных окружения. Этот документ описывает реализованное поведение, а не соответствие стандартам или юридическую сертификацию.

## Исполняемая структура

Приложение представляет собой браузерный клиент на Vue/Vite и Express API, запускаемый через `tsx server/index.ts`.

| Компонент | Фактическая реализация |
| --- | --- |
| Browser UI | Vue 3, Vue Router, Pinia и клиентские сервисы подписи |
| API | Express 5 на порту `PORT`, по умолчанию `3001` |
| Персистентность | Prisma 7 с адаптером MariaDB; значение по умолчанию для `DATABASE_URL` — `mysql://novus:novus123@localhost:3306/novus_edo` |
| Объектное хранилище | Cloudflare R2 через AWS S3 SDK с предварительно подписанными URL для загрузки/скачивания |
| Почта | Resend плюс рендеринг через Vue Email |
| Конвертер | Независимый HTTP-сервис на `127.0.0.1:4174`, запускающий LibreOffice (`SOFFICE_PATH` или `soffice`) |
| Подпись в браузере | Закрытые ключи документов остаются на стороне браузера в соответствии с реализованной клиентской архитектурой; сервер сохраняет артефакты подписи и метаданные |

`server/index.ts` загружает dotenv, отклоняет отсутствующий или фиктивный `JWT_SECRET` только при `NODE_ENV=production`, настраивает CORS с `CORS_ORIGIN` или `*`, монтирует маршруты и раздает `dist/` в продакшене.

## Браузерные маршруты

| Маршрут | Требование аутентификации | Реализованное представление / назначение |
| --- | --- | --- |
| `/`, `/about`, `/privacy`, `/terms`, `/login`, `/register` | Нет | Публичные страницы, юридическая информация и экраны идентификации |
| `/dashboard` | Да | В настоящее время повторно использует `Inbox.vue` |
| `/documents`, `/documents/new`, `/documents/:id` | Да | Список документов, рабочий процесс создания и просмотра деталей |
| `/contacts`, `/archive`, `/settings` | Да | Адресная книга, архив и настройки |
| `/features`, `/pricing` | Нет | Перенаправление на `/` |

Навигационный защитник (navigation guard) получает данные текущего пользователя при наличии токена и перенаправляет неаутентифицированный доступ к защищенным маршрутам на `/login` (`src/router/index.ts`).

## Каталог Express API

Все приведенные ниже пути имеют префикс `/api`, указанный в первой колонке.

| Префикс | Операции | Аутентификация | Назначение |
| --- | --- | --- | --- |
| `/health` | `GET` | Нет | Базовый ответ о состоянии процесса |
| `/proxy` | `POST` | Нет | Бинарный прокси для трафика EUSign CMP/TSP/OCSP |
| `/auth` | `POST /register`, `POST /login`, `GET /verify-email`, `GET /me` | Для `/me` требуется bearer-токен | Вход по Email/паролю и КЭП/ИНН, регистрация и подтверждение |
| `/users` | `PUT /me`, `PUT /me/password` | Bearer-токен | Обновление профиля/email и установка/смена пароля |
| `/organizations` | `GET /`, `POST /`, `GET /:id/members`, `POST /:id/members` | Bearer-токен | Членство в организации и управление участниками |
| `/documents` | `POST /`, `GET /`, `GET /tasks`, `POST /:id/sign`, `GET /:id/archive`, `GET /:id/download` | Bearer-токен | Устаревший рабочий процесс загрузки локальных документов |
| `/v2/documents` | `GET /`, `GET /:id`, `POST /presigned-url`, `POST /`, `POST /:id/sign`, `DELETE /:id`, `POST /:id/cancel`, `GET /:id/archive` | Bearer-токен | Рабочий процесс DocumentPackage с хранилищем R2 и маршрутизацией участников |

| `/public` | `POST /store-verification`, `GET /verify/:id`, `GET /verify/:id/protocol` | Эндпоинт сохранения опционально принимает bearer-токен; чтение является публичным | Публичная проверка подписи и скачивание протокола |
| `/settings/document-types` | `GET`, `POST`, `POST /:id/toggle` | Bearer-токен | Глобальный реестр типов документов / реестр рабочей области |

У API нет зафиксированного документа OpenAPI. Маршрутизатор и эти исходные файлы представляют собой текущий HTTP-контракт.

## Поведение данных и объектного хранилища

Существует два независимых пути сохранения документов:

1. Устаревший `/api/documents` использует Multer `uploads/` и сохраняет локальные пути в базе данных. Скачивание оригинала считывает файл по этому пути в файловой системе; создание архива передается потоком из этого локального состояния.
2. `/api/v2/documents` сохраняет метаданные пакета в Prisma и использует ключи объектов R2. Он выдает предварительно подписанный URL для загрузки со сроком действия пять минут и загружает подписи/PAdES-файлы в R2 после того, как Multer получает их локально.

Публичная проверка сохраняет анонимные объекты по пути `unclaimed/<RNOKPP>/<document UUID>/...`; аутентифицированная отправка использует `individuals/<user ID>/documents/<verification ID>/...`. Процесс создает или повторно использует фиксированную системную учетную запись для анонимных сохраненных пакетов. Записи в R2 запрашивают шифрование на стороне сервера `AES256`.

## Реестр переменных окружения

| Переменная | Тип / по умолчанию | Где используется | Критичность для запуска / функционала |
| --- | --- | --- | --- |
| `NODE_ENV` | string; production активирует обязательное применение JWT и раздачу статического контента | `server/index.ts` | Граница запуска |
| `PORT` | integer/string; `3001` | `server/index.ts` | Граница запуска |
| `DATABASE_URL` | MariaDB URL; небезопасный локальный резервный вариант (fallback) показан выше | `server/db.ts` | Критично для функционала всех механизмов хранения данных |
| `JWT_SECRET` | secret; в production должен отличаться от значения по умолчанию | `server/index.ts`, `server/middleware/auth.ts` | Критично для безопасности |
| `ENCRYPTION_KEY` | секрет из 64 hex-символов; случайный резервный вариант для процесса | `server/utils/crypto.ts` | Критично для безопасности и чтения данных |
| `BLIND_INDEX_SECRET` | secret; случайный резервный вариант для процесса | `server/utils/crypto.ts` | Критично для непрерывности поиска/индексации |
| `CORS_ORIGIN` | origin string; `*` | `server/index.ts` | Граница безопасности |
| `R2_ACCOUNT_ID`, `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PRESIGNED_EXPIRES_IN` | эндпоинт/учетные данные R2; срок действия `900` секунд | `server/storageService.ts` | Критично для функционала объектов v2/публичных объектов |
| `RESEND_API_KEY`, `APP_URL` | секрет почты и URL; `APP_URL` по умолчанию принимает значение `http://localhost:5173` в почтовой службе ЭДО | `server/emailService.ts` | Критично для функционала доставки писем / ссылок |
| `SOFFICE_PATH` | имя/путь к исполняемому файлу; `soffice` | `server/converter.mjs` | Критично для функционала только сервиса конвертации |
| `REDIS_HOST`, `REDIS_PORT` | чтение локальных для сервиса переменных окружения | пути кода воркера/очереди | Критично для функционала только там, где запущен воркер очереди |

Файлы `.env.example` или `.env.sample` не найдены в репозитории. В README упоминается только часть этого списка и опущены `ENCRYPTION_KEY`, `BLIND_INDEX_SECRET`, `NODE_ENV`, `PORT`, `R2_ACCOUNT_ID`, `R2_PRESIGNED_EXPIRES_IN`, `SOFFICE_PATH` и настройки Redis.

## Сценарии отказов и ограничения реализации

| Ситуация | Наблюдаемое поведение |
| --- | --- |
| Отсутствие или изменение `ENCRYPTION_KEY` или `BLIND_INDEX_SECRET` | Процесс генерирует новый случайный ключ/секрет. Ранее зашифрованные поля не могут быть расшифрованы, а непрерывность поиска по слепому индексу меняется после перезапуска. Это должно рассматриваться как ошибка конфигурации production, а не как безопасный фолбэк. |
| Недопустимая длина ключа шифрования | Операции шифрования/расшифровки вызывают исключение, поскольку разобранный hex-ключ содержит не 32 байта. |
| JWT для production не задан или содержит значение-заглушку (sentinel) | API записывает критическую ошибку в лог и завершает работу до начала прослушивания сокета. |
| Недоступность R2 | Вызовы сохранения v2/public завершаются ошибкой и возвращают серверные ошибки; очистка временных файлов Multer не гарантируется при каждом пути обработки исключений. |
| Недоступность Email | Почтовые функции перехватывают/логируют сбои; основной поток аутентификации/документов все еще может возвращать успешный результат. |
| В конвертере отсутствует LibreOffice | `/api/convert` возвращает `422`; очистка временного каталога выполняется в `finally`. |
| Входные данные конвертера | Конвертер принимает один поддерживаемый офисный файл размером до 25 MiB, запускает LibreOffice без оболочки (shell) и прослушивает только интерфейс loopback. |
| Публичный CMP-прокси | Прокси принимает целевой адрес, предоставленный вызывающей стороной, эвристически нормализует HTTP/HTTPS и выполняет исходящий POST-запрос без реализованного таймаута или строгого списка разрешенных назначений (allow-list). Перед публичным открытием требуется отдельный аудит безопасности. |

## Требуются исправления документации

1. Добавьте реальный шаблон окружения, включающий все реализованные секреты и ключи непрерывности состояния, только с плейсхолдерами.
2. Опубликуйте сгенерированный контракт OpenAPI из файлов маршрутов Express, прежде чем заявлять о стабильном публичном API.
3. Задокументируйте локальное хранение `uploads/` для v1 и персистентность R2 для v2 как отдельные, в настоящее время сосуществующие рабочие процессы.
4. Не описывайте фоллбэк на случайный криптографический ключ как безопасный для продакшена.
