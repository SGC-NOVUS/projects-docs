# Архітектура безпеки та криптографічна модель

**Проєкт:** Novus Life  
**Розробник:** SGC-NOVUS (System Generation Core)  
**Рівень захисту:** Клієнтське наскрізне шифрування з нульовим розголошенням (Zero-Knowledge E2EE)

---

## 1. Модель загроз та архітектурні принципи

Архітектура Novus Life базується на припущенні, що центральні сервери та канали зв'язку можуть зазнавати спроб несанкціонованого доступу. Для забезпечення абсолютної конфіденційності платформа реалізує архітектуру **Zero-Knowledge**:

1. **Виключно клієнтське шифрування:** Первинні показники лічильників, назви адрес, фінансові суми, баланси карток та примітки ніколи не надсилаються на сервер у відкритому вигляді.
2. **Відсутність майстер-ключів на сервері:** База даних PostgreSQL та серверні API не містять закритих ключів або секретів.
3. **Апаратне прискорення криптографії:** Усі операції виконуються через W3C **Web Crypto API** (`crypto.subtle`) з використанням інструкцій AES-NI.

---

## 2. Криптографічні примітиви

### 2.1 Симетричне шифрування (AES-GCM-256)
- **Алгоритм:** `AES-GCM` (Galois/Counter Mode).
- **Довжина ключа:** 256 біт.
- **Вектор ініціалізації (IV):** 96-бітне криптографічно стійке число (`crypto.getRandomValues()`).
- **Тег автентифікації:** 128 біт.

### 2.2 Деривація ключів (PBKDF2)
- **Алгоритм:** `PBKDF2`.
- **PRF:** `HMAC-SHA-256`.
- **Кількість ітерацій:** 100 000.
- **Сіль:** Ізольована сіль ентропії пристрою.

---

## 3. Захист сховища

### 3.1 Persistent Storage API
Novus Life активує захист від автоматичного очищення браузером:
```typescript
await navigator.storage.persist();
```

### 3.2 Резервне копіювання Google Drive
Снапшот резервної копії (`novus_life_vault.json.enc`) зашифровується на клієнті через AES-256-GCM перед передачею в системну теку `appDataFolder`.
