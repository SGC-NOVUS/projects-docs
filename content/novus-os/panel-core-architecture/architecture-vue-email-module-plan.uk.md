# План модулю Vue Email (Panel-Core)

## Мета
Додати повноцінний модуль шаблонів електронної пошти для NOVUS-OS з такими можливостями:
- генерація HTML-листів із підтримкою тем оформлення,
- версійне сховище шаблонів,
- UI для редагування та попереднього перегляду,
- безпечні конвеєри для тестової відправки та продуктивної доставки.

## Доцільність
Це реалістично та технічно нескладно за умови поетапного впровадження.
Основна складність полягає не в рендерингу, а в управлінні шаблонами (версіонування, локалізація, погодження та безпека доставки).

## Рекомендований стек
- `vue-email` для створення шаблонів у вигляді компонентів Vue.
- `@vue-email/components` для безпечних у контексті електронної пошти будівельних блоків.
- `@vue-email/render` для серверного рендерингу HTML.
- Додатковий шар візуального редактора:
  - `vue-email-editor` (обгортка Unlayer) для інтерфейсу drag-and-drop.
  - Зберігати режим коду шаблону як канонічне джерело, щоб уникнути прив'язки до постачальника.

## Пропонована архітектура

### 1) Backend (PHP control-plane)
- Новий модуль: `NotificationsEmail`.
- Таблиці сховища:
  - `panel_email_templates` (id, key, locale, schema_version, status, created_by, updated_by, timestamps).
  - `panel_email_template_revisions` (template_id, revision, source_json, compiled_html, subject, checksum, created_by, created_at).
  - `panel_email_dispatch_log` (template_key, recipient, transport, status, provider_id, error_code, sent_at).
- Сервіси:
  - Сервіс реєстру шаблонів.
  - Сервіс мосту рендерера (sidecar на Node або виклик CLI) для рендерингу Vue Email у HTML.
  - Сервіс тестової відправки з білим списком одержувачів у пісочниці.

### 2) Frontend (Vue модулі)
- Новий модуль: `resources/js/modules/NotificationsEmail`.
- Подання:
  - Каталог шаблонів,
  - Редактор шаблонів,
  - Історія ревізій та diff,
  - Живий попередній перегляд (передумови ширини для десктопа та мобільних пристроїв),
  - Панель тестового надсилання.
- Інтеграція тем:
  - використовувати лише токени `var(--sgc-*)` та `var(--novus-*)` з контракту `config/themes.php`,
  - експортувати детермінований піднабір поштових токенів (без ефектів лише для середовища виконання, таких як blur/backdrop).

### 3) Рендеринг та Доставка
- Шлях реендерингу:
  1. Користувач редагує Vue Email шаблон.
  2. Шаблон компілюється в HTML в ізольованому середовищі виконання рендерера.
  3. Знімок HTML зберігається з незмінною ревізією.
- Транспортні протоколи доставки:
  - Адаптер SMTP-провайдера (перший етап),
  - API-провайдери пізніше (Mailgun/SES/Postmark).

## Безпека та Відповідність
- Сувора санітація та заблоковані теги/атрибути для небезпечного HTML.
- Жодних вбудованих секретів у шаблонах.
- RBAC для кожного шаблону окремо (`platform.notifications.email.read/manage/send`).
- Повний журнал аудиту для подій публікації, відкоту та надсилання.

## План інкрементальної доставки

### Фаза 1 (Низький ризик)
- Додати схему бекенду + API для CRUD шаблонів і ревізій.
- Додати текстовий редактор шаблонів на основі коду (без підтримки drag-and-drop).
- Додати попередній перегляд та тестове відправлення в пісочниці.

### Фаза 2
- Додати візуальний редактор (`vue-email-editor`) під прапорцем функцій (feature flag).
- Додати конструктор міток злиття (merge-tag) та валідацію.

### Фаза 3
- Додати автоматизацію робочих процесів (листування за подіями),
- Додати варіанти A/B-тестування шаблонів та метрики доставки.

## Відомі ризики
- Залежність від постачальника візуального редактора (drag-and-drop).
- Розбіжності в сумісності HTML/поштових клієнтів.
- Складність міграції шаблонів у разі внесення несумісних змін до схеми.

## Рішення
Спочатку реалізувати Фазу 1 в канонічному режимі шаблонів на основі коду, після чого додати візуальний редактор як додатковий шар.
