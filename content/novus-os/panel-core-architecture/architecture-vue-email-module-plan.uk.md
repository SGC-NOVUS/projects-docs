# План модуля Vue Email (Panel-Core)

## Мета
Додати першокласний модуль шаблонів електронної пошти для NOVUS-OS з:
- генерацією HTML-листів із підтримкою тем,
- версіонованим сховищем шаблонів,
- UI-редагуванням та попереднім переглядом,
- безпечними конвеєрами тестового відправлення та продуктивної доставки.

## Доцільність
Це реалістично та технічно нескладно за умови поетапного впровадження.
Основна складність полягає не в рендерингу, а в управлінні шаблонами (версіонування, i18n, затвердження та безпека доставки).

## Рекомендований стек
- `vue-email` для створення шаблонів як Vue-компонентів.
- `@vue-email/components` для безпечних для пошти будівельних блоків.
- `@vue-email/render` для серверного рендерингу HTML.
- Додатковий шар візуального редактора:
  - `vue-email-editor` (обгортка Unlayer) для UX з перетягуванням (drag-and-drop).
  - Зберігати режим кодових шаблонів як канонічне джерело для уникнення залежності від вендора.

## Запропонована архітектура

### 1) Бендкенд (PHP control-plane)
- Новий модуль: `NotificationsEmail`.
- Таблиці сховища:
  - `panel_email_templates` (id, key, locale, schema_version, status, created_by, updated_by, timestamps).
  - `panel_email_template_revisions` (template_id, revision, source_json, compiled_html, subject, checksum, created_by, created_at).
  - `panel_email_dispatch_log` (template_key, recipient, transport, status, provider_id, error_code, sent_at).
- Сервіси:
  - Сервіс реєстру шаблонів.
  - Сервіс-міст рендерера (sidecar на Node або виклик CLI) для рендерингу Vue Email в HTML.
  - Сервіс тестового надсилання з білим списком одержувачів пісочниці.

### 2) Frontend (Vue модулі)
- Новий модуль: `resources/js/modules/NotificationsEmail`.
- Подання (Views):
  - Каталог шаблонів,
  - Редактор шаблонів,
  - Історія ревізій та diff,
  - Живий попередній перегляд (пресети ширини для десктопа та мобільних пристроїв),
  - Панель тестового надсилання.
- Інтеграція тем:
  - використовувати лише токени `var(--sgc-*)` та `var(--novus-*)` з контракту `config/themes.php`,
  - експортувати детермінований під набір поштових токенів (без ефектів лише для рантайму, таких як blur/backdrop).

### 3) Рендеринг і доставка
- Шлях рендерингу:
  1. Користувач редагує поштовий шаблон Vue.
  2. Шаблон компілюється в HTML в ізольованому середовищі рендерингу.
  3. Знімок HTML зберігається з незмінною ревізією.
- Транспортні протоколи доставки:
  - адаптер SMTP-провайдера (перший етап),
  - API-провайдери пізніше (Mailgun/SES/Postmark).

## Безпека та відповідність стандартам
- Сувора санітизація та заблоковані теги/атрибути для небезпечного HTML.
- Відсутність секретів усередині шаблонів (inline).
- RBAC для кожного шаблону окремо (`platform.notifications.email.read/manage/send`).
- Повний журнал аудитів (audit trail) для подій публікації, відкоту та надсилання.

## План інкрементальної доставки

### Фаза 1 (Низький ризик)
- Додати бекенд-схему + API для CRUD шаблонів і ревізій.
- Додати текстовий редактор шаблонів на основі коду (без перетягування — drag-and-drop).
- Додати попередній перегляд і тестове надсилання у пісочниці.

### Фаза 2
- Додати візуальний редактор (`vue-email-editor`) за прапорцем функціоналу (feature flag).
- Додати конструктор тегів злиття (merge-tag) та їх валідацію.

### Фаза 3
- Додати автоматизацію робочих процесів (event-triggered emails),
- Додати A/B варіанти шаблонів і метрики доставки.

## Відомі ризики
- Залежність від вендора візуального редактора (drag-and-drop).
- Розходження в сумісності HTML/поштових клієнтів.
- Складність міграції шаблонів при внесенні несумісних змін до схеми.

## Рішення
Спочатку реалізувати Фазу 1 (канонічний режим шаблону на основі коду), а потім додати візуальний редактор як опціональний шар.
