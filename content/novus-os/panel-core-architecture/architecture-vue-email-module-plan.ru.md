# План модуля Vue Email (Panel-Core)

## Цель
Добавить первоклассный модуль шаблонов электронной почты для NOVUS OS, включающий:
- генерацию HTML-писем с поддержкой тем оформления,
- хранение версионированных шаблонов,
- UI для редактирования и предварительного просмотра,
- безопасные пайплайны для тестовой отправки и промышленной доставки.

## Целесообразность
Это реалистично и технически просто при поэтапном внедрении.
Основная сложность заключается не в рендеринге, а в управлении шаблонами (версионирование, i18n, согласования и безопасность доставки).

## Рекомендуемый стек
- `vue-email` для создания шаблонов в виде компонентов Vue.
- `@vue-email/components` для безопасных в контексте email строительных блоков.
- `@vue-email/render` для серверного рендеринга HTML.
- Опциональный слой визуального редактора:
- `vue-email-editor` (обертка над Unlayer) для UX с поддержкой drag-and-drop.
- Сохранение режима кодовых шаблонов в качестве канонического источника во избежание привязки к вендору.

## Предлагаемая архитектура

### 1) Бэкенд (PHP Control-Plane)
- Новый модуль: `NotificationsEmail`.
- Таблицы хранения:
  - `panel_email_templates` (id, key, locale, schema_version, status, created_by, updated_by, timestamps).
  - `panel_email_template_revisions` (template_id, revision, source_json, compiled_html, subject, checksum, created_by, created_at).
  - `panel_email_dispatch_log` (template_key, recipient, transport, status, provider_id, error_code, sent_at).
- Сервисы:
  - Сервис реестра шаблонов.
  - Сервис моста рендерера (sidecar-сервис на Node или вызов CLI) для рендеринга Vue Email в HTML.
  - Сервис тестовой отправки с белым списком получателей в песочнице.

### 2) Frontend (Vue модули)
- Новый модуль: `resources/js/modules/NotificationsEmail`.
- Представления:
  - Каталог шаблонов,
  - Редактор шаблонов,
  - История ревизий и diff,
  - Живой предпросмотр (пресеты ширины для десктопа и мобильных устройств),
  - Панель тестовой отправки.
- Интеграция тем:
  - использовать только токены `var(--sgc-*)` и `var(--novus-*)` из контракта `config/themes.php`,
  - экспортировать детерминированный подмножество токенов email (без эффектов, доступных только во время выполнения, таких как blur/backdrop).

### 3) Рендеринг и доставка
- Путь рендеринга:
  1. Пользователь редактирует Vue-шаблон email.
  2. Шаблон компилируется в HTML в изолированной среде выполнения рендерера.
  3. HTML-снимок сохраняется с неизменяемой ревизией.
- Транспорты доставки:
  - адаптер провайдера SMTP (первый этап),
  - провайдеры API позже (Mailgun/SES/Postmark).

## Безопасность и соответствие требованиям
- Строгая санитизация и блокировка тегов/атрибутов для небезопасного HTML.
- Отсутствие секретов в виде inline-данных в шаблонах.
- RBAC на уровне шаблонов (`platform.notifications.email.read/manage/send`).
- Полный журнал аудита для событий публикации, отката и отправки.

## План инкрементальной поставки

### Фаза 1 (Низкий риск)
- Добавить бэкенд-схему + API для CRUD шаблонов и ревизий.
- Добавить редактор шаблонов на основе кода (без drag-and-drop).
- Добавить предварительный просмотр и тестовую отправку в песочнице (sandbox).

### Фаза 2
- Добавить визуальный редактор (`vue-email-editor`) под защитой feature flag.
- Добавить конструктор тегов слияния (merge-tag) и валидацию.

### Фаза 3
- Добавить автоматизацию рабочих процессов (триггерные email-рассылки по событиям),
- Добавить A/B варианты шаблонов и метрики доставки.

## Известные риски
- Зависимость от вендора визуального редактора (drag-and-drop).
- Рассинхронизация совместимости с HTML/email-клиентами.
- Сложность миграции шаблонов при введении несовместимых изменений схемы (breaking changes).

## Решение
Сначала приступить к Фазе 1 (канонический режим шаблонов на основе кода), затем добавить визуальный редактор в качестве опционального слоя.
