# Граница gRPC TLS и HMAC-подписи

## Транспорт использует TLS, а не mTLS

gRPC-сервер агента загружает сертификат сервера и закрытый ключ и обслуживает канал по протоколу TLS. Прямой драйвер панели предоставляет настроенный CA-сертификат и может задавать переопределение имени сервера (server-name override). Текущий клиентский канал не предъявляет клиентский сертификат, и агент не настраивает политику проверки клиентских сертификатов. Следовательно, реализованный транспорт представляет собой TLS с аутентификацией запросов на уровне приложения, а не взаимный TLS (mutual TLS).

Если настроенный сертификат или ключ отсутствуют, агент пытается создать самоподписанный сертификат в своей настроенной TLS-директории. Операторы должны убедиться, что панель доверяет центру сертификации ( CA ) и использует ожидаемое имя сервера для данного узла.

## Метаданные подписанного запроса

Аутентифицированные унарные (unary) вызовы и вызовы потоковой передачи (streaming) содержат:

| Метаданные | Значение |
| --- | --- |
| `x-request-timestamp` | Метка времени Unix в секундах, используемая для проверки актуальности. |
| `x-signature` | Шестнадцатеричная HMAC-SHA256 подпись для закодированного запроса Protobuf и метки времени. |
| `x-panel-uuid` | Идентификатор панели, проверяемый по состоянию сопряжения агента. |

Агент отклоняет отсутствующие метаданные, некорректно сформированные метки времени и метки времени, выходящие за пределы допустимого окна расхождения часов. Окно по умолчанию составляет 15 секунд. Сравнение подписей выполняется за постоянное время. Replay Guard отклоняет подпись, которая ранее наблюдалась в пределах активного временного окна.

## Поведение при отклонении запросов и аудит

Сбои аутентификации возвращаются как gRPC `UNAUTHENTICATED`; идентичность панели, нарушающая блокировку сопряженной панели, отклоняется как `PERMISSION_DENIED`. Запросы, превышающие настроенное ограничение частоты запросов для одной панели, отклоняются как `RESOURCE_EXHAUSTED`. Значения по умолчанию составляют 600 запросов в минуту с всплеском до 120.

Когда ведение журнала аудита включено, отклоненные вызовы и результаты обработки записываются в виде структурированных событий. Не помещайте мастер-секреты, закрытые ключи или полные учетные данные в журналы приложений или документацию.

## Операционная политика

- Поля запросов и методы сервисов должны строго соответствовать принципу «contract-first» в определениях Protobuf.
- Выполняйте ротацию учетных данных сопряжения только через поддерживаемый рабочий процесс панели.
- Обновляйте описание транспорта, оперативные инструкции и журнал изменений при каждом изменении реализованного поведения аутентификации.

Ссылки на реализацию: `internal/grpcserver/server.go`, `internal/grpcserver/daemon_runtime.go`, `internal/security/interceptors.go` и `NovusAgentDirectDriver` для панели.
