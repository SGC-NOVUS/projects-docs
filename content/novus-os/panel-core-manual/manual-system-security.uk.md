# Системна безпека

NOVUS-OS застосовує багаторівневі елементи керування безпекою для ідентифікації, дозволів, сеансів браузера, Control-Plane, транспорту агента та керованих робочих навантажень. Цей посібник призначений для авторизованих операторів, які використовують Panel; він не є довідником команд із захисту хоста.

## Відповідальність за безпеку

| Сфера | Відповідальність оператора |
| --- | --- |
| Ідентифікація | Використовуйте індивідуальний обліковий запис, багатофакторну верифікацію там, де це вимагається, та роль із найменшими привілеями для кожного завдання. |
| Доступ | Регулярно переглядайте доступ користувачів, команд та API; видаляйте доступ, який більше не потрібен. |
| Вузли | З'єднуйте в пари та керуйте вузлами виключно через затверджений робочий процес Panel. |
| Робочі навантаження | Використовуйте робочі процеси Panel для операцій із середовищем виконання, файлами, мережею та резервним копіюванням замість прямого доступу до хоста. |
| Іциденти | Зберігайте відповідні докази аудиту Panel та дотримуйтесь затвердженого процесу реагування на інциденти. |

## Безпечні операції

- Переглядайте сповіщення та стан безпеки в Panel перед внесенням привілейованих змін.
- Використовуйте обов'язковий процес підтвердження або багатофакторний процес для чутливих операцій.
- Зберігайте в таємниці сеанси браузера, облікові дані API, токени інтеграції та матеріали для відновлення.
- Перевіряйте цільовий вузел, екземпляр та область дії дії перед її підтвердженням.
- Реєструйте виробничі зміни через процес контролю змін організації.

## Коли щось здається несправним

1. Зупиніть уражений робочий процес, якщо Панель надає безпечний шлях скасування.
2. Не намагайтеся виконувати пряме усунення несправностей хоста або обходити вимоги авторизації.
3. Збережіть відповідний стан Панелі, ідентифікатори аудиту та мітки часу для уповноваженої групи реагування.
4. Передайте інформацію про підозру у витоку облікових даних, несанкціонованому доступі або порушенні цілісності через приватний процес безпеки.
