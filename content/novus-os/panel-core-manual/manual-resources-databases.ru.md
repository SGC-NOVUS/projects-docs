# Базы данных

Рабочая область Databases управляет созданными пользователем базами данных Data-Plane и отображает инвенроризацию только для чтения с подключенных узлов. Данные Control-Plane изолированы от операций с базами данных тенантов.

## Рабочий процесс оператора

1. Выберите узел и область базы данных в Panel.
2. Проверьте базы данных, таблицы, пользователей и привилегии перед запросом изменений.
3. Используйте предоставленные формы для создания базы данных, управления пользователями или настройки привилегий.
4. Подтверждайте деструктивные действия только после проверки выбранного ресурса.
5. Используйте рабочую область Backups для создания точки восстановления перед деструктивным изменением или экспортом.

## Модель доступа

- Администрирование баз данных требует разрешения database-management.
- Для экспорта требуется специальное разрешение backup-export.
- Подключенные узлы поддерживают распределенную инвентаризацию. Операции записи доступны только там, где это явно разрешено текущим контрактом узла.
- Системные хранилища Control-Plane не предоставляются в качестве целей для баз данных тенантов.

## Безопасные операции

Panel проверяет имена, области и привилегии перед пересылкой запроса владельцу базы данных. Учетные данные не возвращаются в ответах API и не отображаются после создания. Используйте принцип наименьших привилегий, ротируйте учетные данные с помощью утвержденного рабочего процесса и регистрируйте производственные изменения через управление изменениями.

## Восстановление и эскалация

Для сбоев операций сохраните идентификатор запроса Panel и состояние ошибки. Не выполняйте прямые команды базы данных и не изменяйте схемы за пределами утвержденной процедуры обслуживания. Восстановление и диагностика схем выполняются уполномоченной командой платформы.

Процедуры реализации, топологии и миграции ограничены внутренней инженерной процедурой.
