# Бази даних

Робочий простір Бази даних керує створеними користувачами Data-Plane базами даних і відображає інвентаризацію лише для читання з підключених вузлів. Дані Control-Plane ізольовані від операцій з базами даних тенантів.

## Робочий процес оператора

1. Виберіть вузол і область бази даних у Панелі.
2. Перегляньте бази даних, таблиці, користувачів і привілеї перед запитом на зміну.
3. Використовуйте надані форми для створення бази даних, керування користувачами або налаштування привілеїв.
4. Підтверджуйте руйнівні дії лише після перевірки вибраного ресурсу.
5. Використовуйте робочий простір Резервні копії для створення точки відновлення перед руйнівною зміною або експортом.

## Модель доступу

- Адміністрування баз даних вимагає дозволу database-management.
- Експорт вимагає спеціального дозволу backup-export.
- Підключені вузли підтримують розподілену інвентаризацію. Операції запису доступні лише там, де це явно дозволено контрактом поточного вузла.
- Системні сховища Control-Plane не надаються як цільові бази даних тенантів.

## Безпечні операції

Панель перевіряє імена, області та привілеї перед пересиланням запиту власнику бази даних. Облікові дані не повертаються у відповідях API і не відображаються після створення. Використовуйте принцип найменших привілеїв, ротуйте облікові дані за допомогою затвердженого робочого процесу та реєструйте зміни у виробничому середовищі через управління змінами.

## Відновлення та ескалація

Для невдалих операцій збережіть ідентифікатор запиту Панелі та стан помилки. Не виконуйте прямі команди бази даних і не змінюйте схеми поза межами затвердженої процедури обслуговування. Відновлення та діагностика схем виконуються уповноваженою командою платформи.

Процедури реалізації, топології та міграції обмежені внутрішньою інженерною процедурою.
