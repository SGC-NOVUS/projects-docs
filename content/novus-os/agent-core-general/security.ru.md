# NOVUS Agent: Модель безопасности

NOVUS Agent является хост-компонентом Data-Plane daemon. Он принимает только поддерживаемый транспорт Panel и не является универсальной административной конечной точкой.

## Границы доверия

- gRPC транспорт требует обязательного использования TLS.
- Привилегированные запросы аутентифицируются с использованием идентичности сопряженной Panel, подписанного запроса, проверки актуальности (freshness validation), защиты от повторного воспроизведения (replay protection) и ограничения частоты запросов (rate limiting) для каждой идентичности.
- После сопряжения Agent привязывается к одной Panel. Запрос от другой идентичности Panel отклоняется.
- Сопряжение (pairing), отвязка (unclaim) и ротация секретов являются чувствительными к безопасности операциями control-plane и должны инициироваться через утвержденный рабочий процесс Panel.

Реализация подписания, политика таймингов, секретные материалы и детали хранения состояния являются внутренней информацией о безопасности. Используйте поддерживаемый клиент Panel или сгенерированные инструменты контрактов вместо реализации собственных клиентов.

## Выполнение на хосте

Agent выполняет разрешенные операции с контейнерами, файловой системой, телеметрией и терминалом только после валидации транспорта. Сеансы терминала используют утвержденную политику оболочки и ретранслируются через Panel; браузеры не получают прямой доступ к оболочке хоста.

Операции с файловой системой нормализуют запрашиваемые пути и применяют защиту от символических ссылок. Политики VFS для конкретных контекстов выполнения остаются активной областью усиления безопасности; операторы не должны рассчитывать на изоляцию тенантов сверх текущего поддерживаемого рабочего процесса и назначенных разрешений Panel.

## Аудит и операции

Когда ведение журнала аудита включено, Agent генерирует структурированные события жизненного цикла безопасности запросов для оперативного контроля. Рассматривайте записи аудита как конфиденциальные данные: они могут содержать имена методов, причины и идентификаторы Panel.

Операторам следует:

1. Развертывать Agent только через утвержденный канал выпуска и установки.
2. Ограничивать сетевой доступ в соответствии с утвержденной инфраструктурной политикой.
3. Мониторить доступность Agent и сбои аутентификации через Panel и систему наблюдаемости хоста.
4. Ротировать учетные данные сопряжения с помощью поддерживаемого процесса Control-Plane.
5. Не допускать попадания секретов, материалов TLS, токенов сопряжения и логов хоста в системы контроля версий и публичные каналы поддержки.

Сведения о поддерживаемых настройках см. в [Справочнике по конфигурации](CONFIGURATION.md). Внутренние результаты реализации предназначены исключительно для инженерного рабочего пространства.
