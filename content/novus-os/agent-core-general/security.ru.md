# NOVUS Agent: Модель безопасности

NOVUS Agent является хост-компонентом Data-Plane. Он принимает только поддерживаемый транспорт Panel и не является универсальной административной конечной точкой.

## Границы доверия

- gRPC транспорт требует обязательного использования TLS.
- Привилегированные запросы аутентифицируются с использованием идентичности сопряженной Panel, подписанного запроса, проверки актуальности (freshness), защиты от повторного воспроизведения (replay protection) и ограничения частоты запросов (rate limiting) для каждого субъекта.
- После сопряжения Agent привязывается к одной Panel. Запрос от другой идентичности Panel отклоняется.
- Сопряжение (Pairing), отвязка (unclaim) и ротация секретов являются чувствительными к безопасности операциями Control-Plane и должны инициироваться через утвержденный рабочий процесс Panel.

Реализация подписи, политика таймингов, секретные материалы и детали хранения состояния являются внутренней информацией безопасности. Используйте поддерживаемый клиент Panel или сгенерированные средства работы с контрактами вместо реализации собственных клиентов.

## Выполнение на хосте

Agent выполняет разрешенные операции с контейнерами, файловой системой, телеметрией и терминалом только после валидации транспорта. Сеансы терминала используют утвержденную политику оболочки и передаются через Panel; браузеры не получают прямой доступ к оболочке хоста.

Операции с файловой системой нормализуют запрашиваемые пути и применяют защиту от символических ссылок (symlink hardening). Политики VFS для конкретных контекстов выполнения остаются активно развивающимся направлением укрепления безопасности; операторы не должны полагаться на изоляцию тенантов сверх поддерживаемого в настоящее время рабочего процесса и назначенных прав Panel.

## Аудит и эксплуатация

Когда ведение журнала аудита включено, Agent генерирует структурированные события жизненного цикла безопасности запросов для оперативного контроля. Записи аудита следует рассматривать как конфиденциальные: они могут содержать имена методов, причины и идентификаторы Panel.

Операторы должны:

1. Развертывать Agent исключительно через утвержденный процесс выпуска и установки.
2. Ограничивать сетевой доступ в соответствии с утвержденной инфраструктурной политикой.
3. Мониторить доступность Agent и сбои аутентификации через Panel и систему наблюдаемости хоста.
4. Ротировать учетные данные сопряжения с помощью поддерживаемого процесса Control-Plane.
5. Не допускать попадания секретов, материалов TLS, токенов сопряжения и логов хоста в системы контроля версий и публичные каналы поддержки.

Сведения о поддерживаемых настройках см. в [Справочнике конфигурации](CONFIGURATION.md). Внутренние результаты реализации предназначены исключительно для инженерного рабочего пространства.
