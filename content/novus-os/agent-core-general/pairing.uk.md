# NOVUS Agent-Core: Pairing

Pairing встановлює єдину довірену прив'язку Panel до Agent. Після успішного створення пари привілейовані виклики виконання приймаються виключно від прив'язаної Panel через підписаний транспорт gRPC.

## Підтримуваний процес (Supported Flow)

1. Оператор генерує одноразовий токен створення пари на незв'язаному Agent за допомогою підтримуваного робочого процесу CLI.
2. Panel надсилає `PairNodeRequest` зі своїм UUID, одноразовим токеном та захищено налаштованим головним секретом (master secret).
3. Agent перевіряє, що він не зв'язаний, перевіряє UUID та токен Panel, зберігає прив'язку та повертає статус створення пари разом з ідентифікаторами Agent і Panel.
4. Подальші привілейовані виклики використовують звичайний підписаний транспорт і повинні відповідати ідентифікатору прив'язаної Panel.

Токен є одноразовим і закінчується відповідно до `NOVUS_AGENT_PAIRING_TOKEN_TTL_MINUTES`. Ніколи не вставляйте токени створення пари або головні секрети в тікети, публічну документацію, історію оболонки (shell history) або систему контролю версій.

## Резюме контракту

| RPC | Необхідний намір запиту | Результат |
| --- | --- | --- |
| `PairNode` | Request UUID, Panel UUID, токен створення пари, головний секрет, необов'язкове ім'я Panel | Встановлює початкове прив'язання Panel. |
| `UnclaimNode` | Request UUID, прив'язаний Panel UUID, необов'язкова принагідна причина | Видаляє поточне прив'язання після звичайної авторизації транспорту. |
| `RotateMasterSecret` | Request UUID, прив'язаний Panel UUID, необов'язковий відбиток старого секрету, секрет на заміну | Замінює секрет для поточного прив'язання. |

Точні визначення полів та їхні номери містяться в `proto/novus.proto`. Agent не повертає головний секрет у `PairNodeResponse`.

## Межа однієї Panel

Agent зберігає один прив'язаний Panel UUID. Запити від іншої Panel відхиляються. Створення пари не може перезаписати існуюче прив'язання; оператори повинні спочатку використати затверджений робочий процес розриву прив'язання / відновлення.

## Рекомендації для оператора

- Створюйте пару для Agent лише через робочий процес реєстрації вузла Panel або затверджену процедуру відновлення.
- Перевіряйте ідентичність вузла в Panel перед затвердженням створення пари.
- Вважайте розрив прив'язання та ротацію секретів адміністративними діями, чутливими до безпеки.
- У разі помилок підключення перевірте статус служби Agent та справність вузла Panel; не вимикайте перевірку транспорту для діагностики проблеми.
